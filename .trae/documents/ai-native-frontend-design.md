# AI 原生前端交互设计 — 产商品研发/运营助手

## 一、设计原则

### 核心原则：对话即界面

```
传统模式：           AI 原生模式：
┌──────────────┐    ┌──────────────────────┐
│ 左侧菜单导航  │    │ 对话是唯一的操作入口   │
│ 中间表单填写  │    │ 自然语言驱动一切       │
│ 右侧结果面板  │    │ 结构化结果内联在消息中  │
│ 页面跳转审批  │    │ 没有页面跳转           │
└──────────────┘    └──────────────────────┘
```

**三条铁律**：
1. **一切操作在对话中完成** — 没有侧栏面板、没有独立页面、没有弹出对话框
2. **结构化结果内联展示** — 表格、卡片、趋势图都在聊天消息里，用户不用转头看别处
3. **渐进式信息流** — 思考过程 → 工具执行 → 正文报告 → 追问建议，自上而下自然流出

## 五、消息渲染流程（代码级）

### 5.1 消息数据结构

```typescript
interface AssistantMessage {
  id: string;
  role: 'assistant';
  
  // Layer 1: 理解层 — 思考过程
  reasoning: ReasoningStep[];        // 思考步骤（时间线动画）
  intentType: string;                // 意图标签
  
  // Layer 2: 执行层 — 工具结果
  toolResults: ToolResult[];         // 每个工具的执行结果卡片
  
  // Layer 3: 表达层 — 正文 + 结构化数据
  streamText: string;                // 流式输出正文
  content: string;                   // 完整正文
  intentData?: any;                  // 结构化数据（ProductOpsPanel 消费）
  nextSteps: string[];              // 追问建议
  
  // 状态
  loading: boolean;
  done: boolean;
}
```

### 5.2 渲染顺序（ChatMessageList.vue）

```vue
<!-- AI 消息渲染顺序 — 自上而下渐次出现 -->
<template v-if="msg.role === 'assistant'">
  <!-- 1. 思考过程面板 -->
  <ThinkingProcessPanel :steps="msg.reasoning" />

  <!-- 2. 工具执行结果（#2 新增） -->
  <ToolResultPanel v-if="msg.toolResults?.length" :results="msg.toolResults" />

  <!-- 3. 正文报告（流式 Markdown） -->
  <MessageCard :content="replyDisplayText(msg)" :streaming="isReplyTyping(msg)" />

  <!-- 4. 结构化结果卡片（内联） -->
  <ProductOpsPanel v-if="msg.intentType && msg.intentData" ... />

  <!-- 5. 追问建议 -->
  <NextSteps v-if="msg.nextSteps?.length" :steps="msg.nextSteps" />
</template>
```

## 六、关键交互设计

### 6.1 输入框 — 唯一的操作入口

```
┌─────────────────────────────────────────────────────┐
│ 📎 文件  [输入业务诉求...]                    [发送] │
└─────────────────────────────────────────────────────┘
```

- 没有场景切换按钮
- 没有快捷操作芯片
- 用户直接说需求，Agent 自动识别意图
- 支持文件上传（拖入或粘贴）

### 6.2 思考过程 — 透明化 Agent 推理

```
思考过程 3步
① 正在理解您的需求...                     ← 意图识别
② 已确认业务意图：异动归因  把握度: 92%   ← 识别结果
③ 正在分析异动原因...                     ← 工具执行中
```

- 用户能看到 AI 在做什么
- 每步完成时显示结果标签
- 完成后可一键收起

### 6.3 工具执行结果 — 证据可追溯

```
┌─ sparql_query ──────────────────────── 1.2s ─┐
│ ✅ 查询完成                                    │
│ 查询: 家庭融合畅享128本月各渠道收入数据          │
│ 结果: 15 条记录  [查看证据]                     │
└───────────────────────────────────────────────┘
```

- 每个工具一个卡片
- 显示状态、耗时、结果摘要
- 可展开查看详情（证据、原始数据）

### 6.4 正文报告 — 流式自然语言输出

```
## 异动根因分析

家庭融合畅享128本月收入下滑30%，主要原因是**渠道A订购量下降**（贡献度40%），
其次是**渠道B转化率下降**（贡献度25%）。

### 详细数据
| 渠道 | 收入变化 | 贡献度 |
|------|---------|-------|
| 渠道A | -30%   | 40%   |
| 渠道B | -15%   | 25%   |
| 渠道C | -5%    | 10%   |
```

- 流式打字机效果打出
- 包含当事表格、代码块
- 正文结束后才出现追问建议

### 6.5 结构化结果卡片 — 关键数据一目了然

```
┌───────────────────────────────────────────────┐
│ 📊 归因结论                                    │
│                                                │
│ 主因: 渠道A订购量下降    贡献度 40%            │
│ 次因: 渠道B转化率下降    贡献度 25%            │
│ 次因: 渠道C自然流失      贡献度 10%            │
└───────────────────────────────────────────────┘
```

- 在正文报告之后展示
- 只展示关键摘要，不重复正文
- 可点击展开详情

### 6.6 追问建议 — 自然引导下一步

```
下一步可以: [具体哪个渠道影响最大] [和上月对比] [生成产品优化工单]
```

- 点击后自动填入输入框
- 建议基于当前上下文动态生成
- 支持维度下钻、时间对比、后续动作

## 八、设计对比

| 维度 | 旧设计（传统） | 新设计（AI 原生） |
|------|---------------|-----------------|
| 操作入口 | 输入框 + 右侧面板按钮 | 只有输入框 |
| 结果展示 | 聊天消息 + 右侧面板 | 全部在聊天消息中 |
| 结构化数据 | 右侧面板独立展示 | 内联卡片嵌入消息 |
| 场景切换 | 点击场景标签 | 自然语言表达即可 |
| 追问 | 自行输入文字 | 点击追问建议芯片 |
| 学习成本 | 需要理解面板布局 | 只需会打字聊天 |
