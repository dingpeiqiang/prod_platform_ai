## 一、基于LLM的多策略融合推荐引擎系统

### 技术领域
人工智能、推荐系统、表单自动化

### 核心创新点

本系统创新性地将LLM（大语言模型）与多策略推荐引擎深度融合，实现**确定性值优先、多策略并行、置信度加权**的分层推荐架构。

### 关键技术方法

1. **确定性值与推荐候选分层决策机制**（参见 [high_perf_engine.py:57-83](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/services/recommendations/high_perf_engine.py#L57-L83)）：
   - 优先从用户输入、工具结果、上下文变量中收集"确定性值"
   - 然后通过LLM批量提取未被覆盖的字段值
   - 最后仅对剩余未确定的字段执行多策略推荐
   - 避免对已有确定性值的字段进行冗余计算

2. **并行多策略推荐执行架构**（参见 [parallel_executor.py](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/services/recommendations/parallel_executor.py)）：
   - 历史频率策略：基于历史填写频率排序
   - 用户个性化策略：同一用户的历史记录优先
   - 时间衰减策略：近期数据权重更高
   - 静态配置策略：无历史数据时使用默认值
   - 四种策略通过 `ThreadPoolExecutor` 并行执行，互不阻塞

3. **批量AI推断引擎**（参见 [batch_ai_inference.py:153-215](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/services/recommendations/batch_ai_inference.py#L153-L215)）：
   - 一次LLM调用批量推断多个字段的候选值
   - 提示词中嵌入本体定义、字段约束、业务规则
   - 支持字段联动关系和实体级约束推理

4. **置信度加权决策算法**（参见 [high_perf_engine.py:187-247](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/services/recommendations/high_perf_engine.py#L187-L247)）：
   - 每个推荐候选携带来源、置信度、策略权重
   - 按照优先级 + 综合分数排序选择最佳值
   - 支持约束感知的最终决策修正

### 可专利性分析
- **新颖性**：现有推荐系统通常使用单一策略或简单加权，本系统将LLM推断与多策略并行推荐有机融合，采用"确定性值先验、推荐候补"的分层架构，显著区别于传统推荐方法
- **创造性**：解决了AI表单填写中"既需要LLM智能推断，又需要历史数据推荐"的矛盾，通过分层决策和并行执行实现高效融合
- **实用性**：适用于各类智能表单系统、企业级数据录入平台

## 二、AI输出的多维度熵检测与自适应校准方法

### 技术领域
人工智能质量控制、输出验证、不确定性评估

### 核心创新点

一种对AI输出进行**多维度熵值检测**并**自适应校准**的方法，通过一致性熵、格式熵、内容熵、语义熵四个维度全面评估AI输出的质量。

### 关键技术方法

1. **四维熵值检测模型**（参见 [entropy_detector.py:90-100](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/entropy/entropy_detector.py#L90-L100)）：
   - **一致性熵**：检测多次输出的稳定性（字符集合相似度算法）
   - **格式熵**：检测输出格式规范性（JSON/XML/Markdown格式检测）
   - **内容熵**：检测内容完整性（占位符检测、长度分析、必需字段检查）
   - **语义熵**：检测语义一致性（主题偏离、自相矛盾、重复度检测）

2. **加权综合熵值算法**（参见 [entropy_detector.py:504-513](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/entropy/entropy_detector.py#L504-L513)）：
   - 四个维度按权重加权（一致性0.3、内容0.3、格式0.2、语义0.2）
   - 输出0-1的总体熵值
   - 映射为五级熵级别（极低到极高）

3. **自适应阈值调整机制**（参见 [entropy_detector.py:537-553](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/entropy/entropy_detector.py#L537-L553)）：
   - 基于历史检测结果动态调整各维度的阈值
   - 避免过于严格或过于宽松的检测标准
   - 10次检测为一个调整窗口

4. **智能建议系统**（参见 [entropy_detector.py:451-535](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/entropy/entropy_detector.py#L451-L535)）：
   - 根据检测到的问题自动生成修复建议
   - 如：格式问题→检查JSON语法；内容不完整→补充缺失信息

### 可专利性分析
- **新颖性**：将信息论中的熵概念创新性地应用于AI输出质量评估，提出多维度熵值检测的框架
- **创造性**：设计了专门针对AI输出特征的四种熵检测算法（一致性、格式、内容、语义），并引入自适应阈值调整，是传统质量评估方法未涉及的
- **实用性**：适用于任何需要LLM输出的系统，可显著提升AI输出的可靠性和一致性

## 三、基于LLM的可视化工作流自动生成与执行方法

### 技术领域
工作流自动化、可视化编程、AI Agent

### 核心创新点

一种**自然语言驱动**的可视化工作流平台，用户通过业务需求描述即可自动生成可执行的工作流，支持多种节点类型和智能执行引擎。

### 关键技术方法

1. **LLM驱动的自然语言到工作流转换**（参见 [workflow_generator.py:23-76](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/services/workflow_generator.py#L23-L76)）：
   - 用户输入自然语言业务需求
   - LLM自动生成包含节点和连接的结构化工作流定义
   - 自动验证工作流的合法性（开始节点、结束节点、连接完整性）

2. **节点自治的可扩展执行引擎**（参见 [workflow_executor.py:212-267](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/engine/workflow_executor.py#L212-L267)）：
   - **NodeExecutor抽象基类**定义标准执行接口
   - 各类节点独立管理自身执行逻辑（LLM调用、HTTP请求、条件分支等）
   - 新增节点类型无需修改执行器核心代码
   - 节点注册机制实现自动发现

3. **智能变量解析系统**（参见 [workflow_executor.py:399-621](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/engine/workflow_executor.py#L399-L621)）：
   - 支持多种变量引用格式：`{{var}}`、`{var}`、`{{{var}}}`
   - 支持字段访问：`{{variable.field}}` 和数组索引：`{{variable[index]}}`
   - 变量元数据管理（类型推断、来源追踪、预览）
   - 支持变量搜索和建议功能

4. **条件分支引擎**（参见 [workflow_executor.py:795-1056](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/engine/workflow_executor.py#L795-L1056)）：
   - 支持多分支条件（branches格式）
   - 12种条件运算符（等于、不等于、大于、小于、包含、为空等）
   - 支持变量引用和常量比较
   - 与可视化编辑器的handle系统无缝对接

5. **工作流暂停与用户交互机制**（参见 [workflow_executor.py:1106-1141](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/engine/workflow_executor.py#L1106-L1141)）：
   - 用户输入节点可暂停工作流执行
   - 保存暂停状态和待收集信息到上下文
   - 支持从暂停点恢复执行

### 可专利性分析
- **新颖性**：将LLM生成与可视化工作流编辑器深度整合，实现了"自然语言→可视化工作流→可执行代码"的完整链路，创新性地提出了节点自治的执行架构
- **创造性**：与现有低代码/无代码平台不同，本系统不需要用户拖拽配置，而是通过LLM理解用户意图自动生成工作流；节点自治模式使得工作流引擎具备高度的可扩展性
- **实用性**：可应用于企业流程自动化、智能客服、RPA等领域

## 四、AI驱动的动态表单字段推断与零代码扩展方法

### 技术领域
动态表单、自然语言处理、本体工程

### 核心创新点

一种**完全由AI驱动**的动态表单系统，通过本体定义+LLM推断实现"新增表单零代码"，所有字段提取和推断逻辑由LLM完成，代码只负责流程编排。

### 关键技术方法

1. **本体驱动的表单Schema定义**（参见 [FORMS.md:182-203](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/FORMS.md#L182-L203)）：
   - 实体-字段两级层级结构
   - 每种表单类型只需定义JSON Schema
   - 选中枚举值、字段约束、业务规则统一在Schema中定义

2. **LLM字段推断规则系统**（参见 [FORMS.md:7-148](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/FORMS.md#L7-L148)）：
   - 编码类字段推断（根据格式模式匹-配）
   - 枚举/选择类字段推断（根据关键词匹配）
   - 数值类字段推断（支持单位转换）
   - 日期时间字段自然语言转换
   - 关联字段推断（基于已提取字段）
   - 必填字段优先处理策略

3. **场景识别与意图分类**（参见 [ARCHITECTURE.md:80-90](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/ARCHITECTURE.md#L80-L90)）：
   - 用户输入 → 输入护栏 → 场景识别 → LLM意图识别 → 输出校验 → 返回结果
   - 支持动态场景映射配置

4. **表单类型零代码扩展流程**（参见 [FORMS.md:119-126](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/FORMS.md#L119-L126)）：
   - 只需定义本体JSON + 配置场景映射 + 编写场景提示词
   - 无需修改任何Python代码

### 可专利性分析
- **新颖性**：现有动态表单系统多基于规则引擎或预定义的字段映射，本系统创新性地将表单字段提取完全交由LLM完成，实现了"配置即定义、零代码扩展"
- **创造性**：提出本体定义+场景提示词+LLM推断的三层架构，将表单系统的扩展成本从"开发新代码"降低到"配置新JSON"，这是传统表单系统无法实现的
- **实用性**：适用于企业级表单管理、政务审批系统、金融数据录入等场景

## 五、多层次AI输出自验证与修复闭环方法

### 技术领域
AI质量保证、自动化验证、自修复系统

### 核心创新点

一种对AI输出进行**多层次自动验证**并**自动修复**的闭环系统，通过Schema验证、字段校验、安全检查、LLM深度验证四级检查机制，确保AI输出的质量。

### 关键技术方法

1. **四级验证管道**（参见 [self_verifier.py:136-318](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/verification/self_verifier.py#L136-L318)）：
   - **Schema验证**：检查输出类型是否符合Schema定义
   - **字段验证**：检查必需字段、字段类型、数值范围、字符串长度、枚举值
   - **安全检查**：检测敏感信息泄露（密码、API Key、Token等）
   - **LLM深度验证**：使用LLM评估格式正确性、内容完整性、逻辑一致性、安全性

2. **评分与阈值决策系统**（参见 [self_verifier.py:28-56](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/verification/self_verifier.py#L28-L56)）：
   - 每项验证扣分，最终0-100分
   - 四级评分等级（优秀、良好、合格、不合格）
   - 可配置的通过阈值（默认70分）

3. **验证-修复闭环机制**（参见 [self_verifier.py:320-380](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/verification/self_verifier.py#L320-L380)）：
   - 验证不通过时自动调用修复函数
   - 支持最大重试次数配置
   - 修复失败时保留原始输出和验证结果

4. **智能建议生成**（参见 [self_verifier.py:573-591](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/verification/self_verifier.py#L573-L591)）：
   - 根据检测到的问题类型自动生成修复建议
   - 如：类型错误→检查字段类型；长度问题→调整字段长度

### 可专利性分析
- **新颖性**：提出"验证-评分-修复"闭环的AI输出质量控制方法，特别是将LLM自身作为验证工具（LLM验证LLM输出），形成自洽的质量保障机制
- **创造性**：将传统软件工程中的Schema验证与AI特有的不安全/不确定性问题检测有机结合，形成完整的质量保障体系
- **实用性**：适用于需要保障AI输出可靠性的生产环境

多Agent系统、分布式计算、智能调度

## 八、AI输入输出的多维度安全护栏系统

### 技术领域
AI安全、内容过滤、注入攻击防护

### 核心创新点

一种专门针对AI系统的**双向安全护栏系统**，同时防护输入和输出两个方向的安全风险，覆盖14种威胁类型，支持分级拦截。

### 关键技术方法

1. **14种威胁模式检测**（参见 [input_guard.py:57-126](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/guardrails/input_guard.py#L57-L126)）：
   - XSS攻击（脚本注入、事件注入、JavaScript协议）
   - SQL注入（Union、Drop、Exec）
   - 命令注入（Shell、管道、分号）
   - Prompt注入（忽略指令、覆盖指令、越狱攻击）
   - 恶意URL、路径遍历

2. **敏感信息检测**（参见 [input_guard.py:128-145](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/guardrails/input_guard.py#L128-L145)）：
   - API Key、密码、私钥、Token的自动识别
   - 严格模式下自动拦截

3. **威胁分级机制**（参见 [input_guard.py:147-153](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/guardrails/input_guard.py#L147-L153)）：
   - 五级威胁（Safe、Low、Medium、High、Critical）
   - 基于威胁权重累加评分
   - CRITICAL级别强制拦截，HIGH级别严格模式下拦截

4. **双向防护架构**（参见 [engine.py:198-298](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/engine.py#L198-L298)）：
   - 输入护栏：用户输入到达AI前进行安全检查
   - 输出护栏：AI输出返回前进行格式校验和内容验证
   - 与Harness引擎深度集成，形成端到端安全链路

5. **安全清理功能**（参见 [input_guard.py:249-264](file:///d:/工作/sitech/项目/研发/git_workspace/AI/prod_platform_ai/backend/app/harness/guardrails/input_guard.py#L249-L264)）：
   - 自动移除script标签
   - HTML特殊字符转义
   - 作为防御性措施

### 可专利性分析
- **新颖性**：专门针对AI系统的Prompt注入攻击防护，这是传统Web安全未覆盖的新威胁领域；输入输出双向检测架构
- **创造性**：将传统安全检测（XSS、SQL注入）与AI特有威胁（Prompt注入、越狱攻击）整合，并针对AI输出设计格式校验机制
- **实用性**：任何将LLM接入生产环境的系统都需要此类安全防护

### 评估方法论

采用**五维评估模型**对每项专利进行量化评分，每个维度满分10分，总分50分：

| 维度 | 权重 | 说明 |
|:----:|:----:|------|
| **新颖性 (Novelty)** | 高 | 与现有技术的差异程度，是否有类似已公开的技术方案 |
| **创造性 (Inventive Step)** | 高 | 非显而易见性——对本领域技术人员是否"意想不到" |
| **实用性 (Applicability)** | 中 | 能否在产业上制造或使用，并产生积极效果 |
| **授权前景 (Allowance Prospect)** | 中 | 基于当前中国AI领域专利审查实践，授权概率 |
| **维权可行性 (Enforceability)** | 低 | 侵权检测的难易度，权利要求是否容易被规避 |

评估综合考虑：
- 中国国家知识产权局（CNIPA）2023-2026年AI领域专利审查趋势
- 已知的现有技术（公开专利、论文、开源项目）
- 权利要求撰写的难易程度和保护范围

### 总体评估结论

| 指标 | 评估结果 |
|:----|:---------|
| **平均授权概率** | **约65-75%**（高于AI领域平均50-60%的授权率） |
| **高成功率专利** | 专利二、四（授权概率75-85%） |
| **最大风险因素** | 现有技术公开（特别是开源项目和海外产品） |
| **最佳策略** | "核心发明+实用新型补充"组合申请 |
| **建议申请量** | 建议首批提交3-4件发明+1-2件实用新型 |

### 关键成功因素

1. **尽早申请**：AI技术迭代快，越早申请越能锁定优先权日
2. **场景绑定**：将AI技术与具体的"表单字段推断"等业务场景绑定，避免因"纯算法"被驳回
3. **流程细化**：在说明书中详细描述方法的每一步流程，增加权利要求的技术性
4. **实施例丰富**：使用项目中实际的资费备案、流程审批等案例作为实施例，增加说服力
5. **组合申请**：将关联技术组合申请，形成专利组合而非单件专利
