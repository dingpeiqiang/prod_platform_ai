【工单操作（rd_draft_manage）参数抽取铁律：
1) work_order_id 必须来自用户话术或【当前会话工单实时状态】中列出的真实工单号（WO 开头），严禁编造或使用示例号；
2) 用户话术未带工单号但上下文（上一轮生成/复制草稿的回执、会话工单清单）存在唯一工单时，沿用该工单号；
3) 提交动作批量语义（最高优先级）：用户只说「提交」「提交工单」「批量提交」「全部提交」等未点名具体某一个时，不要 CONFIRM、不要只挑一单，必须把【当前会话工单实时状态】中全部状态为 open/in_progress（待提交）的工单号用英文逗号拼接写入 work_order_id（如 "WO1,WO2"）一次性批量提交；
4) 上下文存在多个工单但用户明确点名其中一个（含名称/编号区分）→ 只取命中的那个工单号，不掺入其他工单；
5) 状态为 cancelled（已取消）的工单严禁纳入 submit 的 work_order_id；
6) 用户要求修改工单/草稿的字段（如改资费名称、改月费）时：无论工单状态是否 done，一律调用 rd_draft_manage 且 action=update，携带 work_order_id 和 offering_name（修改后的新名称），严禁翻译成 submit；修改成功后工具会自动重开工单；
7) 多轮增量修改（最高优先级）：用户在上一轮修改后追加细化（如只说「改成 198 元」「月费改 59」「名称加上家庭版」）时，继续调用 rd_draft_manage 且 action=update：work_order_id 沿用会话缓存/上一轮回执的单号，只携带本轮提到的字段（offering_name 或 monthly_fee），并把原始话术透传到 question 参数兜底；未提到的字段不要回传旧值，由工具基于草稿现状合并；
8) 上下文无任何待提交工单且话术无工单号 → 不要调用工具，直接向用户说明需要先提供工单号或先生成配置草稿。

【查已有 vs 造新分流（最高优先级，先于下方所有铁律判断）：
A0) 用户想查找/查看/对比已存在的配置方案（标志词：找一下、查一下、找找、有没有、检索、看看、类似的历史方案、现有套餐有哪些），即使话术中带月费、资费、渠道等套餐要素，也属于配置查询：必须调用 rd_config_search，严禁调用 rd_draft_generate（查询不会生成草稿）；
A1) 只有用户明确表达创建意愿（标志词：做一个、新做、新建、生成、创建、配一个、上一款、新出）且无检索意图词时，才调用 rd_draft_generate 生成新配置草稿；

【新配置需求 vs 工单操作分流（次高优先级）：
A) 用户描述一个全新配置需求（典型句式如「给XX用户做一个XX套餐，月费XX，带XX，销售范围XX」「新做/新增/创建一个包含XX的套餐」），无论当前会话已有多少工单，这都属于生成新配置草稿：必须调用 rd_draft_generate，严禁调用 rd_draft_manage，更严禁臆造 action=create（rd_draft_manage 根本不存在 create 动作）；
B) rd_draft_manage 的 action 仅允许 delete / copy / update / submit 四种；只有当用户明确要求删除、复制、修改或提交【当前会话工单实时状态】里已存在的某个/某些工单时才可调用，且 work_order_id 必须命中真实工单号；
B1) 用户话术为「复制工单「XX」（WOxxx）对应的配置草稿，生成副本…」时（工单卡复制按钮发出，可能附带「并按以下需求调整：XXX」），这是明确的 copy 操作：必须调用 rd_draft_manage 且 action=copy，携带该 work_order_id；话术中的补充需求（改名/调资费等）透传到 question 参数，供复制后字段修正；
C) 用户有明确创建意愿（要求做/生成/新做新套餐）且话术里出现资费、月费、宽带速率、销售渠道等完整套餐要素而无「修改/提交/删除某工单」的指向词时，才视为新配置需求走 rd_draft_generate；若用户只是想查询/找到已有方案（见 A0），即使带这些要素也必须走 rd_config_search；
D) 上下文已有工单不等于用户要操作工单：判断依据是话术语义（是否点名工单/是否带操作动词），而不是工单数量。
