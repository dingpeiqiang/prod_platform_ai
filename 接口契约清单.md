### 1.1 history_service.py

**文件路径**：`backend/app/services/history_service.py`

**类名**：`HistoryService`

**职责**：基于历史数据的字段推荐服务，融合静态配置与历史实例数据。

**公开方法**：

| 方法 | 参数 | 返回值结构 |
|------|------|-----------|
| `get_recommend_values` | `form_code: str, field_code: str, user_id: str, db: Session, limit: int = 10` | `{"success": bool, "recommendations": [{"value": Any, "label": str, "score": float, "source": str}], "source": "hybrid" | "static"}` |
| `save_history` | `form_instance_id: str, field_code: str, field_value: Any, user_id: str, db: Session` | 无返回值（void） |

**方法详解**：

- `get_recommend_values`：混合推荐策略。先从历史实例数据（OntologyInstanceHistory）聚合统计，再叠加静态配置兜底。返回的 recommendations 列表中每个 item 包含 value/label/score/source 四个字段。source 顶层字段标识整体数据来源（"hybrid" 表示有历史数据，"static" 表示仅静态兜底）。
- `save_history`：保存单条字段填写历史记录到 OntologyInstanceHistory 表。

**依赖**：
- Model：`OntologyInstance`, `OntologyInstanceHistory`
- Service：`OntologyService`
- Config：`config_loader`

### 1.2 history_ai_service.py

**文件路径**：`backend/app/services/history_ai_service.py`

**类名**：无类，模块级函数

**职责**：AI 历史数据智能维护，包括分析、生成、查询、导出。

**公开函数**：

| 函数 | 参数 | 返回值结构 |
|------|------|-----------|
| `analyze_history` | `form_code: str, db: Session` | `{"success", "hasData", "formCode", "formName", "qualityScore", "totalRecords", "completeness", "distribution", "anomalies", "summary", "recommendations"}` |
| `apply_generated_data` | `form_code: str, db: Session` | `{"success", "formCode", "importedCount", "errors", "fieldStats", "message"}` |
| `list_available_data` | 无参数 | `List[Dict]` |
| `get_history_summary` | `form_code: str, db: Session` | `{"formCode", "formName", "hasOntology", "totalRecords", "fieldStats"}` |
| `query_history_records` | `form_code, start_date, end_date, user_id, page, page_size, db` | `{"success", "records", "total", "page", "page_size", "total_pages"}` |
| `export_history_data` | `form_code, format, start_date, end_date, user_id, db` | JSON 返回 `{"success", "content", "filename", "content_type"}`；文件返回 `{"success", "recordCount", "filename", "content_type"}` |

**返回值 key 详解**：

analyze_history 返回：
- qualityScore：float，数据质量评分（0-100）
- completeness：Dict，各字段填充率
- distribution：Dict，字段值分布统计
- anomalies：List，异常数据列表
- summary：str，AI 生成的分析摘要
- recommendations：List，改进建议列表

apply_generated_data 返回：
- importedCount：int，成功导入记录数
- errors：List[str]，错误信息列表
- fieldStats：Dict，各字段导入统计

get_history_summary 返回：
- hasOntology：bool，是否存在本体配置
- fieldStats：List[Dict]，各字段统计 `{"fieldCode", "fieldName", "filled", "empty", "fillRate"}`

**依赖**：
- Service：`llm_service`
- Model：`OntologyInstance`, `OntologyInstanceHistory`
- Config：`config_loader`

### 1.3 recommendation_engine.py

**文件路径**：`backend/app/services/recommendation_engine.py`

**类名**：`RecommendationEngine`, `RecommendationRequest`（dataclass）

**职责**：多策略推荐引擎，按优先级合并 AI 推断、频率统计、用户个性化、时间衰减、上下文感知、静态兜底等策略。

**RecommendationRequest dataclass 字段**：
- form_code: str
- field_code: str
- user_input: str
- user_id: str
- conversation_context: Dict
- max_recommendations: int = 5
- strategies: List[str]
- db: Session

**公开方法**：

| 方法 | 参数 | 返回值结构 |
|------|------|-----------|
| `recommend` | `form_code, field_code, user_input, user_id, conversation_context, max_recommendations, strategies, db` | RecommendationResult{success, field_code, recommendations: List[RecommendationItem], total_candidates, strategy_used, processing_time_ms, error} |
| `batch_recommend` | `form_code, extracted_fields, user_input, user_id, conversation_context, max_per_field, db, field_codes` | Dict[str, RecommendationResult] |

**RecommendationResult 结构**：
- success：bool
- field_code：str
- recommendations：List[RecommendationItem]，每项含 {value, label, score, source}
- total_candidates：int
- strategy_used：str
- processing_time_ms：float
- error：Optional[str]

**策略优先级**（高到低）：
1. AI 推断（inference）
2. 近期常用（frequency + time_decay）
3. 用户高频（user_personalized）
4. 静态配置（static fallback）

**依赖**：
- Strategy：`FrequencyRecommendationStrategy`, `UserPersonalizedStrategy`, `TimeDecayStrategy`, `ContextAwareStrategy`
- Config：`config_loader`

## 六、Java 迁移注意事项

### 6.1 架构映射建议

| Python 组件 | Java Spring Boot 对应 |
|-------------|----------------------|
| FastAPI Router | @RestController + @RequestMapping |
| Pydantic 模型 | Java DTO / Record + @Valid |
| Session（SQLAlchemy） | EntityManager / JdbcTemplate |
| 全局单例（llm_service） | @Service + @Autowired（Spring 单例） |
| AsyncGenerator（SSE 流） | SseEmitter / ResponseEntity<Flux> |
| WebSocket | @ServerEndpoint / Spring WebSocket |
| dataclass | Java Record / Lombok @Data |
| 模块级函数 | @Component 静态方法或 @Service |
| 文件数据源（config_loader） | @ConfigurationProperties / YAML 配置 |

### 6.2 关键迁移要点

1. **LLM Provider 工厂模式**：
   - Python 使用装饰器注册 Provider
   - Java 可用 Spring 的 @Component + Map<String, BaseProvider> 自动注入
   - 或使用 Factory Bean 模式

2. **SSE 流式响应**：
   - Python 使用 AsyncGenerator yield
   - Java 使用 SseEmitter 或 WebFlux Flux
   - 注意 thinking/reasoning/text 三种事件类型的处理

3. **WebSocket 表单协同编辑**：
   - Python 使用 FastAPI WebSocket
   - Java 使用 Spring WebSocket 或 STOMP
   - 需要保持 fieldChange/formControl/versionUpdate 事件协议不变

4. **推荐引擎多策略**：
   - Python 使用策略类 + 合并器
   - Java 可用 Strategy 接口 + @Component 列表注入
   - 注意优先级排序逻辑

5. **工作流引擎**：
   - 暂停/恢复机制需要持久化执行状态
   - 表单节点等待用户输入时需保存上下文
   - Java 可用 Spring State Machine 或自定义状态管理

6. **文件数据源**：
   - config_loader 从 YAML/JSON 文件读取
   - Java 迁移时建议改为数据库存储或 Spring 配置
   - 注意 SceneService、OntologyService 的 create/update/delete 目前不支持（返回错误）

7. **MCP 工具系统**：
   - OpenAPI 规范导入需要解析器
   - Java 可用 swagger-parser 库
   - 调用日志统计需异步记录

8. **向量检索（KBService）**：
   - Python 使用 harness.memory 向量存储
   - Java 可用 Spring AI 或直接集成向量数据库（Milvus/Pinecone）

9. **全局单例刷新**：
   - llm_service 的 refresh_config() 需要在 Java 中实现为刷新 Spring Bean 状态
   - 可用 @RefreshScope 或自定义刷新逻辑

10. **错误处理**：
    - Python 返回 {"success": false, "error": str}
    - Java 建议使用 @ControllerAdvice + 自定义异常体系
    - 但需保持 API 响应格式与前端兼容
