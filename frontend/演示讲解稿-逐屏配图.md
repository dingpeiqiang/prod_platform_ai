# AI 原生产品工作台 · 逐屏配图讲解稿

> 本稿是《产品手册-客户演示版》的**配套口播脚本**。每一屏给四样东西：**画面 · 操作 · 讲解词 · 截图位**，照着念即可完成一次完整演示。
> 全篇口径已统一：产品流程为 **配置 → 审批 → 审批通过即上架**，不涉及测试 / 备案公示 / 上架销售；研发助手本次只演示「资费配置」；档案调阅并入「智能问答」。

---

## 〇、演示前准备

**启动**
```bash
npm run dev
# 打开 http://localhost:3000/chat
```

**环境建议**

| 项 | 建议 |
|---|---|
| 分辨率 | 1920×1080（三栏全展开），浏览器缩放 100% |
| 窗口 | 全屏，隐藏书签栏 |
| 时长 | 完整版约 12～15 分钟；赶时间走「精简版」7 屏（见文末） |
| 演示主角 | `WeWalk-Data Only-澳门.香港.台湾共用30日不限量(30GB高速)` |

**贯穿全场的三条主线（讲解时反复呼应）**

1. **一条时间轴**：研发（上线前）→ 运营（上线后），查询贯穿全程。
2. **一个产品、一套数据**：三个助手看的是同一个产品。
3. **一个闭环**：运营发现问题 → 查询核实 → 研发配置 → 审批上架 → 回到运营。

## 一、开场 · 工作台

### 屏 01 ｜ 工作台首页（驾驶舱）+ 全局公共能力（四个按钮）

- **画面**：三栏布局；顶部导航「工作台 ｜ 产品研发助手 产品运营助手 产品查询助手」；中栏三张助手卡；右上角一排全局按钮：我的草稿、我的产品、我的待办、用户中心。
- **操作**：打开系统即截；依次点开「我的草稿」「我的产品」「我的待办」简介；「用户中心」口头带过。
- **讲解词**：
  > "大家看到的是**AI 原生产品工作台**。它跟传统系统最大的不同，是**没有一堆菜单**——整个平台就一个驾驶舱，上面是三个 AI 助手。"
  > "左边是场景和历史对话，中间是对话区，右边是跟随场景出现的工作面板。"
  > "这三个助手不是三个孤立工具：**研发助手管产品上线前，运营助手管上线后，查询助手贯穿全程**。而且它们互相调用——这一会儿大家会看到。"
  > "右上角还有一排**贯穿三个助手的公共能力**，它们不归任何一个助手，而是**所有助手共享的**"
  > "第一个，'**我的草稿**'——还没提交的配置都在这里，点一下就能继续配。"
  > "第二个，'**我的产品 / 工单中心**'——把已提交和已上架的产品统一管理，支持按多个维度快捷检索；点'产品运营指标'会**自动切到运营助手**打开看板，**跨助手联动**这里已经能看出来。"
  > "第三个，'**我的待办**'——把'我的审批'和'今日待办'放在一起，待办按紧急程度分三级；最关键的是待办**不是死链接**，点某个待办的'分析'会**直接跳进对话、自动把根因分析做出来**（稍后在运营助手里会完整看到）。"
  > "第四个，'**用户中心**'——当前登录工号和角色（这里也对应前面讲的身份概念）。"

## 三、产品运营助手 · 把产品"运营好"

### 屏 10 ｜ 运营助手欢迎页 + 运营身份

- **画面**：顶部切「产品运营助手」；欢迎页有「产品运营视图」入口卡和三个场景卡；中栏右上角出现「**运营视角：平台运营 | 代理商运营**」（**演示环境提供，用于在同一账号下演示两种身份**）。
- **操作**：点顶部「产品运营助手」。
- **讲解词**：
  > "运营助手负责产品**上线后**。这里先说明一下它的**运营身份**机制。"
  > "有两个角色：**平台方**关心整个流量池、代理商、地区；**代理商**关心自己名下的客户、套餐、用量。"
  > "两个视角**看到的、能做的事也不一样**：**平台视角**看的是平台整体，以及代理商、地区、套餐档位的结构，可以在代理商之间做比较；**代理商视角**看的是自己名下的用户、套餐和用量，还能做**套餐优化建议**。接下来我们会分别演示。"
  > "这里提一下，后续开发，**运营助手是按登录工号自动区分身份的**——平台方的工号进来，看到的是全局数据；代理商的工号进来，看到的是自己管理的数据。**不同工号的数据范围自动过滤，不需要谁去手动选**。"
  > "今天的演示环境我们只登录了一个账号，所以在这里放了一个「**运营视角**」切换，用来把**两种身份的效果**都演示给大家看。**正式部署时，它会跟着工号自动走。**"

### 屏 13 ｜ 【平台视角】对话场景二：异动归因分析（重点屏）

- **画面**：回复「**异动归因分析 · 套餐新增异动**」：异动概览（本月新增订购 **21000 笔**、环比 **-26.1%**、转折点 **8月12日**）→ **按套餐 / 地区 / 代理商三张拆解表** → **根因贡献度表**；回复里带「看地区退订率」「出高速升级方案」等下钻入口。
- **操作**：发送（可先点快捷回复一键填入）。
- **话术**：
  > `本月哪个套餐新增异动最大，是哪个地区、哪个代理商贡献的`
- **讲解词**：
  > "接下来是运营助手最有价值的能力——**异动归因**。我们这里输入平台运营关注的问题：'**本月哪个套餐新增异动最大，是哪个地区、哪个代理商贡献的**'"
  > "它先给一个**异动概览**：平台本月新增订购 **21000 笔、环比 -26.1%**，转折发生在 **8月12日** 之后。"
  > "然后把降幅**拆成三个维度看是谁贡献的**：按套餐是 **30GB档异动最大**（-51.7%，贡献 **54%**）；按地区主要是 **香港（贡献 41%）** 和 **台湾（27%）**；按代理商主要是 **鑫联国际（38%）** 和 **港通数码（25%）**。"
  > "最关键的是这张**根因贡献度表**——它把原因拆开：**30GB 档落后竞品贡献 46%、15日档被分流 24%、渠道收缩 18%、季节性 12%**，最后得出结论：**'竞争性新增萎缩'**。"
  > "过去做这样一份归因，要先提数据需求、再等排期、再人工分析；现在是**一句话**需求。"
- **截图位**：`![屏13 异动归因摘要](./screenshots/13-ops-anomaly.png)`
