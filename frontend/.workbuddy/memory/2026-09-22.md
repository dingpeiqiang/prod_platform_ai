## 撰写《产品手册-客户演示版.md》

- 目标：为客户演示撰写一份逻辑连贯（非孤立功能罗列）的 markdown 产品手册，覆盖三个助手。
- 先深度梳理了代码库交互与场景（Explore 子代理 + 直接读关键文件），随后产出 `产品手册-客户演示版.md`（项目根目录）。
- 结构：序章 → 总体架构与助手关系 → 研发助手 → 运营助手 → 查询助手 → 全局能力 → 闭环演示脚本 → 附录（话术速查/术语与数据）。
- 核心叙事：三个助手按"产品全生命周期"分工（研发=上线前做产品、运营=上线后运营、查询=贯穿全程），并以跨助手联动闭环（运营→查询→研发→审批→测试→上架）作为"串联"卖点。

### 梳理出的关键事实（供后续复用）

- 项目是 Vue3 + Pinia + Vue Router + Element Plus 的"AI原生产品工作台"，唯一页面 `src/components/ChatPage.vue`，演示地址 `http://localhost:3000/chat`。
- 三个助手 key：`rd`(研发) / `ops`(运营) / `query`(查询)，配置在 `src/config/assistantModes.js`。
- **与旧版《全场景全流程交互手册.md》不一致、已按代码实测修正的点**：
  1. 顶部流程条当前只有 **3 阶段**：方案设计 → 产品配置 → 审批上架（`src/stores/workflow.js`）；旧的六阶段（含测试审核/备案公示/上架销售）只存在于查询助手制度知识库 KB-004 条文里。
  2. 配置工作台当前只有 **4 个页签**：基础信息 / 属性信息 / 资源配置 / 信息预览（`ProductConfigPanel.vue` baseTabs）；测试报告/备案公示/销售渠道仅保留只读快照代码，已不在页签内。
  3. 示例产品已全部替换为联通国际 `WeWalk-Data Only` 港澳台共用国际漫游数据卡（存量 5 档），旧手册的"智享99/畅享59/校园卡"已废弃。
- 运营助手有**双视角**开关（平台运营 platform / 代理商运营 agent），持久化 key `ops.perspective.v1`；平台视角隐藏"套餐优化建议"(ops.scene3)。
- 查询助手实际场景卡只有 2 个：智能问答、比对分析；"档案调阅"由问答/快捷按钮触发。
- 制度知识库 5 条（KB-001~005）；存量产品库 5 档（SP-HK-TW-1D/3D/15D/30D/30D-HIGH）。

## 手册 v2.0 修订（客户反馈）

用户对 v1.0 提出三点修改，已产出 v2.0：
1. **流程精简**：去掉"测试 / 备案公示 / 上架销售"三个环节，口径统一为「配置 → 审批 → 审批通过即上架」；闭环链路止于审批通过→上架→归档工单中心。

- 顺带清理：制度问答示例改为"产品命名规范"（不再举备案公示/测试审核）；附录 B 移除测试报告号/备案编号。
