# AI 原生产品工作台 · 产品手册

> **一句话定位**：这是一个由「一个工作台 + 三个 AI 助手」构成的**产品全生命周期作业平台**。它把过去散落在多个系统、多张表单里的产品工作，收敛成"用一句话说需求、AI 帮你把事办完"的一条流水线。

| 项目 | 说明 |
|---|---|
| 产品名称 | AI 原生产品工作台（PRODUCT WORKBENCH） |
| 适用业务 | 中国联通国际业务 · WeWalk 国际漫游数据卡等资费产品的研发与运营 |
| 核心组成 | 工作台（驾驶舱）+ 产品研发助手 + 产品运营助手 + 产品查询助手 |
| 演示地址 | `http://localhost:3000/chat` |
| 手册版本 | 客户演示版 v2.0 |

## 序章 · 我们想解决什么问题

一个资费产品，从"想法"到"上市"再到"持续赚钱"，要经历一条不短的链路：

```text
产品创意 → 立项设计 → 资费配置 → 提交审批 → 审批通过（即上架） → 运营监控 → 发现问题 → 优化迭代 → （回到配置）
```

这条链路有两个痛点：

1. **断层**——配置一个系统、审批一个系统、运营又是一个系统，数据不互通。一个产品"上线前怎么配的"和"上线后表现如何"常常对不上账。
2. **重手工**——配一个套餐要填几十个字段的表单；要一份分析报告，得先提数据需求、再等排期；想查某个产品的历史配置，需要翻阅多个文件。

**AI 原生产品工作台的做法是：不给三个孤立的工具，而是给一条打通的产品流水线。**

- 把这条流水线按"时间轴"切成三段：**上线前的事交给产品研发助手，上线后的事交给产品运营助手，而"找资料"这件事由产品查询助手全程兜底**。
- 三个助手不是三套系统各自为政，而是**同一个工作台里的三个角色**，彼此可以互相调用——运营助手发现问题后，会**自动叫上查询助手核数据、叫上研发助手开配置单**，把"发现问题"直接变成"解决问题"。

一句话概括它们的分工：

> **研发助手负责"把产品做出来"，运营助手负责"把产品运营好"，查询助手负责"让一切查得到"。**

## 第一章 · 总体架构：一个工作台，三位助手

### 1.1 一个工作台（驾驶舱）

打开系统，首先看到的不是某个功能菜单，而是一个**三栏式的工作台**——它是所有事情的统一入口：

| 区域 | 位置 | 作用 |
|---|---|---|
| **左栏** | 场景入口 + 历史对话 | 上面是当前助手的**快捷场景**，下面是**历史对话**（支持按标题/内容/工单号检索、删除），最下面是用得着的**使用提示**；顶部有醒目的「**新建会话**」按钮。 |
| **中栏** | 对话区 | 与 AI 对话的主战场。运营助手在这里会显示「运营视角」（由工号自动决定，演示环境下可手动切换）。输入框上方会根据场景动态出现**配置方式选择条 / 快捷动作芯片**。 |
| **右栏** | 动态面板 | 随场景自动出现的"工作台"：配置工作台、产品档案、比对面板、运营看板等。三栏联动，**说到哪，右边就长出什么**。 |

**顶部导航**是整个平台的"遥控器"：

```text
PRODUCT WORKBENCH · AI原生产品工作台      工作台 ｜ 产品研发助手  产品运营助手  产品查询助手      我的草稿  我的产品  消息通知  用户菜单
```

> 顶部这排按钮就是三个助手的"总开关"：点谁就进谁的场景，**当前对话会自动归档到历史**，随时可以再切回来。

### 1.2 三位助手，各管一段（速览）

| 助手 | 一句话职责 | 覆盖环节 | 主要场景 |
|---|---|---|---|
| 🧪 **产品研发助手** | 把产品**做出来** | 产品**上线前** | **资费配置**（核心） |
| 📈 **产品运营助手** | 把产品**运营好** | 产品**上线后** | 运营数据分析 · 异动归因分析 · 套餐优化建议 |
| 🔍 **产品查询助手** | 让一切**查得到** | **贯穿全程** | 智能问答（含档案调阅） · 比对分析 |

> 说明：产品研发助手后续还会拓展"营销活动管理""业务规则管理"等场景，本手册暂不展开，聚焦最能体现"AI 原生"的核心场景——**资费配置**。

### 1.3 它们的关系：一条时间轴 + 一个闭环

**第一层关系——时间轴上的接力：**

```mermaid
flowchart LR
  A["产品研发助手<br/>上线前：配资费"] -->|产品上架| B["产品运营助手<br/>上线后：看数据 / 查异动 / 出方案"]
  B -.->|"发现异动，需要优化"| A
  C["产品查询助手<br/>贯穿全程：问商品 / 调档案 / 做比对"]
  C -.-> A
  C -.-> B
```

- **研发 → 运营**：研发助手配好的产品，上架后进入运营助手的监控视野；工单中心里点某个产品的"运营指标"，会**自动跳到运营助手**并打开它的看板。
- **运营 → 研发**：运营助手发现产品亚健康，给出优化方案后点"启动产品优化"，会**自动调用研发助手**打开一张预填好的配置工作台——发现问题直接接上解决问题。
- **查询贯穿两端**：无论是研发阶段要"找个老套餐当模板"，还是运营阶段要"核实某产品的资费画像"，查询助手随时待命；而且**研发助手配置的草稿，查询助手也能直接查到、拿来比对**。

**第二层关系——面对同一个产品，三个助手看到的是同一条数据：**

这就是这套产品最关键的"衔接点"。以一张 WeWalk 数据卡为例：

> 研发助手配好它的"高速配额 30GB、漫游地香港.台湾、PCRF 限速"；上架后，运营助手看到的流量使用率正是这张卡的；查询助手调出的档案，也是同一张卡的完整画像。
> **三个助手，一个产品，一套数据。** 这不是三份报表，而是同一个产品的三种看法。

**第三层关系——工作台负责"居中调度"：**

工作台本身不处理业务，它是驾驶舱，负责把三个助手串起来。你会在演示中反复看到这种"接力"：

- 运营助手出方案 → **自动打开研发助手的配置工作台**；
- 工单中心点"运营指标" → **自动切到运营助手**；
- 通知待办点"分析" → **自动跳进对话做根因分析**；
- 查询助手说"查我最近配的套餐" → **调出研发助手的在配草稿**。

### 1.4 运营助手的"运营身份"：一套数据，两种角色

国际业务里有两个天然角色：

- 🏢 **平台运营（联通国际视角）**：管**代理商 / 地区 / 套餐**——关心的是整个流量池卖得好不好、哪些代理商拖后腿。
- 🤝 **代理商运营（一级总代视角）**：管**个人用户 / 套餐 / 用量**——关心的是我自己手里的客户和买来的流量用得怎么样。

**运营助手的视角由登录工号自动决定**：平台方工号进来看到全局数据，代理商工号进来看到自己名下的数据，**不同工号的数据范围相互隔离**，不需要人工选择。视角不同，**同一套场景卡、同一套数据底座，会呈现出不同的口径、不同的推荐话术、不同的看板**（平台视角会隐藏"套餐优化建议"这类面向代理商的动作）。这让平台方和代理商方**在同一个系统里各看各的**，又能对得上账。

> 演示环境使用单一账号，因此界面上提供了「运营视角」切换入口，用于在同一个账号下演示两种身份的差异；正式环境将随工号自动匹配。

### 1.5 贯穿全篇的主角

为了让手册读起来是一条线，后文统一用同一个"主角产品"来串讲：

> **主角：`WeWalk-Data Only-澳门.香港.台湾共用30日不限量(30GB高速)`**
> 一档 5G 数据卡（Data Only），一次性资费、有效期 30 天、高速配额 30GB、漫游地澳门.香港.台湾共用、高速用尽后 PCRF 限速不限量。

下面开始，我们跟着这张卡走一遭：**先在研发助手把它配出来，再在运营助手看它表现、发现问题，最后在查询助手把它的资料查个透。**

## 第二章 · 产品研发助手：把产品"做出来"（上线前）

### 2.1 定位与进入

**定位**：管产品**上线前**的事——当前核心就是**把资费配置出来**。品牌标 `R&D ASSISTANT`，输入框提示"描述你的研发需求..."。

**进入方式**（三种任选）：
1. 顶部导航点「产品研发助手」；
2. 欢迎页点助手卡或场景卡；
3. 不选助手，直接在下方输入框说需求。

进入后，**左栏出现快捷场景**（当前为资费配置）。点场景，中栏会展示该场景的欢迎说明与推荐话术——**不知道怎么说？点推荐话术就能自动填入输入框**。

### 2.2 核心场景：资费配置 ★

这是研发助手最"重"、也最能体现"AI 原生"的地方——**配一张卡不再是填几十个字段的表单，而是说一句话。**

选中「资费配置」后，**输入框上方出现三种配置方式，任选一种开始**：

```text
选择配置方式：  ● 对话式配置    ○ 文件导入批量配置    ○ 存量产品复制配置
```

#### 方式一 · 对话式配置（说一句话就出配置单）

**① 你说需求。** 例如：

> `配置一档WeWalk-Data Only-香港.台湾共用30日不限量(30GB高速)数据卡：一次性资费，高速配额30GB，有效期30天，漫游地香港.台湾，PCRF限速`

**② AI 解析出字段。** 系统用自然语言把这句话拆成结构化字段（高速配额、有效期、漫游地、限速策略、资费类型……），回复一张「**对话式配置 · 字段解析结果**」表格，并同时完成三件小事：

- 自动生成**工单号**（如 `WO20260827001`）；
- 登记到右上角「**我的草稿**」；
- **在右侧自动打开「配置工作台」**。

**③ 看懂工作台里的两类标签。** 打开的工作台里，字段会带一个来源标签，这正是"AI 配置"的透明度所在：

| 标签 | 含义 | 悬停可看 |
|---|---|---|
| 🟦 **已解析** | 你说的话里明确提到的字段 | "根据用户需求解析得出" |
| 🟪 **AI 推荐** | AI 依业务模板（并参考产品库中相似产品）自动补全的字段 | 补全理由（如"WeWalk 港澳台共用数据卡为 Data Only 纯流量产品"） |

> 只读档案（存量产品快照）属于历史归档数据，不再显示这两类标签。

**④ 继续用对话改。** 觉得哪里不对，直接说：`月费改成198元` / `漫游地加上澳门` → 工作台字段**实时更新**。

**⑤ 稽核与提交。** 点「**智能稽核**」做提交前校验，通过后点「**提交配置**」→ 生成/确认工单号，**进入审批**。

> **附加包怎么配？** 如果配的是附加包/加油包，对话式配置会自动切到附加包模板（预填示例：`WeWalk-Data Only-澳门.香港.台湾共用2日不限量(800MB/日高速)`），并提示"归属产品、语音/短信资源量待确认"。

#### 方式二 · 文件导入批量配置（传一个文件，配一批套餐）

适合"手里已经有一张需求表，要一次配好几档套餐"。

1. 选中该方式，**上传配置文件**（支持拖拽、粘贴）；
2. 系统解析出多个产品，写成一张「**文件导入批量配置 · 解析结果**」目录表（含产品名、工单编号、资费概要、状态），并写入「**我的草稿**」，**自动打开第一个草稿的工作台**；
3. 逐个完善并提交，**提交一个自动跳下一个**，工作台底部可用「上一个 / 第 x 个 · 共 y 个 / 下一个」导航；全部提交完成后提示"全部草稿产品已提交，进入审批阶段"。

> 演示用文件（《WeWalk套餐配置需求20230803(1).xlsx》）会一次解析出 3 档产品：1日(800MB/日高速)、15日(15GB高速)、30日(30GB高速)。

#### 方式三 · 存量产品复制配置（找个老套餐当模板）

适合"新套餐跟老套餐很像，改几个字段就行"。

1. 选中该方式，**输入框会变成一个"槽位模板"**（下拉 + 填空的组合），照这样填：

   > `我想要查【套餐类型：预付费主套餐 / 附加包】的【套餐名称】套餐，套餐编码为【套餐编码】。`

2. 系统按名称或编码**模糊检索存量产品库**，返回一张「**存量产品复制配置 · 检索结果**」表格（编码 / 名称 / 资费概要）；
3. 点「**查看详情**」打开该产品的**只读配置档案**，确认没问题后点「**复制**」——**复制品立即变成一张可编辑的新产品**（产品名自动追加"（复制）"、生成新工单号），随后走与方式一完全相同的提交审批流程。

**存量产品库（5 档 WeWalk 数据卡）**：

| 产品编码 | 产品名称 | 模板 |
|---|---|---|
| `SP-HK-TW-1D` | WeWalk-Data Only-澳门.香港.台湾共用1日不限量(800MB/日高速) | 可选包·数据卡 |
| `SP-HK-TW-3D` | WeWalk-Data Only-澳门.香港.台湾共用3日不限量(800MB/日高速) | 个人主资费·数据卡 |
| `SP-HK-TW-15D` | WeWalk-Data Only-澳门.香港.台湾共用15日不限量(15GB高速) | 个人主资费·数据卡 |
| `SP-HK-TW-30D` | WeWalk-Data Only-澳门.香港.台湾共用30日不限量(30GB高速) | 个人主资费·数据卡 |
| `SP-HK-TW-30D-HIGH` | WeWalk-Data Only-澳门.香港.台湾共用30日不限量(3GB/日高速) | 个人主资费·数据卡 |

### 2.3 三种方式最终都收口到同一张「配置工作台」

无论用哪种方式进入，最终都在同一张**配置工作台**里完成配置，共四个页签：

| 页签 | 关键字段 |
|---|---|
| **基础信息** | 产品类型、卡类型、网络类型、开户/漫游模版、产品编码、名称、描述、发布租户、退订规则（附加包）、订购附加产品（主套餐）、归属产品（附加包） |
| **属性信息** | 资费类型、有效期属性、资源重置周期、产品有效期、是否激活、延长生命周期、重复订购、唤醒激活、延长期限 |
| **资源配置** | 数据资源（高速配额、漫游地、限速策略、**限速模版动态表格**）、语音资源、短信资源 |
| **信息预览** | APP 手机壳预览（用户 / 免填单 / 短信三视图），随表单实时渲染 |

工作台底部有三个动作：**保存草稿 / 智能稽核 / 提交配置**。

**智能稽核**会依次跑五步并给出结论：`基础信息完整性校验 → 必填字段检查 → 业务规则校验 → 短信模板合规性检查`，有任何必填项缺失都会明确列出。

### 2.4 提交之后：审批与上架

点「提交配置」后，产品进入**审批**：

- 助手固定回复"已帮您提交，配置已进入审批阶段。工单编号：xxx…"，并附「**查看审批进度**」按钮；
- 右侧滑出**审批抽屉**：显示工单号、产品名、状态标签，以及一条审批时间线——`配置已提交（绿）→ 主管审批（进行中）→ 审批完成`；
- 审批中可「**催办**」；审批通过后即**进入上架**（详见第三章的完整闭环）。

> 演示小技巧：对话式/存量复制提交的工单会**停在"审批中"**，方便现场展示审批态；而由运营助手发起的优化配置会**自动流转到审批通过**，用来演示"一条龙"。

### 2.5 小结：研发助手的产出物流向了哪里

研发助手不是"配完就完"，它的产出会流向全局，也为后续章节埋下伏笔：

- 未提交的 → **我的草稿**（可随时"进入工作台"继续配）；
- 已提交的 → **我的产品**（登记一条"待审批"记录）+ **审批抽屉**；
- 已上架的 → **工单中心**归档；
- 而这些产品，**查询助手也能查到**（第四章）。

**承上启下**：产品配好、审批通过、上架之后，故事就交给了运营助手。下面我们看看这张 WeWalk 数据卡上市后的"体检报告"。

## 第三章 · 产品运营助手：把产品"运营好"（上线后）

### 3.1 定位、进入与运营身份

**定位**：管产品**上线后**的事——看数据、查异动、出方案。品牌标 `OPS ASSISTANT`，输入框提示"描述你的运营问题..."。

进入后，欢迎页除了三个场景卡，还有一张特别的「**产品运营视图**」入口卡——**点它，右侧直接展开运营看板**。运营助手最上方显示「**运营视角**」，它由**登录工号自动决定**（平台运营 / 代理商运营）；演示环境下提供一个切换入口，方便在同一账号下查看两种身份（见 1.4）。

**它的能力会随视角不同而不同**，下面分**平台运营**与**代理商运营**两个视角分别介绍。

### 3.2 平台运营视角

#### 3.2.1 视图：产品运营视图

平台视角的看板分两大类：

- **产品运营**：`收入总览`（报表收入/出账收入）→ `重点产品运营`（规模活跃 / 结构占比 / 新增 / 新增质量 / 收入渠道）→ **下钻到单品**（健康度仪表盘、异动预警、关键指标），并可一键「**根因分析**」回到对话。
- **流量运营**：`流量运营全景总览`（流量池总量/已用/余量/使用率）→ `运营分析` 多页签（**流量趋势 / 代理商 / 地区**）→ `重点运营机会`；表格每一行都能「**让 AI 分析**」。

#### 3.2.2 对话场景

**场景一 · 运营数据分析**：围绕平台经营指标与流量批发做趋势解读，可按代理商 / 地区 / 套餐档位下钻。

> 你可以这样说：`帮我看下本月平台整体流量池的使用率与余量，按地区分布`、`哪些代理商本月新增掉得最多，集中在哪些地区`

系统给出**关键指标表（含环比）→ 归因结论 → 建议动作**，并附「打开运营视图」「下钻」按钮。

**场景二 · 异动归因分析**（演示周期 2026 年 8 月）：

| 异动类型 | 演示数据 | 结论 |
|---|---|---|
| 套餐新增异动 | 本月新增订购 **21,000** 笔（上月 28,400，环比 **-26.1%**） | **竞争性新增萎缩**（30GB 档落后竞品占 46%） |
| 收入下滑 | 批发结算收入 **24,280** 万（环比 **-8.2%**） | **结构性收入下滑**（鑫联国际、港通数码合计贡献 66%） |
| 地区退订率上升 | 平台均值 3.6%，香港 6.8%、台湾 5.9% 偏高 | — |
| 代理商使用率异常 | 均值 57.4%，鑫联国际 69.3%（容量吃紧型） | — |

每条归因结论都配一段**思考过程**（"解析诉求 → 锁定范围 → 拉取数据 → 定位根因 → 生成报告"）和一排**追问按钮**（如"看地区退订率""出高速升级方案"），让你能一层层往下挖。

> 💡「**套餐优化建议**」不对平台视角开放——因为"改套餐组合"是代理商侧的动作。

### 3.3 代理商运营视角

#### 3.3.1 视图：代理商运营视图

以代理商工号进入后，看板切换为代理商口径：

- **代理商运营全景总览**（个人用户）；
- **运营分析**：**个人用户 / 子渠道 / 套餐 / 成本** 四个页签，同样支持「让 AI 分析」。

#### 3.3.2 对话场景

**场景一 · 运营数据分析**：围绕自身用户的活跃 / 订购 / 收入，以及自购流量的使用率与余量。

> 你可以这样说：`看下我这个月自己客户的活跃变化，新增和退订多少`、`我这批买进30GB的流量用得怎么样，还剩多少`

**场景二 · 异动归因分析**：定位"退订率最高的套餐 / 大客户用量骤减 / 毛利下降 / 流失预警客户群"等问题。

**场景三 · 套餐优化建议**：按使用率对套餐分档（🔴高负载 / 🟢利润池 / 🟡健康），给出档位升级 / 组合补位 / 留存提利 / 结构调优等动作。

> 你可以这样说：`我名下哪几档套餐需要优化，怎么调整档位更合理`、`怎么优化我的套餐组合，提高整体毛利`

现成诊断（如整体毛利率 36.8%）+ **四个优化动作**，预计**月增毛利约 14.3 万元**。

### 3.4 两个视角共通：从"看到问题"到"解决问题"的闭环 ★

前面都是"看"，这里开始"办"。当你在异动分析中得到一套优化方案时，回复末尾会出现四个决策按钮：

> **启动产品优化（推荐） · 启动产品下线 · 暂不处理，3 天后再次提醒 · 我有问题需要确认**

点「**启动产品优化**」，工作台会**自动把三个助手串起来跑一条完整链路**：

```text
① 运营助手确认方案A
      ↓ 自动调用
② 查询助手核实品类与资费画像、校验互斥规则
      ↓ 自动调用
③ 研发助手匹配业务模板、预填配置、自动打开配置工作台（字段标好"已解析 / AI推荐"）
      ↓
④ 智能稽核 → 提交配置（生成工单 WO20260812001）
      ↓ 约 9 秒后
⑤ 审批通过 → 即上架（AI 主动播报，产品状态更新为"已上架"）
      ↓
⑥ 归档到右上角「工单中心」
```

整个过程中，右上方有一条**流程条**实时同步进度，共三个阶段：

> **① 方案设计 —— ② 产品配置 —— ③ 审批上架**

这正是"AI 原生产品工作台"最想给客户看的一幕：**一次对话，从数据洞察一路办到产品上架，中间不用切系统、不用手工搬数据。**

> 顺带一提：**运营视图与对话是双向联动的**——看板上任意一行数据点一下就能让 AI 帮你分析（"让 AI 分析"），分析完又能一键回到看板下钻。

## 第四章 · 产品查询助手：让一切"查得到"（贯穿全程）

### 4.1 定位与进入

**定位**：管**找资料**的事——问商品、调档案、做比对。品牌标 `QUERY ASSISTANT`，输入框提示"输入你想查询的产品信息..."。

它有一个很实用的特性：**会记上下文**。比如你刚问完"30GB 数据卡包含多少流量"，接着只说一句 `调阅该商品的配置档案`——"该商品"会自动指向上一轮聊过的那张卡。

查询助手只有**两个场景卡**：**智能问答**、**比对分析**。而"档案调阅"已**并入智能问答**——它不是一个独立场景，而是智能问答能直接触发的一种动作。

### 4.2 场景一：智能问答（一问三答）

一句话提问，系统从**产品库**与**制度知识库**中检索作答，覆盖三种问法：

#### ① 产品问询 —— 问资费要素、套餐内容、办理限制、当前状态

> `WeWalk-Data Only-澳门.香港.台湾共用30日不限量(30GB高速)包含多少高速流量？`

返回一张「**要点速览**」卡：先高亮你要的字段，再列出产品类型 / 高速流量 / 有效期 / 漫游地 / 限速策略 / 月费 / 语音 / 短信 / 套外 / 状态等要素。

#### ② 制度问询 —— 问产品命名、编码等规范

> `产品命名有什么规范要求？`

回答以 **RAG 风格**给出，并标注**引用来源**：`📎 引用来源：《产品命名与编码规则》· 产品管理中心规范 产管〔2025〕07号 · 更新于 2025-11-02`。

#### ③ 档案调阅 —— 把产品"翻开来看"

> `调阅"WeWalk-Data Only-澳门.香港.台湾共用30日不限量(30GB高速)"的配置档案` 或 `查一下 SP-HK-TW-30D 的档案`

右侧打开一张**只读的配置工作台**，四个页签一目了然：**基础信息 / 属性信息 / 资源配置 / 信息预览**。存量在架产品的档案打开时，流程条会被置为"全生命周期已完成"，一眼就能看出"这是已上架的老产品"。

**这里有一个关键的"跨助手联动"**：

> 说一句 `查一下我最近配置的套餐` → 系统会列出**你在研发助手配置的在配草稿**。
> 也就是说——**研发助手配的草稿，查询助手能查到；查询助手查到的存量产品，研发助手能复制它当模板**。两个助手其实是通的。

### 4.3 场景二：比对分析（把两款产品"摆在一起"）

> `对比WeWalk-Data Only-澳门.香港.台湾共用30日不限量(30GB高速) 和 WeWalk-Data Only-澳门.香港.台湾共用15日不限量(15GB高速)`

右侧打开**比对面板**，三块内容：

- **资费要素对比表**（高速配额 / 有效期 / 漫游地 / 网络速率 / 限速策略 / **运营数据**），**优势项高亮**；
- **资源量柱状对比图**；
- **差异结论摘要**。

如果几个产品都有关联运营数据，还能直接比对"订购量"（订购量 / 去重用户 / 人均订购 / 占比 / 使用率 + 合计行）。

**而且可以继续改**，面板实时刷新：

> `把30日换成15日`（换） · `叠加3GB/日高速档`（加） · `去掉1日档`（减）

少于 2 个产品时面板自动收起，并提示"还需要 1 个产品才能生成比对视图"。

### 4.4 小结

查询助手是三个助手里唯一"不生产数据、只消费数据"的角色，但正是它把另外两个助手连成了一个整体：

- **对研发助手**：提供"存量模板"和历史档案，让新配置有据可依；
- **对运营助手**：提供产品画像核实能力，是"启动产品优化"链路里的第一站；
- **对使用者**：随时把散落的资料（制度、配置、版本、归属）一句话问出来。

## 第五章 · 全局能力：贯穿三个助手的公共设施

这些能力不属于某个助手，但每个助手都用得到，是整台"工作台"的公共设施。

### 5.1 我的草稿（未提交的配置）

右上角铅笔图标，角标显示草稿数。抽屉里列出所有**未提交的产品草稿**（来源：对话式 `dialog` / 文件导入 `batch` / 存量复制 `copy`），点产品即可**继续配置**；提交后自动从草稿移出。

### 5.2 我的产品 / 工单中心（已提交与已上架的产品）

右上角文件图标，标题「**我的产品**」，副标题"产品与工单 · 统一管理"，支持按**产品名 / 工单号 / 模板 / 渠道**搜索。每条工单可：

- 查看「**配置画像（只读）**」；
- 点「**产品运营指标**」→ **自动切到运营助手**并打开该产品视图（跨助手联动）；
- 下架 / 恢复上架。

### 5.3 消息通知与今日待办

右上角铃铛，角标 = **审批中工单数 + 待办未读数**。下拉分两区：

- **我的审批**：列出审批中的工单，点开进审批抽屉；
- **今日待办**（按紧急程度三级）：
  - 🔴 **紧急·异动**：某数据卡新增下滑 35%（持续 7 天）→ 点「**分析**」直接跳进对话做根因分析；
  - 🟡 **重要·整合**：某套餐澳门漫游覆盖待确认 → 点「**跟进处理**」；
  - 🟢 **提醒·合规**：某数据卡资费字段未同步新模板 → 点「**补录**」。

点「进入对话查看详情」，AI 会**主动播报**今日待办，并在消息里渲染可点击的待办卡片。

### 5.4 输入框能力

- **多模态输入**：文件上传、图片上传、**语音输入**（按住说话）、拖拽文件、粘贴；
- **模型切换**：右下角模型胶囊（演示环境为 mock 模型）；
- 消息支持**赞同 / 不赞同 / 复制 / 重新生成**，思考过程可折叠展开。

### 5.5 会话管理

- **新建会话**：一键清空当前对话、复位面板；
- **历史对话检索**：支持按**标题 / 内容 / 工单号**搜索，命中高亮；跨助手命中会特别标记；
- **删除会话**：hover 历史项即可删除。
