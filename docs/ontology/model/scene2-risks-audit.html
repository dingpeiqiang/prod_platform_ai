需求建模结构推理过程体验

高风险产品稽核：需求 · 本体建模 · 推理过程

货架上那些"看着就不对"的商品，得在出事前挑出来。判定不靠人盯，也不靠模型猜，靠本体规则逐条过筛。

一、场景需求

在架商品里混着零元资费、全额白送、长期没人买、低效占坑的货。稽核要给出违规结论、风险等级和处置话术，并且每条结论都能追到具体数值。

难点

  • 风险种类杂，判据字段各不相同，人肉核对看不过来
  • 单个问题能忍，几个问题叠在一起还压着不复核才是真事故
  • 等级靠人拍，同一商品两个人能给两个结论
  • 结论说不清依据，整改就没有抓手

做法

  • 每类风险一条规则，阈值统一挂命名个体，随时可调
  • 先把单点风险归并成"高风险"，再按在架时长升级为"紧急复核"
  • 等级、评分、处置动作全部由规则算出，不交给模型
  • 结论随证据三元组一起下发，可以逐项回查

输入是商品编码清单（也可空跑全量）。费用、销量、在架天数、白名单、战略标签全部由服务端从货架图取，用户不提供任何判据。

二、本体建模结构

关键决策：风险结论全部落在商品身上，都是 :Offering 的子类。风险的主体就是商品本身，没有第二类证据实体。

阈值做成八个命名个体挂在 :ThresholdHolder 下，规则体只写 ?t 占位，运行时按 ops_rules.json 覆写值。规则骨架恒定，业务调阈值不用改 TTL。

规则前置判据（须同时满足）默认阈值结论
R-B01 零元—月费 = 0 且 一次性费 = 0 且 不在白名单—零元资费
R-B01 白送—折扣 ≥ 阈值 且 可重复订购 且 无目标客户群100%异常全额赠送
R-B02已零元仍在架 且 无合约—零元无合约在架
R-B03—近 30 日销量 = 0 且 在架天数 > 阈值180 天长期零销
R-B04—低效品类 且 收入后 5% 且 无战略标签后 5%低效产商品
R-B05已高风险在架天数 > 阈值30 天紧急复核
R-B02 的前置是「已判为零元」，R-B05 的前置是「已判为高风险」。没有前一级结论，后一级就不成立，这是把零散问题串成事故等级的关键。

三、本体推理过程

以样例里真实存在的 84176765（校园迎新体验包 0 元）为例：零元、在架 45 天、无合约。推理机先查单点风险，再由归并层升级，最后读结论。

三档评分固定：HIGH 基分 92、MEDIUM 70、LOW 40；紧急复核再加 5 分并封顶 99。清单按分数倒序输出，高危压在最上面。

非命中 / 兜底情形处理
商品编码不在货架图，或已下架不计入结果，扫描总数照常累计
规则一条都没命中不出现在清单里，不占用待处置位
SWRL 关闭 / 规则配置为 java跳过推理，走同逻辑的 Java 判定
推理抛异常记 warn，整批降级为 Java，引擎字段标 fallback-java

四、体验

需后端已启动（默认 localhost:6174）。填一个或多个商品编码，逗号分隔；留空则稽核全部在架商品。

五、边界


    
  
  • 只稽核在架商品，已下架的不计入；商品清单为空时按全量跑。
    • 
  
  • 低效占比按当前货架收入分布现算，货架变化后同一商品的结论可能变动。
    • 
  
  • 风险结论不落库，处置只在本次响应里，不产生工单。
    • 
  
  • 白名单按标签或名称包含匹配，改名可能误判为白名单。
