# 工作流配置规范文档

## 1. 概述

本文档定义了工作流配置的 JSON 结构规范，确保工作流配置与解析的一致性和可维护性。

**核心原则**：工作流节点的出入参配置使用**数组格式**，因为每条配置都需要多个字段来描述（名称、值/来源、类型、描述等），字典格式无法表达这种多字段结构。

> **v1.1 重要变更**：工作流的执行权已收归**后端固定流程引擎**（见《固定流程引擎设计文档》与《业务驱动改造方案》§12）。
> - 本规范新增节点执行语义字段（`timeoutMs`/`retry`/`onFailure`，§3.3）与 condition 节点分支规范（§3.4）
> - 前端编辑器仅承担**编辑与监控**职责，不再执行流程（前端 DFS 引擎将拆除）
> - 定义期校验（无环/工具存在/引用合法/condition 兜底分支）在**保存/发布时**由引擎执行——发布即绿灯

## 2. 工作流配置整体结构

```json
{
  "id": "workflow-unique-id",
  "name": "工作流名称",
  "description": "工作流描述",
  "version": "1.0.0",
  "created_at": "2024-01-01T00:00:00Z",
  "updated_at": "2024-01-01T00:00:00Z",
  "nodes": [],
  "connections": []
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 工作流唯一标识（UUID 或自定义唯一字符串） |
| `name` | string | 是 | 工作流显示名称 |
| `description` | string | 否 | 工作流描述说明 |
| `version` | string | 是 | 版本号（遵循语义化版本规范） |
| `created_at` | string | 是 | 创建时间（ISO 8601 格式） |
| `updated_at` | string | 是 | 更新时间（ISO 8601 格式） |
| `nodes` | array | 是 | 节点配置列表 |
| `connections` | array | 是 | 节点连接关系列表 |

## 3. 节点配置规范

### 3.1 节点基础结构

```json
{
  "id": "node-unique-id",
  "type": "workflow.call_llm",
  "name": "节点显示名称",
  "position": { "x": 0, "y": 0 },
  "action": "workflow.call_llm",
  "action_params": {}
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 节点唯一标识 |
| `type` | string | 是 | 节点类型（与 `action` 一致） |
| `name` | string | 否 | 节点显示名称 |
| `position` | object | 否 | 编辑器位置信息 |
| `action` | string | 是 | 节点执行动作标识 |
| `action_params` | object | 是 | 节点配置参数 |

### 3.2 节点类型列表

**引擎支持的节点类型（v1.1，首发 7 种）**：

| 节点类型 | action 值 | 说明 |
|---------|-----------|------|
| 流程开始 | `flow.start` | 流程起始节点，承载结构化入参 |
| 流程结束 | `flow.end` | 流程结束节点，声明流程输出 |
| 调用工具 | `flow.tool` | 调用 `AgentTool` 注册表中的真实工具 |
| LLM 调用 | `flow.llm` | 调用大语言模型（prompt 模板 + 变量注入） |
| 条件分支 | `flow.condition` | SpEL 表达式，多分支显式路由（见 §3.4） |
| 人工节点 | `flow.human` | 挂起等待人工确认/填表后恢复（支持 TTL） |
| HTTP 请求 | `flow.http` | 调用外部系统接口 |

**暂不进入引擎的类型**（编辑器可画，定义期校验将拒绝发布）：

| 原类型 | 处置 |
|--------|------|
| `workflow.execute_code` | 二期单独评审（沙箱安全） |
| `workflow.set_variable` | 能力由变量解析承担，无需独立节点 |
| `workflow.ask_user` | 并入 `flow.human`（挂起时下发表单 schema） |
| `workflow.merge_results` | 由变量引用 `{{node-id.output.*}}` 天然表达 |
| loop/循环 | 不做循环节点；批量迭代需求封装为 AgentTool（方案 §12.1 判据） |

### 3.3 节点执行语义字段（v1.1 新增）

所有可执行节点（tool/llm/http）支持以下语义字段：

```json
{
  "action_params": {
    "timeoutMs": 30000,
    "retry": { "maxAttempts": 2, "backoffMs": 1000 },
    "onFailure": "fail"
  }
}
```

| 字段 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `timeoutMs` | 否 | 30000 | 节点执行超时；超时按失败处理 |
| `retry.maxAttempts` | 否 | 0 | 失败重试次数（0=不重试；重试策略必须显式声明） |
| `retry.backoffMs` | 否 | 1000 | 重试退避间隔 |
| `onFailure` | 否 | `fail` | `fail`（流程失败）/ `continue`（记录失败继续，下游标 skipped） |

### 3.4 条件分支节点规范（v1.1 新增）

```json
{
  "type": "flow.condition",
  "action": "flow.condition",
  "action_params": {
    "branches": [
      { "id": "high-risk", "expression": "${node-tool-001.output.riskLevel} == 'HIGH'", "label": "高风险 → 人工审批" },
      { "id": "pass", "expression": "default", "label": "通过 → 自动提交" }
    ]
  }
}
```

**强制规则**（定义期校验）：
- 分支按声明顺序求值，首个为 true 的命中；`expression: "default"` 为兜底分支，**每个 condition 节点必须声明**，否则发布被拒
- 表达式语法与安全约束见《固定流程引擎设计文档》§5（SpEL 沙箱，长度 ≤500，禁类型引用）
- 分支命中依据（表达式+求值结果）自动写入节点执行记录，供审计回溯

## 4. 参数配置规范

### 4.1 入参配置（inputParams）

**格式**：数组，每项为一个入参配置对象。

```json
{
  "inputParams": [
    {
      "name": "param_name",
      "value": "{{flow.user_input}}",
      "description": "参数描述"
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 参数名称 |
| `value` | any | 是 | 参数值（支持变量引用 `{{变量路径}}`） |
| `description` | string | 否 | 参数描述 |

### 4.2 出参配置（outputParams）

**格式**：数组，每项为一个出参配置对象。

出参支持两种配置方式：
1. **新增出参变量（input）**：定义新的变量名并指定数据来源
2. **引用已有变量（reference）**：将已有变量的值作为输出，参数名和值均来自引用变量

```json
{
  "outputParams": [
    {
      "name": "output_field_name",
      "nameType": "input",
      "nameRef": "",
      "source": "response_json",
      "type": "string",
      "description": "输出字段描述"
    },
    {
      "name": "",
      "nameType": "reference",
      "nameRef": "llm_output.result",
      "source": "llm_output.result",
      "type": "string",
      "description": "引用已有变量"
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 输出字段名称（nameType=input 时必填） |
| `nameType` | string | 否 | 参数名称模式：`input`（新增出参）/ `reference`（引用变量），默认 `input` |
| `nameRef` | string | 否 | 引用变量路径（nameType=reference 时必填，参数名和值均从该变量获取） |
| `source` | string | 是 | 数据源路径 |
| `type` | string | 否 | 输出类型（见下表） |
| `description` | string | 否 | 字段描述 |

**outputParams.type 取值说明**：

| 值 | 说明 |
|----|------|
| `string` | 输出为字符串（对象自动转为 JSON 字符串） |
| `object` | 输出为对象（JSON 字符串自动解析） |
| 空/其他 | 保持原始类型不变 |

**outputParams.source 取值说明**（适用于 LLM 节点）：

| 值 | 说明 |
|----|------|
| `response` | LLM 返回的原始响应字符串 |
| `model` | 使用的模型名称 |
| `response_json` | 解析后的 JSON 对象 |
| `field_name` | JSON 对象中的指定字段名 |

## 5. 变量引用规范

### 5.1 变量引用格式

```
{{变量路径}}
```

### 5.2 变量路径规则

| 变量类型 | 格式示例 | 说明 |
|---------|---------|------|
| 流程变量 | `{{flow.user_input}}` | 流程级别的全局变量 |
| 节点输出 | `{{node-id.output.field_name}}` | 指定节点的输出字段 |
| 系统变量 | `{{system.timestamp}}` | 系统内置变量 |
| 上下文变量 | `{{context.xxx}}` | 会话上下文变量 |

### 5.3 变量引用示例

```json
{
  "action_params": {
    "prompt": "用户输入：{{flow.user_input}}\n请分析并提取关键信息",
    "inputParams": [
      { "name": "order_id", "value": "{{extract-node.output.order_id}}" }
    ]
  }
}
```

## 6. 连接配置规范

```json
{
  "connections": [
    {
      "source": "node-a",
      "target": "node-b",
      "sourceHandle": "output",
      "targetHandle": "input"
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `source` | string | 是 | 源节点 ID |
| `target` | string | 是 | 目标节点 ID |
| `sourceHandle` | string | 否 | 源节点输出端口 |
| `targetHandle` | string | 否 | 目标节点输入端口 |

## 7. 完整配置示例

```json
{
  "id": "workflow-tariff-analysis",
  "name": "套餐分析工作流",
  "description": "分析用户输入并提取套餐信息",
  "version": "1.0.0",
  "created_at": "2024-01-01T10:00:00Z",
  "updated_at": "2024-01-01T10:00:00Z",
  "nodes": [
    {
      "id": "start-node",
      "type": "workflow.start",
      "name": "开始",
      "position": { "x": 100, "y": 200 },
      "action": "workflow.start",
      "action_params": {
        "inputParams": [
          { "name": "user_input", "value": "{{flow.user_input}}" }
        ]
      }
    },
    {
      "id": "llm-extract",
      "type": "workflow.call_llm",
      "name": "提取套餐信息",
      "position": { "x": 300, "y": 200 },
      "action": "workflow.call_llm",
      "action_params": {
        "prompt": "请从以下用户输入中提取套餐编码：\n{{start-node.output.user_input}}",
        "model": "qwen-plus",
        "temperature": 0.7,
        "outputParams": [
          { "name": "tariff_code", "source": "tariff_code", "type": "string", "description": "套餐编码" },
          { "name": "input_json", "source": "response_json", "type": "string", "description": "完整JSON输出" }
        ]
      }
    },
    {
      "id": "end-node",
      "type": "workflow.end",
      "name": "结束",
      "position": { "x": 500, "y": 200 },
      "action": "workflow.end",
      "action_params": {}
    }
  ],
  "connections": [
    { "source": "start-node", "target": "llm-extract" },
    { "source": "llm-extract", "target": "end-node" }
  ]
}
```

## 8. 配置校验规则

> v1.1：以下校验全部由后端引擎在**保存/发布时**执行（定义期守门，发布即绿灯）；运行期不再出现"图本身非法"的失败类别。

### 8.1 必需字段校验

| 校验项 | 规则 |
|--------|------|
| 工作流 ID | 非空且唯一 |
| 节点 ID | 非空且在工作流内唯一 |
| 节点 action | 必须是引擎已注册的节点类型（§3.2 引擎支持列表） |
| 连接关系 | source 和 target 必须指向有效节点 |
| condition 节点 | 必须声明 `default` 兜底分支 |
| tool 节点 | `toolName` 必须存在于 `AgentTool` 注册表 |
| 变量引用 | 引用的节点必须存在且在当前路径的上游 |

### 8.2 变量引用校验

- 引用的节点必须存在于工作流配置中
- 引用的字段必须在目标节点的输出配置中声明
- 循环引用检测（节点不能引用自身或形成循环依赖——DAG 校验，有环发布被拒）

### 8.3 数据类型校验

- `version` 字段必须符合语义化版本格式
- `created_at`/`updated_at` 必须符合 ISO 8601 时间格式
- `position.x`/`position.y` 必须是数字类型

### 8.4 执行语义校验（v1.1 新增）

- `timeoutMs` 为正整数，上限 300000（5 分钟）
- `retry.maxAttempts` ∈ [0, 5]
- condition 表达式非空、长度 ≤500、定义期空跑求值通过（语法合法）
- 引用外部工具/HTTP 的节点必须显式声明超时策略（或接受默认值）

## 9. 命名规范

### 9.1 JSON 字段命名

**统一使用 snake_case**

```json
// ✅ 正确
{
  "input_params": [],
  "output_params": [],
  "user_input": "value"
}

// ❌ 错误
{
  "inputParams": [],
  "outputParams": [],
  "userInput": "value"
}
```

### 9.2 节点 ID 命名

- 使用小写字母、数字和连字符
- 避免使用特殊字符
- 建议格式：`node-type-unique-suffix`

```
// ✅ 正确
llm-extract-info
call-tool-query
http-request-api

// ❌ 错误
LLMExtractInfo
call_tool_query
node_123
```
