# 模型连接测试错误日志优化说明

## 问题描述

之前当模型连接测试失败时，前端只显示"✗ 模型连接测试失败"，没有任何详细的错误信息或日志，导致无法排查问题。

## 根本原因

1. **OpenAIProvider.call_sync 方法吞掉了所有异常**：当请求失败时，只是简单地返回 `None`，没有记录任何错误信息
2. **缺少详细的日志记录**：没有在关键步骤记录日志
3. **前端没有显示详细错误**：即使后端返回了错误信息，前端也没有展示

## 修复内容

### 1. 后端 - OpenAIProvider 增强错误处理

**文件**: `backend/app/services/llm/openai_provider.py`

#### 主要改进：

1. **添加 logger**：
```python
import logging
logger = logging.getLogger("llm.openai")
```

2. **增强 call_sync 方法的错误处理**：
   - 配置检查：记录 base_url 和 api_key 是否完整
   - 请求开始：记录 URL 和 Model 信息
   - HTTP 错误：提取并记录详细的错误消息
   - 超时处理：专门捕获 Timeout 异常
   - 连接错误：专门捕获 ConnectionError 异常
   - 网络异常：捕获其他 RequestException
   - 未知错误：捕获所有其他异常并记录堆栈跟踪

3. **抛出异常而非返回 None**：让调用者能够知道具体发生了什么错误

#### 示例日志输出：

```
19:35:26.144 [WARNING ] llm.openai: [OpenAIProvider] 配置不完整 - base_url: False, api_key: False
19:35:26.144 [INFO    ] llm.openai: [OpenAIProvider] 开始同步调用 - URL: http://invalid-url/v1/chat/completions, Model: test-model
19:35:26.962 [ERROR   ] llm.openai: [OpenAIProvider] 请求失败 - HTTP 401: Incorrect API key provided
19:35:26.962 [ERROR   ] llm.openai: [OpenAIProvider] 未知错误: HTTP 401: Incorrect API key provided
Traceback (most recent call last):
  ...
```

### 2. 后端 - API 接口增强错误返回

**文件**: `backend/app/api/chat.py`

#### 主要改进：

1. **添加详细的日志记录**：
   - 测试开始：记录 Provider 和 Model
   - 测试成功：记录成功信息
   - 测试失败：记录详细错误信息和堆栈跟踪

2. **返回详细的错误信息**：
   - 添加 `detail` 字段包含原始错误消息
   - 针对不同错误类型返回友好的提示信息
   - 成功时返回响应预览

3. **捕获 call_sync 的异常**：确保异常能被正确处理和记录

#### 返回格式示例：

**成功**：
```json
{
  "success": true,
  "message": "模型连接测试成功",
  "provider": "openai",
  "model": "qwen-vl-plus-2025-05-07",
  "response_preview": "Hello! How can I help you today?"
}
```

**失败**：
```json
{
  "success": false,
  "message": "认证失败: API Key 无效或已过期",
  "detail": "HTTP 401: Incorrect API key provided. For details, see: https://help.aliyun.com/..."
}
```

### 3. 前端 - 显示详细错误信息

**文件**: `frontend/src/components/ModelSelector.vue`

#### 主要改进：

1. **显示成功时的响应预览**：
```javascript
if (result.response_preview) {
  successMsg += `\n响应预览: ${result.response_preview}`
}
```

2. **显示详细的错误信息**：
```javascript
let errorMsg = '✗ ' + (result.message || '测试失败')
if (result.detail && result.detail !== result.message) {
  errorMsg += `\n详细信息: ${result.detail}`
}
```

3. **添加控制台日志**：便于调试

## 使用方法

### 查看日志

1. **控制台输出**：启动后端服务后，所有日志会实时显示在控制台
2. **日志文件**：查看 `backend/logs/app.log` 文件（注意：Windows 下可能有编码问题）

### 常见错误及解决方案

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| 配置不完整 - base_url: False, api_key: False | .env 文件未配置或配置为空 | 检查 `backend/.env` 文件中的 LLM_API_KEY 和 LLM_BASE_URL |
| HTTP 401: Incorrect API key | API Key 无效或已过期 | 检查 API Key 是否正确，是否已过期 |
| HTTP 403: Forbidden | 权限不足 | 确认 API Key 有访问该模型的权限 |
| HTTP 404: Not Found | 模型不存在或路径错误 | 检查模型名称和 base_url 是否正确 |
| 连接失败: 无法连接到指定的服务器 | 网络问题或服务器不可达 | 检查网络连接和服务器地址 |
| 连接超时: 服务器响应时间过长 | 服务器响应慢或网络延迟 | 检查网络状况，或增加 timeout 值 |
| SSL 证书错误 | HTTPS 证书问题 | 检查证书配置或使用 http |
