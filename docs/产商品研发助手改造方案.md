## 1. 背景与问题定性

产商品研发助手（scene=rd）当前存在三类结构性问题：

| # | 问题 | 典型症状 | 根因 |
|---|------|---------|------|
| P1 | 业务硬编码 | "备案公示"专属资产散落 13+ 文件；PS_* 策略集 switch 写死；模板引擎按"家庭融合"场景名分支 | 业务知识以代码/常量形态存在，新增一个业务需改 N 处 |
| P2 | 对话链路无工作流通道 | 用户说"把 XX 提交审批"时，LLM 无流程可调，只能靠关键词路由（FlowIntentRouter）字面匹配，长尾话术全部漏掉 | 白名单无 flow 工具、prompt 无流程清单、无 flow_execute 工具 |
| P3 | 演示残留 | OF-HF-128、家庭融合畅享128、10086 话术等写死在提示词/兜底文案/测试用例中 | 演示用例未与生产代码隔离 |

改造总原则（继承上位文档）：
- **LLM 只进节点不进引擎**：条件求值、路由锚点必须是确定性代码
- **引擎入口不收自由文本**：workflow_code + 版本锁定为确定性锚点，LLM 只做能力选择
- **双轨灰度**：关键词路由（快）与 LLM 语义路由（慢）并行，逐步接管

### 2.2 LLM → 工作流链路打通（P2 主修复）

新建 `FlowExecuteTool`（`service/agent/tool/flow/FlowExecuteTool.java`），完整链路：

```
用户话术 → AgentOrchestrator
  ├─ 快路径：FlowIntentRouter.tryRoute() 关键词命中 → 直接执行（不变）
  └─ 慢路径（新增）：
       DefaultUnderstander.buildSystemPrompt()
         └─ buildFlowCapabilitySection()：注入已发布流程清单（code/名称/触发词）
       LLM 输出 {intent, tools:["flow_execute"], params:{workflow_code, input_data}}
         ↓ 守门①白名单：KNOWN_TOOLS / RD_KNOWN_TOOLS 已含 flow_execute
         ↓ 守门②流程注册表：workflow_code 必须命中 FlowIntentRouter.listRoutes()
         ↓   不合法 → 剔除该工具；剔除后无工具 → null → chatPlan() 统一回复话术
       FlowExecuteTool.execute()
         └─ FlowEngineService.startExecution(code, null, inputData, null)（版本自动锁定）
```

关键设计点：

| 点 | 说明 |
|----|------|
| 能力清单注入 | `buildFlowCapabilitySection()`（DefaultUnderstander.java:928）从路由注册表读已发布流程；**注册表为空时不注入**，不给 LLM 编造空间 |
| 双重守门 | 白名单（防编造工具名）+ workflow_code 注册表校验（防编造流程码，DefaultUnderstander.java:445 起的守门块 + `hasRegisteredFlow()`） |
| 循环依赖解法 | FlowExecuteTool ← ObjectProvider&lt;FlowEngineService&gt; 延迟解析（打破 flowExecuteTool→Engine→ToolExecutionService→List&lt;AgentTool&gt; 环），与项目既有模式一致 |
| 统一回复话术兜底 | 找不到匹配流程时走 CHAT 链路，由 LLM 生成"无法办理"说明，**绝不猜测执行** |
| 思考面板文案 | ThinkingCopy：TOOL_COPY["flow_execute"]="执行固定流程"、ACTION_DISPLAY["FLOW_EXEC"]="流程执行" |
| 输出契约 | nl_answer(SUMMARY)/status/execution_id(BUSINESS_ENTITY_ID)/conclusion(CONCLUSION)/flow_execution，编排层通用渲染零改动 |

设计铁律合规性论证：「LLM 从能力清单选 workflow_code」未违背路由确定性——确定性锚点已从"关键词匹配"移到"workflow_code + 引擎版本锁定"，LLM 只做能力选择不做流程内判定；流程内 LLM 仅出现在 llm 节点（铁律二不变）。
