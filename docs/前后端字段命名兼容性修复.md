# 前后端字段命名兼容性问题修复

## 🐛 问题描述

用户在前端点击"测试连接"时，后端日志显示：

```
22:06:19.035 [WARNING ] llm.openai : LLM 配置不完整！请通过前端界面配置模型参数。
22:06:19.035 [WARNING ] llm.openai : [OpenAIProvider] 配置不完整 - base_url: False, api_key: False
22:06:19.038 [WARNING ] chat_api   : [ModelTest] 测试失败 - 返回值为 None
```

**问题**：前端发送的配置没有被 Provider 正确接收。

## 🔍 问题分析

### 根本原因：前后端命名风格不一致

#### 前端发送（下划线命名）
```javascript
// ModelSelector.vue
{
  provider: "custom",
  model: "minimax-m2.7",
  api_key: "cb3a5cb469de1d0820d25a1e6349306dc4482f90",  // ✅ 下划线
  base_url: "https://aicp.teamshub.com/openai/api/v1/openai/v1",  // ✅ 下划线
  temperature: 0.3,
  max_tokens: 2048,  // ✅ 下划线
  thinking: false
}
```

#### 后端期望（驼峰命名）
```python
# openai_provider.py
self.api_key = config.get('apiKey', '')  # ❌ 期望驼峰
self.base_url = config.get('baseUrl', '')  # ❌ 期望驼峰
self.max_tokens = config.get('maxTokens', 2048)  # ❌ 期望驼峰
```

**结果**：`config.get('apiKey')` 返回 `None`，导致配置不完整。

## ✅ 解决方案

### 修改后端 Provider，兼容两种命名方式

**文件**: `backend/app/services/llm/openai_provider.py`

#### 修改前
```python
def __init__(self, config: Dict[str, Any]):
    super().__init__(config)
    settings = get_settings()
    
    # 只支持驼峰命名
    self.api_key = config.get('apiKey', '') or (settings.LLM_API_KEY.strip() if settings.LLM_API_KEY else '')
    self.base_url = config.get('baseUrl', '') or (settings.LLM_BASE_URL.strip() if settings.LLM_BASE_URL else '')
    self.temperature = config.get('temperature', 0.3)
    self.max_tokens = config.get('maxTokens', 2048)
    self.max_input_tokens = config.get('maxInputTokens', 180000)
```

#### 修改后
```python
def __init__(self, config: Dict[str, Any]):
    super().__init__(config)
    settings = get_settings()
    
    # ✅ 兼容驼峰和下划线两种命名方式
    self.api_key = (
        config.get('apiKey') or config.get('api_key') or ''
    ) or (settings.LLM_API_KEY.strip() if settings.LLM_API_KEY else '')
    
    self.base_url = (
        config.get('baseUrl') or config.get('base_url') or ''
    ) or (settings.LLM_BASE_URL.strip() if settings.LLM_BASE_URL else '')
    
    # 如果 config 中没有提供 model，使用 .env 的默认值
    if not self.model and settings.LLM_MODEL:
        self.model = settings.LLM_MODEL.strip()
    
    # 检查配置完整性，给出友好提示
    if not self.api_key or not self.base_url:
        logger.warning(
            "LLM 配置不完整！请通过前端界面配置模型参数。\n"
            "访问 http://localhost:5173，在侧边栏找到'模型配置'面板进行设置。"
        )
    
    # ✅ 兼容两种命名方式
    self.temperature = config.get('temperature', 0.3)
    self.max_tokens = config.get('maxTokens') or config.get('max_tokens') or 2048
    self.max_input_tokens = config.get('maxInputTokens') or config.get('max_input_tokens') or 180000
```

## 🎯 设计原则

### 1. 向后兼容

同时支持旧代码（驼峰命名）和新代码（下划线命名），确保：
- ✅ 旧的 API 调用不会中断
- ✅ 新的前端代码可以正常工作
- ✅ 平滑过渡，无需一次性修改所有代码

### 2. 优先级策略

```python
# 优先级：驼峰 > 下划线 > 默认值
value = config.get('camelCase') or config.get('snake_case') or default_value
```

**原因**：
- 优先使用驼峰命名，保持与旧代码的兼容性
- 其次尝试下划线命名，支持新代码
- 最后使用默认值作为兜底

### 3. 统一规范

虽然代码兼容两种命名，但建议：
- **前端 JavaScript**：变量用驼峰，API 请求用下划线
- **后端 Python**：统一使用下划线
- **数据库**：统一使用下划线

## 📊 命名转换对照表

| 字段 | 驼峰命名 (camelCase) | 下划线命名 (snake_case) | 说明 |
|------|---------------------|------------------------|------|
| API Key | `apiKey` | `api_key` | 认证密钥 |
| Base URL | `baseUrl` | `base_url` | API 基础地址 |
| Max Tokens | `maxTokens` | `max_tokens` | 最大输出 token 数 |
| Max Input Tokens | `maxInputTokens` | `max_input_tokens` | 最大输入 token 数 |
| User Identifier | `userIdentifier` | `user_identifier` | 用户标识 |
| Config Name | `configName` | `config_name` | 配置名称 |

## 💡 最佳实践建议

### 1. 前端开发

```javascript
// ✅ 推荐：使用统一的命名转换函数
import { snakeCase } from 'lodash-es'

const frontendData = {
  apiKey: 'sk-xxx',
  baseUrl: 'https://...',
  maxTokens: 2048
}

// 发送前转换为下划线
const requestData = Object.keys(frontendData).reduce((acc, key) => {
  acc[snakeCase(key)] = frontendData[key]
  return acc
}, {})

fetch('/api/v1/llm-config/save', {
  method: 'POST',
  body: JSON.stringify(requestData)
})
```

### 2. 后端开发

```python
# ✅ 推荐：使用 Pydantic 的 alias 功能
from pydantic import BaseModel, Field

class LLMConfigRequest(BaseModel):
    api_key: str = Field(alias='apiKey')  # 接受 apiKey，存储为 api_key
    base_url: str = Field(alias='baseUrl')
    max_tokens: int = Field(alias='maxTokens', default=2048)
    
    class Config:
        populate_by_name = True  # 同时接受别名和原名
```

### 3. TypeScript 类型定义

```typescript
// 前端 TypeScript 接口
interface LLMConfigRequest {
  user_identifier: string  // 直接使用下划线，与后端一致
  provider: string
  model: string
  api_key?: string
  base_url?: string
  temperature: number
  max_tokens: number
  thinking: boolean
}
```
