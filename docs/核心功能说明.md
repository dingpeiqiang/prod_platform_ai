## 1. LLM 聊天和意图识别

### 1.1 概述

聊天意图**完全由通用大模型接管**，同时支持规则降级（LLM不可用时）。

### 1.2 架构

```
用户输入
    ↓
POST /api/v1/chat
    ↓
LLM意图识别（优先）
    ↓
    ├─→ intentType: "form" → 生成表单
    │
    └─→ intentType: "chat" → LLM聊天回复
    ↓
规则降级（LLM不可用/失败）
    ↓
关键词识别 → 表单或规则回复
```

### 1.3 API 接口

#### POST /api/v1/chat

**请求：**
```json
{
  "messages": [
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好！有什么可以帮你？"},
    {"role": "user", "content": "帮我填一个销售订单"}
  ]
}
```

**响应（form意图）：**
```json
{
  "success": true,
  "intentType": "form",
  "formCode": "sales_order",
  "extractedFields": {
    "customer_name": "张三"
  }
}
```

**响应（chat意图）：**
```json
{
  "success": true,
  "intentType": "chat",
  "reply": "我是产商品智能助手，我可以帮你...",
  "formCode": null,
  "extractedFields": null
}
```

### 1.4 降级机制

| LLM状态 | 处理方式 |
|---------|---------|
| ✅ 可用 | 完全由LLM识别和回复 |
| ❌ 不可用 | 关键词识别 + 规则回复 |
| ❌ 调用失败 | 关键词识别 + 规则回复 |

### 1.5 配置 LLM

在 `config/app_config.json` 中：

```json
{
  "llm": {
    "enabled": true,
    "apiKey": "your-api-key",
    "baseUrl": "https://api.openai.com/v1",
    "model": "gpt-4",
    "temperature": 0.3,
    "maxTokens": 2048,
    "fallbackToRules": true
  }
}
```

### 1.6 使用示例

#### 聊天对话
```
用户：你好
助手：你好！我是产商品智能助手...

用户：你能做什么？
助手：我可以帮你：1. 生成和填写表单...
```

#### 生成表单
```
用户：帮我填一个请假申请
助手：（意图识别为form）好的，我来帮你生成表单...
（显示请假表单）
```

#### 带字段提取
```
用户：帮我填一个销售订单，客户姓名张三
助手：（提取到customer_name: "张三"）好的，我来帮你生成表单...
（显示销售订单表单，客户姓名字段已自动填充）
```

## 2. AI Skills（Function Calling）

### 2.1 概述

项目已改造为真正的 AI Skills！现在 LLM 可以主动调用这些 Skills（工具）来完成任务。

### 2.2 改造前后对比

| 方面 | 改造前 | 改造后 |
|------|--------|--------|
| Skills定位 | 轻量级业务模块，独立运行 | AI工具（Tools），可被LLM调用 |
| LLM关系 | 独立运行，互不干扰 | LLM可以决定何时调用哪个Skill |
| 命名 | 容易混淆 | 明确：Tools/Function Calling |
| 调用流程 | 先调用Skills，再调用LLM（可选） | LLM决定调用哪些Tools |

### 2.3 三个 AI Skills（Tools）

| 工具名称 | 说明 |
|---------|------|
| **recognize_scene** | 识别用户输入的场景（表单类型） |
| **extract_fields** | 从用户输入中提取字段值 |
| **get_available_forms** | 获取所有可用的表单类型列表 |

### 2.4 ToolRegistry - 工具注册器

#### 功能
- 注册工具定义（名称、描述、参数Schema）
- 获取工具列表（OpenAI Function Calling格式）
- 调用工具执行

#### 工具定义格式
```json
{
  "type": "function",
  "function": {
    "name": "recognize_scene",
    "description": "识别用户输入的场景（表单类型），返回表单编码",
    "parameters": {
      "type": "object",
      "properties": {
        "user_input": {
          "type": "string",
          "description": "用户的原始输入文本"
        }
      },
      "required": ["user_input"]
    }
  }
}
```

### 2.5 API 接口

#### POST /api/v1/chat_with_tools

**请求：**
```json
{
  "messages": [
    {"role": "user", "content": "帮我填一个请假申请，请假天数3天"}
  ]
}
```

**响应：**
```json
{
  "success": true,
  "intentType": "form",
  "formCode": "leave",
  "extractedFields": {
    "leave_days": 3
  },
  "toolCalls": [
    {
      "tool": "recognize_scene",
      "input": "帮我填一个请假申请...",
      "output": "leave"
    },
    {
      "tool": "extract_fields",
      "input": {"user_input": "...", "form_code": "leave"},
      "output": {"leave_days": 3}
    }
  ]
}
```

### 2.6 当前实现状态

| 功能 | 状态 | 说明 |
|------|------|------|
| **ToolRegistry** | ✅ 完成 | 工具注册和调用框架 |
| **三个Tools** | ✅ 完成 | recognize_scene、extract_fields、get_available_forms |
| **提示词** | ✅ 完成 | function_calling.txt |
| **手动工具调用** | ✅ 完成 | 演示工具调用流程 |

### 2.7 LLM 主动调用工具（未来优化）

## 3. 流式输出功能

### 3.1 概述

聊天接口现已支持**真正的流式输出**，用户可以在聊天窗口中看到实时的推理过程和回复内容（打字机效果）。

### 3.2 功能特性

#### 实时推理过程显示

```
🔍 正在分析用户意图...
🧠 调用 LLM 进行意图识别...
✅ 意图识别完成: form/chat
📋 识别到表单类型: leave
📝 提取到 3 个字段
💬 正在生成回复...
🤖 调用 LLM 生成回复...
```

#### 流式文本输出

- **聊天回复**：逐字显示，类似打字机效果
- **表单意图**：显示完整的 JSON 结果
- **Skills Fallback**：同样支持流式输出

### 3.3 事件类型

后端通过 Server-Sent Events (SSE) 发送以下事件类型：

| 事件类型 | 说明 | 示例 |
|---------|------|------|
| `thinking` | 推理过程消息 | "🔍 正在分析用户意图..." |
| `text_start` | 文本开始标志 | - |
| `text` | 文本片段 | "你好" |
| `text_end` | 文本结束标志 | - |
| `result` | 结构化结果（JSON） | 意图识别结果 |
| `done` | 完成标志 | `{"isForm": true}` |
| `error` | 错误信息 | - |

### 3.4 技术实现

#### 后端实现

**文件**: `backend/app/api/chat.py`

```python
async def stream_generator():
    yield f"data: {json.dumps({'type': 'thinking', 'content': '🔍 ...'})}\n\n"
    
    intent_result = llm_service._call_llm_sync(intent_prompt)
    
    for i in range(0, len(reply_text), 2):
        chunk = reply_text[i:i+2]
        yield f"data: {json.dumps({'type': 'text', 'content': chunk})}\n\n"
        await asyncio.sleep(0.03)
    
    yield f"data: {json.dumps({'type': 'done', 'isForm': False})}\n\n"
```

#### 前端集成

```javascript
const response = await fetch('/api/v1/chat/stream', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ messages: [...] })
});

const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  
  const chunk = decoder.decode(value);
  const lines = chunk.split('\n\n');
  
  for (const line of lines) {
    if (line.startsWith('data: ')) {
      const data = JSON.parse(line.slice(6));
      
      switch (data.type) {
        case 'thinking':
          showThinking(data.content);
          break;
        case 'text':
          appendText(data.content);
          break;
        case 'done':
          if (data.isForm) {
            generateForm();
          }
          break;
      }
    }
  }
}
```

### 3.5 配置参数

#### 流式输出速度控制

```python
await asyncio.sleep(0.2)   # 推理步骤延迟，默认 200ms
await asyncio.sleep(0.03)  # 文本输出速度，每 2 个字符延迟 30ms
```

**建议值**：
- 推理步骤：0.2-0.5 秒（让用户看清每个步骤）
- 文本输出：0.02-0.05 秒（流畅的打字机效果）

### 3.7 性能优化

1. **减少延迟**：减少 `asyncio.sleep` 的时间
2. **批量输出**：增加每次输出的字符数
3. **缓存推理步骤**：对于常见问题，缓存推理步骤
