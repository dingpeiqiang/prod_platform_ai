## 🎯 配置架构

### 新的配置优先级

```
┌─────────────────────────────────────┐
│  1. 前端动态配置 (最高优先级)        │
│     - 用户通过 UI 设置               │
│     - 存储在 localStorage           │
│     - 每次请求传递给后端             │
└──────────────┬──────────────────────┘
               │
               ↓
┌─────────────────────────────────────┐
│  2. .env 文件 (Fallback)            │
│     - 仅作为后备配置                 │
│     - 当前已全部注释                │
│     - 未来可作为全局默认值           │
└──────────────┬──────────────────────┘
               │
               ↓
┌─────────────────────────────────────┐
│  3. app_config.json (默认参数)      │
│     - 仅保留非敏感参数              │
│     - temperature, maxTokens 等     │
│     - 作为最后兜底                  │
└─────────────────────────────────────┘
```

### 配置文件用途对比

| 文件 | 之前用途 | 现在用途 |
|------|---------|---------|
| `.env` | LLM + 基础设施 | 仅基础设施 |
| `app_config.json` | LLM + 业务配置 | 仅业务配置（LLM 默认参数） |
| 前端 localStorage | ❌ 不存在 | ✅ LLM 主要配置来源 |
