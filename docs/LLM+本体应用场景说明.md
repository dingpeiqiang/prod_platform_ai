# LLM + 本体 核心业务场景应用说明

| 项 | 内容 |
|---|---|
| **文档定位** | 选取两个最能体现「LLM + 本体」融合价值的核心业务场景，讲清**业务背景 → 本体如何建模 → 两者如何协同 → 业务价值** |
| **适用读者** | 业务人员、产品经理、方案汇报 |

## 一、先建立两个基本认知

**1. 本体是"业务世界的数字地图"**
把业务中的人、事、物和关系建成机器可读、可推理的知识网络：

```
实体：产商品 / 指标 / 渠道 / 竞品 / 促销 / 用户行为
关系：畅享128 —销售渠道→ 代理网点；畅享128 —对标竞品→ 友商20元套餐
规则：渠道订单降超20%且贡献≥30% → 渠道是根因（R-A02）
```

**2. LLM 与本体分工一句话**
**LLM 负责"听懂与说清"，本体负责"事实可信、判定可解释"**——LLM 把业务人员的话翻译成对知识图谱的查询/推理，本体给出确定性结论，LLM 再讲成人话。LLM 不查数（会幻觉）、不定结论（会编），本体不理解人话（要 LLM 翻译）。

## 二、核心场景 1：产商品研发——对话式配置 + 合规校验（RD）

### 业务背景

配置一个新套餐（如"给校园学生上一个月费 59 的附加资费"），研发人员要查模板库、抄相近套餐、逐项填表、再翻规则手册自查合规——**一个配置 30-60 分钟**，且人工核对易漏。

### 本体如何建模

**① 配置知识（是什么、默认什么）**
- **配置方案本体**：配置方案 ↔ 品类（个人主资费/宽带/家庭套餐等 6 类）、销售策略、发布范围、计费方案、优惠、权益、资费相容关系；
- **品类模板**（6 份）：每类产品"必填什么、默认什么、字段怎么联动"显式定义。例：家庭套餐模板规定——选了"分层优惠=是"才出现优惠方式/费用等 5 个字段；`角色数上限 = 手机成员上限 + 宽带成员上限` 自动派生；渠道未说 → 默认"全渠道"。

**② 配置合规规则（什么不能配）**
9 条合规规则（R-C01~C09）显式定义并绑定到品类模板：互斥冲突（R-C03）、附加依赖主资费（R-C04）、零固费红线（R-C05）、必填缺失（R-C06）、异常优惠漏洞（R-C07，如折扣 100% 且可重复计费）、固费上下限（R-C09）。

### LLM + 本体如何协同

```
用户："给家庭用户做一个融合套餐，月费158，带500M宽带，全渠道销售"
   │
   ├─ LLM：抽取业务要素 → {场景=家庭融合, 月费=158, 宽带=500M, 渠道=全渠道}
   │
   ├─ 本体·字段推理：按品类模板补全缺省（语音/流量未说 → 模板默认值补齐）
   │
   ├─ 本体·合规校验：逐条执行 R-C01~C09
   │     发现：与用户现有主套餐互斥冲突（R-C03）→ 拦截
   │
   └─ LLM：把结果讲成人话
        "已按家庭融合模板补全语音300分钟/流量20GB；
         校验发现与主套餐互斥冲突（规则 R-C03），请调整后提交"
```

> **铁律**：合规不通过时，LLM 必须如实说"不可提交"并给出规则编号——**本体结论 AI 不得改写**（提示词层面明文约束）。
>
> 配套场景：**文档批量转配置**（LLM 通读方案文档逐条抽取 → 模板白名单拦住"编造字段" → 本体批量合规 → 待修正区人工确认，2-4 小时 → 分钟级）。

### 业务价值

| 维度 | 价值 |
|------|------|
| **效率** | **30-60 分钟 → 1-2 分钟**；文档批量配置 2-4 小时 → 分钟级 |
| **防幻觉** | 字段抽取受模板白名单约束，LLM 编不出不存在的字段和取值 |
| **合规刚性** | 互斥、零固费、优惠漏洞等红线由规则引擎把守，AI 只解释不裁决，杜绝"幻觉放行" |
| **低门槛** | 业务人员"说话即配置"，不需要懂字段表和规则手册 |
| **可追溯** | 每个默认值、每次拦截都有规则编号，可审计 |

## 三、核心场景 2：产商品运营——异动归因 + 风险稽核（OPS）

### 业务背景

- **异动归因**："畅享128 当月营收环比下降 16%"——运营人员要拉渠道数、竞品数、促销记录，凭经验逐维排查，**1-4 小时**，且各人结论不一；
- **风险稽核**：零资费、低效产品稽核靠人工导清单逐条核，实际**只能抽查**——大量高风险产品处于盲区。

### 本体如何建模

**① 归因规则（SWRL，5 条，阈值外置可调）**

| 规则 | 业务含义 | 判定条件 |
|------|---------|---------|
| R-A01 异动确认 | 指标确实异常 | 指标降幅 ≤ -10% |
| R-A02 渠道归因 | 渠道是主因 | 渠道订单降幅 ≤ -20% 且贡献占比 ≥ 30% |
| R-A03 促销归因 | 促销到期所致 | 促销 7 天内到期 且驱动订单占比 ≥ 25% |
| R-A04 竞品冲击 | 被友商抢客 | 竞品价差 ≥ 15% 且渗透率上升 |
| R-A05 行为变化 | 用户行为变化 | 行为权重 ≥ 8% |

**② 风险规则（R-B01~B05，风险结论直接建模为本体中的"类"——推理命中即自动归类）**
零元资费风险（需白名单/合约）、零元无合约在架、长期零销（在架 180 天销量为 0）、低效产品（收入分位后 5% 且无战略标签）、高风险超期未复核。风险评分模型（高 92 / 中 70 / 低 40）同样外置可调。

### LLM + 本体如何协同

```
【异动归因】告警：畅享128 营收环比 -16%
   ├─ 本体：SWRL 推理逐条点火
   │    R-A01 确认异动 → R-A02 渠道命中（代理渠道订单 -42%，贡献 38%）
   │                    → R-A04 竞品命中（价差 15%）→ 输出根因路径
   └─ LLM：归因报告
        "🔍 主要根因：核心代理渠道佣金调整，办理量降42%（R-A02）
         📊 次要因素：竞品20元套餐分流15%新增（R-A04）
         💡 建议：恢复佣金政策 + 配套短期促销"

【风险稽核】每日定时全量扫描（OpsBatchAuditScheduler）
   ├─ 本体：全量在售产品灌图 → SWRL 批量推理 → 风险分级
   │    "共扫描 8 款零资费产品：高风险 2、中风险 1、低风险 5"
   └─ LLM：处置建议 → 一键生成工单 → 处置结果回写本体（闭环）
```

### 业务价值

| | 异动归因 | 风险稽核 |
|------|---------|---------|
| **效率** | 1-4 小时 → 分钟级 | 人工抽查 → **全量日扫** |
| **可复现** | 同一数据任何人归因结果一致，经验不再"拍脑袋" | 规则日扫常态化，零遗漏零盲区 |
| **可解释** | 每条根因可指认规则与阈值，争议可核查 | 每款高风险产品可指认命中规则与证据 |
| **闭环** | 归因 → 推演（退市影响量化，不写生产数据）→ 工单 → 回写本体 | 稽核 → 研判 → 工单 → 回写，全程留痕 |

## 四、两个场景共同揭示的本体价值

| 价值 | 说明 | LLM 做不到 |
|------|------|-----------|
| **事实可信** | 所有数字与结论来自统一事实图，全公司口径唯一 | LLM 直接"答数"会编 |
| **判定可解释** | 合规/归因/风险结论可指认规则 ID 与阈值，可审计、可复现 | LLM 推理是黑盒 |
| **知识可沉淀** | 品类模板、业务规则、历史方案成为组织资产：可版本化、可回退、可热更 | LLM 知识冻结在训练时刻 |

> **电梯说明**：我们给产商品建了一张业务知识地图（本体）——产品、渠道、竞品、指标、规则都在图上，机器能查、能推、能校验；再配上懂人话的大模型：研发说句话就出合规配置（分钟级），运营一句"收入为什么掉了"就出可复现的归因报告，风险产品全量自动稽核不漏一个——**大模型负责听懂和表达，本体负责让数据和结论可信**。
