# 项目命名规范统一说明

## 📋 核心原则

**前后端通信统一使用 snake_case（下划线命名）**

这是 Python/SQLAlchemy 生态的标准做法，也是现代 API 设计的趋势。

## 🎯 明确答案

### Q: 项目到底用哪种命名规范？

**A: 分层使用不同的命名规范**

| 层级 | 命名规范 | 示例 | 原因 |
|------|---------|------|------|
| **Python 代码** | snake_case | `user_identifier`, `get_user_info` | PEP 8 标准 |
| **数据库字段** | snake_case | `api_key`, `base_url` | SQLAlchemy 默认 |
| **API JSON 数据** | snake_case | `{"api_key": "xxx"}` | 与后端一致 |
| **JavaScript 变量** | camelCase | `userId`, `getUserInfo` | JS 社区标准 |
| **Vue 组件名** | PascalCase | `ModelSelector` | Vue 规范 |

// 或者：使用工具类型自动转换
type SnakeCase<T> = {
  [K in keyof T as K extends string 
    ? K extends `${infer First}${infer Rest}` 
      ? First extends Uppercase<First> 
        ? `_${Lowercase<First>}${Rest}` 
        : K 
      : K
    : K]: T[K]
}

  userId: string
  apiKey: string
  baseUrl: string

### 迁移策略

#### 方案 1：Pydantic Alias（推荐用于旧代码）

```python
from pydantic import BaseModel, Field

class WorkflowCreateRequest(BaseModel):
    # 内部使用 snake_case
    workflow_code: str = Field(alias='workflowCode')
    workflow_name: str = Field(alias='workflowName')
    is_active: bool = Field(alias='isActive', default=True)
    
    class Config:
        populate_by_name = True  # 同时接受两种命名
```

**优点**：
- ✅ 内部统一使用 snake_case
- ✅ 外部可以发送 `workflowCode` 或 `workflow_code`
- ✅ 平滑过渡，不影响现有调用

**缺点**：
- ⚠️ 需要修改所有旧模型
- ⚠️ 增加了一些复杂度

#### 方案 2：手动兼容（当前临时方案）

```python
# openai_provider.py
self.api_key = config.get('apiKey') or config.get('api_key') or ''
self.base_url = config.get('baseUrl') or config.get('base_url') or ''
```

**优点**：
- ✅ 无需修改旧代码
- ✅ 立即生效

**缺点**：
- ⚠️ 代码重复
- ⚠️ 需要维护兼容性逻辑

### 2. 前端工具函数

创建统一的命名转换工具：

```javascript
// utils/naming.js
import { snakeCase, camelCase } from 'lodash-es'

/**
 * 将对象的所有键转换为 snake_case
 */
export function toSnakeCase(obj) {
  if (!obj || typeof obj !== 'object') return obj
  
  const result = {}
  for (const key in obj) {
    if (obj.hasOwnProperty(key)) {
      result[snakeCase(key)] = toSnakeCase(obj[key])
    }
  }
  return result
}

/**
 * 将对象的所有键转换为 camelCase
 */
export function toCamelCase(obj) {
  if (!obj || typeof obj !== 'object') return obj
  
  const result = {}
  for (const key in obj) {
    if (obj.hasOwnProperty(key)) {
      result[camelCase(key)] = toCamelCase(obj[key])
    }
  }
  return result
}

// 使用示例
const frontendData = {
  userId: 'user-123',
  apiKey: 'sk-xxx',
  maxTokens: 2048
}

const backendData = toSnakeCase(frontendData)
// { user_id: 'user-123', api_key: 'sk-xxx', max_tokens: 2048 }
```

### 3. Axios 拦截器（自动转换）

```javascript
// utils/api.js
import axios from 'axios'
import { snakeCase, camelCase } from 'lodash-es'

const api = axios.create({
  baseURL: '/api/v1'
})

// 请求拦截器：自动转换为 snake_case
api.interceptors.request.use(config => {
  if (config.data && typeof config.data === 'object') {
    config.data = toSnakeCase(config.data)
  }
  return config
})

// 响应拦截器：自动转换为 camelCase
api.interceptors.response.use(response => {
  if (response.data && typeof response.data === 'object') {
    response.data = toCamelCase(response.data)
  }
  return response
})

export default api
```

这样前端可以继续使用 camelCase，自动转换对开发者透明。
