# 产品配置落地支撑·实施计划明细

> 依据：《产品配置落地支撑设计方案.md》v1.4（§10 分阶段实施、§11 可行性、§12~§13 运维治理、§14 复杂度评估）
> 目标：将 P1/P2/P3 三阶段拆解为可执行、可验收的任务明细，明确每项任务的内容、挂点文件、产出物、量级与依赖关系。

---

## 0. 总览

| 阶段 | 主题 | 任务数 | 核心验收 |
|------|------|:---:|---------|
| **P1** | 模板抽取 + 双品类验证 + 运维底线 | 7 | 六类模板可列出；`familyBasePrc`/`broadBandMainPrc` 全链路走通；家庭行为回归不变；版本登记 + 热重载可回退 |
| **P2** | 编译 + 抽取/推理配置化 + 发布审核 | 7 | 新增字段仅需改模板；新增产品零代码注册；合规报告等价存量；发布需过 review、回滚可用 |
| **P3** | 模板管理 + 图谱合并（演进） | 6 | 研发自助新增产品类型无需开发介入；智查覆盖新产品；"为什么"可回答 |

**阶段依赖链**：

```
P1(模板仓库+守卫) ──► P2(配置化+门禁) ──► P3(管理+图谱)
      │                                      ▲
      └── P3-4 双世界收敛 / P3-5 监控落盘 可视进度提前 ──┘
```

**里程碑红线（跨阶段）**：

1. 运维治理（P1-5/P1-6）必须与模板仓库**伴生上线**，不得拖至 P3（§12.8：否则 P2"零代码注册"上线即埋雷）。
2. 家庭/校园行为全程不得漂移；`field_code` 与报文投影映射**不改名**；P1 阶段 message_projection 仅观察不接管（§10.1）。
3. SHACL 降档：P1/P2 维持 Java R-C* + compliance_bindings + 轻量约束，SHACL 仅 P3 等价验证通过后接管（§11.4/§11.9）。
4. 复杂度纪律：新增逻辑独立成类，禁止向 `ProductOntologyService`（3758 行/99 方法）继续堆方法（§14.4-1）。
5. derive_rules 与存量 Java 双份逻辑并存**硬性一个迭代周期**，diff 通过后立即清理（§14.4-3）。

### P1-6 last-known-good 快照守卫（§13.2）

| 项 | 说明 |
|----|------|
| 挂点 | `ProductOntologyService#reloadGraph`(L154) / `reloadOpsRules`(L185) / `publishConfigDraft`(L1259) / `loadGraph`(L160) |

| 量级 | 中 |
| 依赖 | P1-5 |
| 产出 | 守卫逻辑（建议独立 `LastKnownGoodGuard` 类）+ 回退测试（SMOKE 段由 P1-7 用例集回接） |

### P2-5 模板生命周期状态机（§13.3）

| 项 | 说明 |
|----|------|
| 状态机 | `draft ──review──► review ──publish(dryrun通过)──► published ──deprecate──► deprecated`；rollback 可从 published/deprecated 回退；编辑新 draft 版本号++ |
| 落点 | 状态流转落在表 A `status`；`ProductTemplateRegistry` 只认 `published` |
| 双源约定 | 模板文件内 `status` 仅作注册种子初值，运行时生效状态以表 A 为准；P1 阶段（无状态机）模板落地即默认按 published 注册 |

| 量级 | 中 |
| 依赖 | P1-6、P2-1 |
| 产出 | 状态机服务（建议 `ProductTemplateService`）+ publish/rollback 端点 |

## 6. 工程纪律清单（对齐 AGENTS.md）

1. **新建类独立**：`ProductTemplateRegistry`/`TemplateToShaclCompiler`/`LastKnownGoodGuard`/`ProductTemplateService`/`OntologyVersionService` 独立成类，禁止并入 `ProductOntologyService`。
2. **拆分存量**：从 `ProductOntologyService`（3758 行）按 SRP 拆出草稿持久化、审计、发布子服务；每拆一个回归一次。
3. **去旧留新**：死代码（`OntologyInstanceService`/`OntologyInstanceController` 空文件）删除；stub 接线或 `@Deprecated` 标注替代方案。
4. **复杂度基线**：圈复杂度≤10、函数≤50 行、类方法≤20、嵌套≤4；新模板/规则变更绑定回归门禁。
5. **命名契约**：元数据 snake_case、`field_code` 草稿 camelCase、JSON 传输统一 snake_case。
6. **测试覆盖**：新增代码测试覆盖率≥80%；P1-7 用例集随 publish 自动执行。
