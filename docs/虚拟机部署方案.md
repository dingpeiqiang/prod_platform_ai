# Prod Platform AI - 虚拟机部署方案

> 场景：当前项目为**容器化部署**（Docker 基础镜像 + 应用镜像），现需改为**虚拟机（VM）部署**。
> 本文档提供单台虚拟机上「前后端分别打包为 tar 包、解压启动」的完整方案。

---

## 1. 方案概述

### 1.1 目标

将 AI 驱动动态表单平台部署到**单台 Linux 虚拟机**，最终形态：

```
用户浏览器
    │  HTTP(S):80/8080
    ▼
┌─────────────────────────────── Linux VM ───────────────────────────────┐
│  Nginx（前端静态资源 + 反向代理）                                          │
│    ├─ /         → Vue dist（静态文件）                                     │
│    ├─ /api/*    → proxy → http://127.0.0.1:6174  （Spring Boot 后端）     │
│    └─ /ws/*     → proxy(websocket) → 127.0.0.1:6174                       │
│                                                                           │
│  Spring Boot 后端（backend-app，JDK17，端口 6174）                         │
│    └─ MySQL 8（prodplatformai 库，端口 3306）                              │
└───────────────────────────────────────────────────────────────────────────┘
```

### 1.2 现存容器化与本次虚拟机化的差异

| 维度 | 容器化（现状） | 虚拟机化（本次） |
|------|----------------|------------------|
| 后端 | 镜像内 JDK17 + Maven，构建期离线打包 | 构建机打 `jar` → 打入 tar 包 → VM 解压直接 `java -jar` 运行 |
| 前端 | 镜像内 vite build → Nginx dist | 构建机 `npm run build` 产出 `dist/` → 打入 tar 包 → VM 解压由系统 Nginx 托管 |
| Nginx | 容器内 `/etc/nginx/nginx.conf`，upstream 为 Docker 服务名 `backend` | 系统 Nginx，upstream 改为 `127.0.0.1:6174` |
| 配置注入 | `-v /config:/config` 挂载 + `--spring.config.additional-location` | tar 包内自带外部 `application-*.yml` + 环境变量（systemd / 启动脚本） |
| 数据库 | H2 内嵌（默认）/ 容器外 MySQL | **MySQL 8**（独立进程，连接串由外部配置注入） |
| 服务托管 | Docker 守护进程 | 建议 systemd（也可用 tar 包内置启停脚本） |

## 2. 架构与组件清单

| 组件 | 技术栈 | 端口 | 部署目录（建议） |
|------|--------|------|------------------|
| 前端静态站 | Vue 3 + Vite 产物 | 由 Nginx 承接，对外 80 | `/opt/prod-ai/frontend/dist` |
| Nginx | 系统包 nginx（1.20+） | 80（对外）/ 本地回环 | `/etc/nginx/` |
| 后端 | Spring Boot 3.4 / JDK 17 | **6174**（仅本机回环） | `/opt/prod-ai/backend` |
| 数据库 | MySQL 8.0+ | 3306（本机） | 系统包，数据目录 `/var/lib/mysql` |
| 数据目录 | 上传/日志/运行时数据 | - | `/opt/prod-ai/data` |

> 后端 6174 只监听 `127.0.0.1`，不直接对外暴露；所有外部流量由 Nginx 统一入口。

## 4. 打包流程（在构建机执行）

> 构建机需有 JDK17 + Maven、Node 20 + npm，能访问依赖仓库（Maven 内网仓库 / npm 镜像）。
> 本项目已提供 **一键打包脚本** `deploy/build-tar.ps1`，自动把后端 jar、前端 dist、配置与**内置启停脚本**打成两个 tar 包。

### 4.1 一键打包（推荐）

```powershell
# 1) 后端编译
cd backend-app
mvn -s .mvn/local-settings.xml -DskipTests clean package

# 2) 前端构建
cd ..\frontend
npm ci
npm run build

# 3) 打包（生成 deploy/out/prod-ai-*.tar.gz）
cd ..
powershell -ExecutionPolicy Bypass -File deploy\build-tar.ps1
```

脚本自动组装两个 tar 包的目录结构，并把 `deploy/backend/bin/start.sh`、`deploy/frontend/bin/install.sh`、systemd 单元、nginx 站点配置、后端 env 模板一并打入：

```
prod-ai-backend.tar.gz/
├── app.jar                    # Spring Boot 可执行包
├── config/application.yml     # 外部配置（docker/config 拷贝，可再覆盖）
├── bin/start.sh               # 启停脚本 {start|stop|restart|status}
├── conf/
│   ├── prod-ai-backend.service   # systemd 单元模板
│   └── backend.env.example       # 敏感环境变量模板（.env 注入）
├── logs/  data/  uploads/     # 运行时目录（空）

prod-ai-frontend.tar.gz/
├── html/                      # Vue dist 静态产物（含 index.html）
├── conf/prod-ai.conf          # Nginx 站点配置（upstream=127.0.0.1:6174）
└── bin/install.sh             # 前端装载/启停 {install|start|stop|reload|status}
```

### 4.2 后端手动打包（可选）

若需自定义配置可手工组装：

```bash
cd backend-app
mvn -s .mvn/local-settings.xml -DskipTests clean package

cd ..
mkdir -p dist-backend/{bin,conf,config,logs,data,uploads}
cp backend-app/target/prod-platform-ai-*.jar          dist-backend/app.jar
cp docker/config/application.yml                       dist-backend/config/
cp deploy/backend/bin/start.sh                         dist-backend/bin/
cp deploy/backend/conf/prod-ai-backend.service        dist-backend/conf/
cp deploy/backend/conf/backend.env.example            dist-backend/conf/
tar -czf prod-ai-backend.tar.gz -C dist-backend .
```

### 4.3 交付物清单

| 产物 | 内容 | VM 上如何用 |
|------|------|-------------|
| `prod-ai-backend.tar.gz` | app.jar、config、bin/start.sh、conf（systemd+env 模板）、logs/data/uploads | 解压至 `/opt/prod-ai/backend`，`bin/start.sh start`（或注册 systemd） |
| `prod-ai-frontend.tar.gz` | html（dist 产物）、conf/prod-ai.conf、bin/install.sh | 解压后 `bin/install.sh install`，装载静态资源 + Nginx 配置并起服务 |

> 建议在构建机与 VM 同版本后，把 tar 包通过内网（scp / 公司发布平台）传输，并在 VM 校验校验和（sha256）。

## 5. VM 部署配置要点

### 5.1 前置软件安装（root）

```bash
# CentOS/Rocky
yum install -y java-17-openjdk nginx mysql-server
# 或 JDK 解压版: 将 jdk-17 放置 /opt/jdk-17，配置 JAVA_HOME

# 启动并开机自启
systemctl enable --now nginx mysqld
```

### 5.2 后端外部配置

后端 jar 内置 `application.yml`（默认 prod，H2 兜底）。VM 部署时通过**外部配置目录** + **环境变量覆盖**注入 MySQL 与 LLM 等，不修改 jar 内配置。

建议在 `config/application-vm.yml`（或环境变量）中覆盖：

```yaml
# dist-backend/config/application.yml 中追加或独立 profile
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/prodplatformai?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    driver-class-name: com.mysql.cj.jdbc.Driver
    username: prodplatformai
    password: ${SPRING_DATASOURCE_PASSWORD}
  sql:
    init:
      mode: never      # MySQL 表结构由 sql/ 脚本维护，不依赖 jar 内嵌 h2 初始化
prodai:
  auth:
    jwt-secret: ${AUTH_JWT_SECRET}
  llm:
    enabled: ${LLM_ENABLED:true}
```

启动时用环境变量注入敏感项（禁止明文入配置）：

```bash
export SPRING_DATASOURCE_PASSWORD='xxxx'
export AUTH_JWT_SECRET='<32+随机字节>'
export LLM_ENABLED=true
```

### 5.3 数据库初始化

在 VM 上（或有权限的 MySQL 管理端）执行 `sql/` 下脚本，顺序：

```bash
# 1) 建库 + 应用账号（root 身份，注意改默认密码）
mysql -uroot -p < sql/00_create_database.sql

# 2) 全量 DDL（全新环境；存量库严禁执行此 DROP+CREATE 脚本）
mysql -uprodplatformai -p prodplatformai < sql/01_full_schema_ddl.sql

# 3) 种子数据（幂等）
mysql -uprodplatformai -p prodplatformai < sql/02_init_data.sql
```

> 详细说明、升级/回滚策略见 `sql/README.md`。首次上线为全新环境，执行 00→01→02 即可。

### 5.4 Nginx（单机反代 + 静态）

将 `prod-ai-frontend.tar.gz` 中的 `html/` 解压到 `/opt/prod-ai/frontend/dist`，`conf/` 放入 Nginx 配置目录。**关键改动**：upstream 从容器服务名 `backend` 改为 `127.0.0.1:6174`。

```nginx
# /etc/nginx/conf.d/prod-ai.conf
upstream backend-prodai {
    server 127.0.0.1:6174;
}

server {
    listen       80;
    server_name  _;

    root   /opt/prod-ai/frontend/dist;
    index  index.html;

    location ^~ /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    location ^~ /api/ {
        proxy_pass http://backend-prodai;
        proxy_http_version 1.1;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_buffering off;          # SSE 需关闭缓冲
        proxy_read_timeout 86400;
        proxy_send_timeout 86400;
    }

    location ^~ /ws/ {
        proxy_pass http://backend-prodai;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 86400;
    }

    # Swagger UI / OpenAPI
    location ^~ /swagger-ui { proxy_pass http://backend-prodai; }
    location ^~ /v3/api-docs { proxy_pass http://backend-prodai; }

    location = /index.html { add_header Cache-Control "no-cache"; }

    location / {
        try_files $uri $uri/ /index.html;
        add_header Cache-Control "no-cache";
    }
}
```

校验并重载：

```bash
nginx -t && systemctl reload nginx
```

> 原 `frontend/nginx.conf` 面向容器（`user nginx; listen 6173; root /usr/share/nginx/html`），VM 上应使用系统 Nginx + 上述站点配置，勿直接套用容器版。

## 6. 启动与进程托管（前后端均用 shell 脚本）

> **前后端启停统一走 tar 包内置的 shell 脚本**（`backend/bin/start.sh`、`frontend/bin/install.sh`），
> 不强制依赖 systemd。如需开机自启/崩溃自愈，再按附录将脚本包装为 systemd 单元（可选）。

### 6.1 后端 shell 脚本启停

后端脚本：`/opt/prod-ai/backend/bin/start.sh`，用法：

```bash
# 1) 解压
mkdir -p /opt/prod-ai/backend
tar -xzf prod-ai-backend.tar.gz -C /opt/prod-ai/backend

# 2) 配置环境变量（可选）：cp conf/backend.env.example /etc/prod-ai/backend.env 后填写真实值
mkdir -p /etc/prod-ai
cp /opt/prod-ai/backend/conf/backend.env.example /etc/prod-ai/backend.env
chmod 600 /etc/prod-ai/backend.env   # 并编辑填入库密码/JWT/LLM 开关
# 脚本启动时自动读取 /etc/prod-ai/backend.env（存在则导入）

# 3) 启动 / 停止 / 重启 / 状态
bash /opt/prod-ai/backend/bin/start.sh start
bash /opt/prod-ai/backend/bin/start.sh stop
bash /opt/prod-ai/backend/bin/start.sh restart
bash /opt/prod-ai/backend/bin/start.sh status
```

脚本行为：
- 自动探测 `java`（未找到则报错并提示设置 `JAVA_HOME`）
- 启动时以 `nohup` 后台运行，PID 写入 `backend/app.pid`，控制台日志追加 `backend/logs/app.out`
- 启动参数自带 `--spring.config.additional-location=optional:file:config/`，读取解压根目录下 `config/` 外部配置
- `stop` 优雅终止（最多等 30s 再 `kill -9`）；旧 PID 文件自动清理
- 若 `USE_SYSTEMD=1` 且已配置 systemd 单元，脚本自动转调 `systemctl`（可选增强）

### 6.2 前端 shell 脚本启停

前端脚本：`/opt/prod-ai/frontend/bin/install.sh`，用法：

```bash
# 1) 解压
mkdir -p /opt/prod-ai/frontend
tar -xzf prod-ai-frontend.tar.gz -C /opt/prod-ai/frontend

# 2) 装载静态资源 + Nginx 站点配置，并启动/重载 Nginx（需 root）
bash /opt/prod-ai/frontend/bin/install.sh install

# 3) 常规管理
bash /opt/prod-ai/frontend/bin/install.sh start    # 启动 Nginx
bash /opt/prod-ai/frontend/bin/install.sh reload   # 变更配置/产物后重载
bash /opt/prod-ai/frontend/bin/install.sh stop     # 停止 Nginx
bash /opt/prod-ai/frontend/bin/install.sh status   # 状态 + 前端首页连通性
```

脚本行为：
- `install`：把 `html/` 覆盖到 `/opt/prod-ai/frontend/dist`，把 `conf/prod-ai.conf` 拷到 `/etc/nginx/conf.d/`，随后 `nginx -t` 校验并重载
- 优先使用 `systemctl` 管理 Nginx（存在 nginx.service 时），否则回退到 `nginx -s` 原生管理
- 端口默认 80，可用环境变量 `NGINX_PORT` 覆盖

### 6.3 可选：包装为 systemd 以支持开机自启 / 崩溃自愈

> 纯 shell 脚本不放 systemd 也能完整启停；若需开机自动拉起，按下面把启动脚本包一层（脚本内已支持 `USE_SYSTEMD=1` 转调）。

**后端** `conf/prod-ai-backend.service`（tar 包已内置）：

```ini
[Unit]
Description=Prod Platform AI Backend (Spring Boot)
After=network.target mysqld.service
Requires=mysqld.service

[Service]
Type=simple
User=prod-ai
Group=prod-ai
WorkingDirectory=/opt/prod-ai/backend
EnvironmentFile=/etc/prod-ai/backend.env
ExecStart=/usr/bin/java -Xms1g -Xmx3g -Dfile.encoding=UTF-8 \
    -jar /opt/prod-ai/backend/app.jar \
    --server.port=6174 \
    --spring.config.additional-location=optional:file:/opt/prod-ai/backend/config/
Restart=on-failure
RestartSec=10
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
```

```bash
useradd -r -s /sbin/nologin prod-ai
cp /opt/prod-ai/backend/conf/prod-ai-backend.service /etc/systemd/system/
chown -R prod-ai:prod-ai /opt/prod-ai/backend
systemctl daemon-reload
systemctl enable --now prod-ai-backend
```

> 用 systemd 后就不再用 `bin/start.sh` 手动启停（二者管理同一进程会冲突）；以 systemd 为准。

**前端** Nginx 本身已是系统服务，`install.sh` 已自动走 `systemctl`，无需额外包装。

**Nginx 校验与重载**：

```bash
nginx -t && systemctl reload nginx
```

> 原 `frontend/nginx.conf` 面向容器（`user nginx; listen 6173; root /usr/share/nginx/html`），VM 上应使用系统 Nginx + tar 包内置 `conf/prod-ai.conf`，勿直接套用容器版。

## 8. 升级与回滚

### 8.1 升级
1. 构建机重新打包前后端 tar
2. 备份现网：`cp -a` 目录 + `mysqldump --single-transaction prodplatformai > backup.sql`
3. 解压新 tar 覆盖旧文件（保留 `config/`、`data/` 外部数据；新增/变更配置对比合并）
4. 如涉及表结构变更，先按 `sql/README.md` 升库脚本
5. 重启后端（脚本方式 `bin/start.sh restart`；若用 systemd 则为 `systemctl restart prod-ai-backend`）、前端 `bin/install.sh reload`
6. 冒烟：health + 核心业务接口

### 8.2 回滚
- 应用：保留上一版 tar，重解压 + 重启即可
- 数据：上线前备份的 `backup.sql` 恢复
- 说明：`01_full_schema_ddl.sql` 为 DROP+CREATE，**严禁对存量库执行**；存量升级走 `sql/README.md` 的增量路径

## 9. 注意事项 / 与原容器化的差异提醒

1. **Nginx upstream 域名**：容器版用服务名 `backend`，VM 版必须改为 `127.0.0.1:6174`，否则反代 502。
2. **端口**：容器前端 listen 6173，VM 版由系统 Nginx 对外 80；后端仍 6174（仅本机）。
3. **数据初始化开关**：容器版默认 H2 + `spring.sql.init` 建表灌数；VM 生产 MySQL 应设 `spring.sql.init.mode=never`，依赖 `sql/` 显式维护。
4. **敏感配置**：库密码、JWT、LLM Key 一律走环境变量/`.env` 文件（600 权限），勿写死于 yml/tar。
5. **进程托管**：前后端启停统一走 tar 包内置 **shell 脚本**（后端 `bin/start.sh`、前端 `bin/install.sh`）；如需开机自启/崩溃自愈，可选用 systemd 包装（可选增强）。
6. **文件目录**：`uploads/`、`logs/`、MySQL 数据目录放独立挂载，避免随应用升级丢失。
