# Prod Platform AI - 虚拟机部署方案

> 场景：当前项目支持容器化部署（Docker 基础镜像 + 应用镜像），同时提供**虚拟机（VM）部署**方式。
> 本文档描述单台虚拟机上「前后端分别打包为 tar 包、解压启动 + 纯 MySQL 8.0 数据库」的完整方案。
> 逐步操作步骤以 `deploy/INSTALL.md` 为准，本文偏重方案设计与原理说明。

---

## 1. 方案概述

### 1.1 目标

将 AI 驱动动态表单平台部署到**单台 Linux 虚拟机**，最终形态：

```
用户浏览器
    │  HTTP(S):80
    ▼
┌─────────────────────────────── Linux VM ───────────────────────────────┐
│  Nginx（前端静态资源 + 反向代理）                                          │
│    ├─ /         → Vue dist（静态文件）                                     │
│    ├─ /api/*    → proxy → http://127.0.0.1:6174  （Spring Boot 后端）     │
│    └─ /ws/*     → proxy(websocket) → 127.0.0.1:6174                       │
│                                                                           │
│  Spring Boot 后端（backend-app，JDK17，端口 6174）                         │
│    └─ MySQL 8.0（poc-stq 库，172.30.0.232:8866，由 DBA 提供）              │
└───────────────────────────────────────────────────────────────────────────┘
```

### 1.2 现存容器化与本次虚拟机化的差异

| 维度 | 容器化（现状） | 虚拟机化（本次） |
|------|----------------|------------------|
| 后端 | 镜像内 JDK17 + Maven，构建期离线打包 | 构建机打 `jar` → 打入 tar 包 → VM 解压直接 `java -jar` 运行 |
| 前端 | 镜像内 vite build → Nginx dist | 构建机 `npm run build` 产出 `dist/` → 打入 tar 包 → VM 解压由系统 Nginx 托管 |
| Nginx | 容器内 `/etc/nginx/nginx.conf`，upstream 为 Docker 服务名 `backend` | 系统 Nginx，upstream 改为 `127.0.0.1:6174` |
| 配置注入 | `-v /config:/config` 挂载 + `-e` 环境变量注入 | tar 包内自带外部 `config/application.yml`（**写死**库地址/账号/密码/JWT），**不使用环境变量** |
| 数据库 | H2 内嵌（默认）/ 容器外 MySQL | **纯 MySQL 8.0**（独立实例，连接串由外部配置写死） |
| 服务托管 | Docker 守护进程 | 建议 systemd（也可用 tar 包内置启停脚本） |

## 2. 架构与组件清单

### 2.1 部署目录规划（按 crm-pgcent-mng 约定）

部署根目录**可配置**，约定在根目录下创建 `crm-pgcent-mng/`，前后端分别落位其内：

```
<根目录>/                                  # 如 /opt（可配置）
└── crm-pgcent-mng/                        # APP_HOME = <根目录>/crm-pgcent-mng
    ├── installer/                         # 发布包存放目录（deployup.sh 从这里取 tar 包）
    │   ├── prod-ai-backend.tar.gz
    │   └── prod-ai-frontend.tar.gz
    ├── prod-ai-backend/                   # 后端：app.jar + bin/ + conf/ + config/ + logs/ + data/ + uploads/
    └── prod-ai-frontend/                  # 前端：html/（原始产物）+ dist/（Nginx 静态根）+ conf/ + bin/
```

> 默认部署路径 `/opt/crm-pgcent-mng`；若根目录不同（如 `/home`、`/data`），
> 全文路径前缀同步替换即可。脚本与 systemd 单元均以 `APP_HOME` 变量标识该目录。

### 2.2 组件清单

| 组件 | 技术栈 | 端口 | 部署目录（建议） |
|------|--------|------|------------------|
| 前端静态站 | Vue 3 + Vite 产物 | 由 Nginx 承接，对外 80 | `${APP_HOME}/prod-ai-frontend/dist` |
| Nginx | 系统包 nginx（1.18+） | 80（对外）/ 本地回环 | `/etc/nginx/` |
| 后端 | Spring Boot 3.4 / **JDK 17** | **6174**（仅本机回环） | `${APP_HOME}/prod-ai-backend` |
| 数据库 | MySQL 8.0+ | `172.30.0.232:8866`（由 DBA 提供） | 独立实例 |
| 数据目录 | 上传/日志/运行时数据 | - | `${APP_HOME}/prod-ai-backend/{data,logs,uploads}` |

> 后端 6174 只监听 `127.0.0.1`，不直接对外暴露；所有外部流量由 Nginx 统一入口。

## 3. 硬件与系统要求建议

| 项 | 建议 |
|----|------|
| 操作系统 | CentOS 7.9+ / Rocky 8 / Ubuntu 20.04+（x86_64） |
| CPU | ≥ 4 核（后端 + Nginx 同机） |
| 内存 | ≥ 8 GB（JDK 2-4GB + 系统） |
| 磁盘 | ≥ 50 GB（含上传、日志） |
| 软件 | **JDK 17（强制）**、Nginx、MySQL 8.0 客户端、curl |
| 网络 | 对外放行 80；6174 仅本机；`172.30.0.232:8866` 需可连通 |

> JDK 主版本必须为 17：`bin/start.sh` 与 systemd 单元均会严格校验，非 17 直接报错退出。

## 4. 打包流程（在构建机执行）

> 构建机需有 JDK17 + Maven、Node 20 + npm，能访问依赖仓库（Maven 内网仓库 / npm 镜像）。
> 本项目已提供 **一键打包脚本** `deploy/build-tar.ps1`，自动把后端 jar、前端 dist、配置与**内置启停脚本**打成三个 tar 包。

### 4.1 一键打包（推荐）

```powershell
# 1) 后端编译
cd backend-app
mvn -s .mvn/local-settings.xml -DskipTests clean package

# 2) 前端构建
cd ..\frontend
npm ci
npm run build

# 3) 打包（生成 deploy/out/prod-ai-*.tar.gz）
cd ..
powershell -ExecutionPolicy Bypass -File deploy\build-tar.ps1
```

脚本自动组装三个 tar 包的目录结构，并把 `deploy/backend/bin/{start,deployup}.sh`、`deploy/frontend/bin/{start,stop,deployup}.sh`、systemd 单元、Nginx 站点配置、**部署专用后端配置**一并打入：

```
prod-ai-backend.tar.gz/
├── app.jar                    # Spring Boot 可执行包
├── config/application.yml     # 外部配置（deploy/backend/config 拷贝，写死 MySQL 连接）
├── bin/start.sh               # 后端启停脚本 {start|stop|restart|status}
├── bin/deployup.sh            # 后端更新脚本（从 installer 取包，替换 app.jar）
├── conf/prod-ai-backend.service   # systemd 单元模板
├── logs/  data/  uploads/     # 运行时目录（空）

prod-ai-frontend.tar.gz/
├── html/                      # Vue dist 静态产物（含 index.html）
├── conf/prod-ai.conf          # Nginx 站点配置（静态文件，upstream=127.0.0.1:6174）
└── bin/                       # deployup.sh 更新静态 / start.sh 启动 / stop.sh 停止
```
prod-ai-backend.tar.gz/
├── app.jar                    # Spring Boot 可执行包
├── config/application.yml     # 外部配置（deploy/backend/config 拷贝，写死 MySQL 连接）
├── bin/start.sh               # 启停脚本 {start|stop|restart|status}
├── conf/prod-ai-backend.service   # systemd 单元模板
├── logs/  data/  uploads/     # 运行时目录（空）

prod-ai-frontend.tar.gz/
├── html/                      # Vue dist 静态产物（含 index.html）
├── conf/prod-ai.conf          # Nginx 站点配置（upstream=127.0.0.1:6174）
└── bin/                       # deployup.sh 更新静态 / start.sh 启动 / stop.sh 停止

prod-ai-mysql.tar.gz/
├── 01_full_schema_ddl.sql     # 全量 DDL（23 张业务表，DROP+CREATE）
├── 03_ext_schema.sql          # 扩展表（指标宽表/ABox/变更订阅/流程引擎节点日志）
├── 02_init_data.sql           # 初始化数据（MCP 工具/DSL 规则/提示词/LLM 占位）
└── install_mysql.sh           # 一键建表脚本（默认对齐 poc-stq 环境）
```

### 4.2 后端手动打包（可选）

若需自定义配置可手工组装：

```bash
cd backend-app
mvn -s .mvn/local-settings.xml -DskipTests clean package

cd ..
mkdir -p dist-backend/{bin,conf,config,logs,data,uploads}
cp backend-app/target/prod-platform-ai-*.jar       dist-backend/app.jar
cp deploy/backend/config/application.yml           dist-backend/config/
cp deploy/backend/bin/start.sh                     dist-backend/bin/
cp deploy/backend/bin/deployup.sh                  dist-backend/bin/
cp deploy/backend/conf/prod-ai-backend.service     dist-backend/conf/
tar -czf prod-ai-backend.tar.gz -C dist-backend .
```

### 4.3 交付物清单

| 产物 | 内容 | VM 上如何用 |
|------|------|-------------|
| `prod-ai-backend.tar.gz` | app.jar、config/application.yml、bin/{start,deployup}.sh、conf/systemd 单元、logs/data/uploads | 首次解压至 `${APP_HOME}/prod-ai-backend`，`bin/start.sh start`；更新执行 `bin/deployup.sh` |
| `prod-ai-frontend.tar.gz` | html（dist 产物）、conf/prod-ai.conf、bin/{start,stop,deployup}.sh | 首次解压至 `${APP_HOME}/prod-ai-frontend`，`bin/start.sh` 启动；更新执行 `bin/deployup.sh` |
| `prod-ai-mysql.tar.gz` | DDL/初始化 SQL + install_mysql.sh | 解压后按 01→03→02 手动执行（或 `bash install_mysql.sh`） |

> 建议在构建机与 VM 同版本后，把 tar 包通过内网（scp / 公司发布平台）传输，并在 VM 校验校验和（sha256）。

## 5. VM 部署配置要点

### 5.1 前置软件安装（root）

```bash
# CentOS/Rocky
yum install -y java-17-openjdk-devel nginx mysql
# Ubuntu: apt install -y openjdk-17-jdk nginx mysql-client
# 或 JDK 解压版: 将 jdk-17 放置 /opt/jdk-17，并在脚本/单元中配置 JAVA_HOME

# Nginx 开机自启（后端进程托管见第 6 节）
systemctl enable --now nginx
```

**配置 JAVA_HOME（JDK 17）**：若系统存在多版本 JDK 或默认 `java` 非 17，需显式指定 JDK17 路径。二选一：

- **脚本方式**：编辑 `bin/start.sh` 顶部 `JAVA_HOME="${JAVA_HOME:-}"` → `JAVA_HOME=/usr/lib/jvm/java-17-openjdk`
- **systemd 方式**：编辑单元中 `Environment="JAVA_HOME=/usr/lib/jvm/java-17-openjdk"` 后 `systemctl daemon-reload`

> 查找路径：`ls /usr/lib/jvm/`（CentOS/Rocky）或 `update-alternatives --list java`。

### 5.2 后端外部配置（写死，不使用环境变量）

后端 jar 内置 `application.yml`（默认 H2 兜底）。VM 部署时通过**外部配置目录**覆盖：

```yaml
# ${APP_HOME}/prod-ai-backend/config/application.yml（随包自带，部署前按环境改值）
spring:
  profiles:
    active: prod
  datasource:
    url: jdbc:mysql://172.30.0.232:8866/poc-stq?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    driver-class-name: com.mysql.cj.jdbc.Driver
    username: poc-stq
    password: Poc@StQ@2026
  sql:
    init:
      mode: never      # 表结构由 deploy/mysql 脚本维护，禁用 jar 内 H2 初始化
  h2:
    console:
      enabled: false
prodai:
  auth:
    enabled: true
    jwt-secret: CHANGE_ME_32_BYTES_RANDOM   # 生产必须改为 32 字节随机串（多实例一致）
  llm:
    enabled: true
```

启动参数已由脚本/单元自带，指向该目录：

```
--spring.config.additional-location=optional:file:${APP_HOME}/prod-ai-backend/config/
```

> 本部署**不使用 `backend.env` 等环境变量文件**，库密码、JWT 等一律**明文写死**在
> `config/application.yml`，属该专用库/专用环境的既定简化策略。

### 5.3 数据库初始化

目标库与账号**已由 DBA 建好**（`172.30.0.232:8866` / `poc-stq` / `Poc@StQ@2026`），本包**只建表**：

```bash
# 解压 MySQL 包后，手动按顺序执行（01 为 DROP+CREATE，严禁对存量有数据的库执行）
mysql -h172.30.0.232 -P8866 -upoc-stq -p'Poc@StQ@2026' poc-stq < 01_full_schema_ddl.sql
mysql -h172.30.0.232 -P8866 -upoc-stq -p'Poc@StQ@2026' poc-stq < 03_ext_schema.sql
mysql -h172.30.0.232 -P8866 -upoc-stq -p'Poc@StQ@2026' poc-stq < 02_init_data.sql
```

> 也可用 `bash install_mysql.sh` 一键执行 01→03→02。
> 详细说明、升级/回滚策略见 `deploy/mysql/README.md`。存量升级请勿执行 `01_full_schema_ddl.sql`。

### 5.4 Nginx（单机反代 + 静态）

tar 包内 `conf/prod-ai.conf` 为静态站点配置，首次部署时拷贝到 Nginx 配置目录。**关键差异**：upstream 从容器服务名 `backend` 改为 `127.0.0.1:6174`：

```nginx
# /etc/nginx/conf.d/prod-ai.conf
upstream backend-prodai {
    server 127.0.0.1:6174;
}

server {
    listen       80;
    server_name  _;

    root   /opt/crm-pgcent-mng/prod-ai-frontend/dist;
    index  index.html;

    client_max_body_size 30m;
    underscores_in_headers on;

    location ^~ /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    location ^~ /api/ {
        proxy_pass http://backend-prodai;
        proxy_http_version 1.1;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_buffering off;          # SSE 需关闭缓冲
        proxy_cache off;
        proxy_read_timeout 86400;
        proxy_send_timeout 86400;
        keepalive_timeout 600;
    }

    location ^~ /ws/ {
        proxy_pass http://backend-prodai;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 86400;
        proxy_send_timeout 86400;
    }

    location ^~ /swagger-ui { proxy_pass http://backend-prodai; }
    location ^~ /v3/api-docs { proxy_pass http://backend-prodai; }
    location = /health { proxy_pass http://backend-prodai; }

    location = /index.html { add_header Cache-Control "no-cache"; }

    location / {
        try_files $uri $uri/ /index.html;
        add_header Cache-Control "no-cache";
    }
}
```

> 若部署根不是 `/opt/crm-pgcent-mng`，需同步修改 `root` 指令。
> 原 `frontend/nginx.conf` 面向容器（`user nginx; listen 6173; root /usr/share/nginx/html`），VM 上应使用系统 Nginx + 上述站点配置，勿直接套用容器版。

校验并重载：

```bash
nginx -t && systemctl reload nginx
```

## 6. 启动与进程托管（前后端均用 shell 脚本）

> **前后端启停统一走 tar 包内置的 shell 脚本**（后端 `backend/bin/start.sh`；前端 `frontend/bin/{install,start,stop}.sh`），
> 不强制依赖 systemd。如需开机自启/崩溃自愈，再按 6.4 将后端包装为 systemd 单元（可选）。

### 6.1 后端 shell 脚本启停

后端脚本：`${APP_HOME}/prod-ai-backend/bin/start.sh`，用法：

```bash
# 1) 解压
mkdir -p /opt/crm-pgcent-mng/prod-ai-backend
tar -xzf prod-ai-backend.tar.gz -C /opt/crm-pgcent-mng/prod-ai-backend

# 2) 按环境修改外部配置（库地址/账号密码/JWT）
vi /opt/crm-pgcent-mng/prod-ai-backend/config/application.yml

# 3) 启动 / 停止 / 重启 / 状态
bash /opt/crm-pgcent-mng/prod-ai-backend/bin/start.sh start
bash /opt/crm-pgcent-mng/prod-ai-backend/bin/start.sh stop
bash /opt/crm-pgcent-mng/prod-ai-backend/bin/start.sh restart
bash /opt/crm-pgcent-mng/prod-ai-backend/bin/start.sh status
```

脚本行为：
- **JDK 校验**：优先用脚本内 `JAVA_HOME`，未配置则回退 PATH 中 `java`；解析主版本，**非 17 直接报错退出**
- `APP_HOME` **可配置**：默认推导为包目录（`prod-ai-backend`）的父目录（即 `crm-pgcent-mng`）；也可在脚本顶部或环境变量 `APP_HOME` 显式指定
- 启动时以 `nohup` 后台运行，PID 写入 `prod-ai-backend/app.pid`，控制台日志追加 `logs/app.out`
- 启动参数自带 `--spring.config.additional-location=optional:file:config/`，读取解压根下 `config/` 外部配置
- `stop` 优雅终止（最多等 30s 再 `kill -9`）；旧 PID 文件自动清理
- 若 `USE_SYSTEMD=1` 且已配置 systemd 单元，脚本自动转调 `systemctl`（可选增强）

### 6.2 前端 shell 脚本首次部署 / 启停

前端脚本：`${APP_HOME}/prod-ai-frontend/bin/{start.sh,stop.sh,deployup.sh}`，用法：

```bash
# 1) 解压
mkdir -p /opt/crm-pgcent-mng/prod-ai-frontend
tar -xzf prod-ai-frontend.tar.gz -C /opt/crm-pgcent-mng/prod-ai-frontend

# 2) 首次放置静态资源 + 安装站点配置（需 root）
cd /opt/crm-pgcent-mng/prod-ai-frontend
mkdir -p dist && cp -r html/. dist/
cp conf/prod-ai.conf /etc/nginx/conf.d/prod-ai.conf && nginx -t

# 3) 启动 / 停止（需 root）
bash /opt/crm-pgcent-mng/prod-ai-frontend/bin/start.sh   # 校验 nginx -t 后启动 Nginx
bash /opt/crm-pgcent-mng/prod-ai-frontend/bin/stop.sh    # 优雅停止（-s quit，最多等 30s 后强制终止）
```

配置 Nginx 安装路径（非系统默认安装时）——在 `start.sh` / `stop.sh` 顶部设置 `NGINX_HOME`：

```bash
# 找到: NGINX_HOME="${NGINX_HOME:-}"   改为: NGINX_HOME=/usr/local/nginx
# 或运行时: NGINX_HOME=/usr/local/nginx bash bin/start.sh
```

脚本行为：
- `start.sh` / `stop.sh`：独立启停脚本，启动前先 `nginx -t` 校验，已运行则跳过；停止用 `-s quit` 优雅退出
- **Nginx 路径配置**：`NGINX_HOME` 指定安装前缀（如 `/usr/local/nginx`），脚本据此推导 `sbin/nginx` 与 `conf/`；留空则回退系统默认（`PATH` 中的 `nginx` + `/etc/nginx`）
- `APP_HOME` **可配置**：默认推导为包目录（`prod-ai-frontend`）的父目录（即 `crm-pgcent-mng`）
- 端口默认 80，可用环境变量 `NGINX_PORT` 覆盖；未指定时从已安装的站点配置 `listen` 读取

### 6.3 更新部署（`deployup.sh`）

首次部署完成后，升级无需重新解压，把新包放进 `${APP_HOME}/installer/` 再执行各自 `deployup.sh`：

```bash
mkdir -p /opt/crm-pgcent-mng/installer
cp /root/deploy-pack/prod-ai-backend.tar.gz  /opt/crm-pgcent-mng/installer/
cp /root/deploy-pack/prod-ai-frontend.tar.gz /opt/crm-pgcent-mng/installer/

# 后端：只替换 app.jar（保留 config/application.yml、logs/、data/、uploads/）
cd /opt/crm-pgcent-mng/prod-ai-backend && bash bin/deployup.sh && bash bin/start.sh restart

# 前端：只替换静态资源 dist/（不重装站点配置）
cd /opt/crm-pgcent-mng/prod-ai-frontend && bash bin/deployup.sh
bash bin/stop.sh && bash bin/start.sh
```

脚本行为：
- 自动从 `${APP_HOME}/installer/` 取固定名包，内部 `tar -xzf` 解压到临时目录后清理
- **后端**：备份原 `app.jar` 为 `app.jar.bak.<时间戳>` 后替换；**不动** `config/application.yml` 与 `logs/`、`data/`、`uploads/`
- **前端**：备份原 `dist/` 为 `dist.bak.<时间戳>` 后清空并替换静态资源；**不动** Nginx 站点配置
- 包目录/包名可用脚本顶部 `INSTALLER_DIR` / `PKG_NAME`（或环境变量）调整

### 6.4 可选：包装为 systemd 以支持开机自启 / 崩溃自愈

> 纯 shell 脚本不放 systemd 也能完整启停；若需开机自动拉起，按下面把启动脚本包一层（脚本内已支持 `USE_SYSTEMD=1` 转调）。

**后端** `conf/prod-ai-backend.service`（tar 包已内置）：

```ini
[Unit]
Description=Prod Platform AI Backend (Spring Boot)
After=network.target mysqld.service
Requires=mysqld.service

[Service]
Type=simple
# ---- 部署根目录（按实际修改，APP_HOME = <根目录>/crm-pgcent-mng）----
Environment="APP_HOME=/opt/crm-pgcent-mng"
# ---- JDK 17 安装路径（按实际修改）----
Environment="JAVA_HOME=/usr/lib/jvm/java-17-openjdk"
User=prod-ai
Group=prod-ai
WorkingDirectory=${APP_HOME}/prod-ai-backend
# 数据源/JWT 等业务配置统一在 ${APP_HOME}/prod-ai-backend/config/application.yml
ExecStart=/usr/bin/env bash -c 'B="${APP_HOME}/prod-ai-backend"; JAVA_BIN="${JAVA_HOME:+${JAVA_HOME}/bin/java}"; JAVA_BIN="${JAVA_BIN:-java}"; \
    MAJOR="$("${JAVA_BIN}" -version 2>&1 | head -n1 | sed -E "s/.*version \"([0-9]+)(\\.([0-9]+))?.*/\\1/")"; \
    [ "${MAJOR}" = "1" ] && MAJOR="$("${JAVA_BIN}" -version 2>&1 | head -n1 | sed -E "s/.*version \"1\\.([0-9]+).*/\\1/")"; \
    [ "${MAJOR}" = "17" ] || { echo "需要 JDK 17，当前: $("${JAVA_BIN}" -version 2>&1 | head -n1)"; exit 1; }; \
    exec "${JAVA_BIN}" -Xms1g -Xmx3g -Dfile.encoding=UTF-8 -jar "${B}/app.jar" \
    --server.port=6174 --spring.config.additional-location=optional:file:"${B}/config/"'
Restart=on-failure
RestartSec=10
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
```

```bash
useradd -r -s /sbin/nologin prod-ai
cp /opt/crm-pgcent-mng/prod-ai-backend/conf/prod-ai-backend.service /etc/systemd/system/
# 按实际修改单元中的 APP_HOME 与 JAVA_HOME
vi /etc/systemd/system/prod-ai-backend.service
chown -R prod-ai:prod-ai /opt/crm-pgcent-mng/prod-ai-backend
systemctl daemon-reload
systemctl enable --now prod-ai-backend
```

> 用 systemd 后就不再用 `bin/start.sh` 手动启停（二者管理同一进程会冲突）；以 systemd 为准。

**前端** Nginx 采用 tar 包内置的独立启停脚本（`bin/start.sh` / `bin/stop.sh`），无需额外包装。

## 9. 注意事项 / 与原容器化的差异提醒

1. **Nginx upstream 域名**：容器版用服务名 `backend`，VM 版必须改为 `127.0.0.1:6174`，否则反代 502。
2. **端口**：容器前端 listen 6173，VM 版由系统 Nginx 对外 80；后端仍 6174（仅本机）。
3. **数据初始化开关**：容器版默认 H2 + `spring.sql.init` 建表灌数；VM 生产 MySQL 应设 `spring.sql.init.mode=never`，依赖 `deploy/mysql` 显式维护。
4. **敏感配置**：本 VM 方案按既定简化策略把库密码/JWT **明文写死**在 `config/application.yml`（专用库/专用环境）；与容器版（`-e` 环境变量注入）不同，二者配置彼此独立、互不影响。
5. **JDK 版本**：**强制 17**，脚本与 systemd 单元均做严格校验，多版本环境需显式配置 `JAVA_HOME`。
6. **进程托管**：前后端启停统一走 tar 包内置 **shell 脚本**；如需开机自启/崩溃自愈，可选用 systemd 包装（可选增强）。
7. **文件目录**：`uploads/`、`logs/` 放独立目录，避免随应用升级丢失。
8. **数据库**：目标库/账号由 DBA 提供且已存在，部署侧**只建表不建库**；`01` 为破坏性脚本，须先确认库为空。
