## 5. SMOKE 守卫链路（P1-6 + P1-7）

热重载 `POST /graph/reload` 事务四步：

1. **LOAD**：装载 pending 图谱（graphOverride 注入回归运行器）；
2. **VALIDATE**：`OpsGraphSchemaValidator` 结构校验；
3. **SMOKE**：`ProductConfigRegressionService.smokeAgainstGraph(pending)` 以六用例对 pending 图谱执行推理/合规/报文断言，任一失败即中止；
4. **COMMIT**：版本登记（`pd_ai_ontology_version` + `pd_ai_ontology_version_log`）后替换现行图谱。

坏图谱注入验证：移除 `bizScenarios` 后 SMOKE 断言失败，reload 返回差异报告且现行图谱不变。

## 6. P1 链路边界与 P2 衔接

- 抽取/推理仍走存量 SLOT_KEYS/`inferFields` 硬编码逻辑，模板仅驱动表单渲染与下发；抽取模板化、derive_rules 引擎分别于 P2-2/P2-3 接管，接管时以本用例集做前后回归。
- 模板 `message_projection` 仅与 `config_message_projection.json` 对齐观察，不接管投影（§10.1 报文契约保护）。
- 已知观察项：守卫版本登记在版本表未初始化环境降级为 WARN（不影响守卫结果），生产环境需先执行建表脚本。
