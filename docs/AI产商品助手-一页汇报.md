# AI 产商品助手：LLM + 本体 融合汇报

## 一、方案核心（一句话）

> **大模型（LLM）负责"听懂人话、说成人话"，本体（业务知识地图 + 规则推理）负责"事实可信、判定可解释"**——用 AI 换效率，用本体守底线。

**架构一句话**：用户自然语言 → LLM 翻译为对知识地图的查询/推理请求 → 本体执行确定性推理 → 权威结论 → LLM 表达为业务语言。**LLM 全程不产生业务结论，只做翻译和表达**——这是防幻觉的架构级设计，不依赖模型自觉。

```
业务人员（说话/传文档）──► LLM（理解意图·抽取要素）──► 本体推理（查事实·跑规则）──► 权威结论
                                                                                │
                                                    LLM（生成报告·解释·追问）◄──┘
```

---

## 二、为什么必须"LLM + 本体"结合（技术选型逻辑）

| 任务 | 纯 LLM 的问题 | 纯传统方案的问题 | LLM+本体的解法 |
|------|--------------|----------------|---------------|
| 理解"畅享128收入掉了"是什么意思 | ✅ 擅长 | ❌ 关键词枚举写不完 | LLM 做意图理解 |
| 查"降幅最大的3款在售5G套餐" | ❌ 直接答会幻觉 | ✅ 准但跨系统难对齐 | LLM 生成查询 → 知识图谱执行，**结果可复现** |
| 判"渠道是不是根因" | ❌ 无法保证可解释 | ✅ 准但规则写死在代码里 | 本体规则推理，**阈值外置、可热更、可审计** |
| 把结论讲给业务听 | ✅ 擅长 | ❌ 报告模板僵硬 | LLM 基于推理结果生成报告 |

**核心判据**：答案随业务变化 → AI；结论必须可指认规则、可复现 → 本体/规则。**每类技术用在它最擅长的环节**。

## 三、本体建模设计：两张知识地图 + 一套外置规则

业务知识不散落在各系统和个人脑子里，而是**显式建模**为机器可读、可推理的两张图。所有概念、关系、规则都定义得清清楚楚、可审计。

### 3.1 配置知识地图（服务研发场景）

以"**配置方案**"为枢纽，把一个套餐该有的要素、要素之间的关系、以及配置要遵守的约束全部建进图里：

| 建模内容 | 业务含义 |
|---------|---------|
| 配置方案 → 资费产品 → **品类**（6 类） | 一个方案配的是什么类型的套餐（个人主资费/宽带/家庭套餐…），品类决定必备要素 |
| 方案 → 销售策略 | 渠道范围、互斥组、合约要求 |
| 方案 → 计费方案 / 优惠政策 / 网络能力 | 月租怎么收、优惠怎么给、带多少带宽 |
| 方案 → 资费相容关系 | 与哪些在架套餐互斥、哪些必须依赖主套餐 |
| 方案 → 合规规则 | 该方案受哪些规则约束 |

**三个设计亮点**：

1. **品类即模板**：6 类品类各挂一份"字段清单模板"（必填什么、默认什么、字段怎么联动），由模板编译器自动转化为机器可校验的约束规则——**新增品类只需加一份模板文件，零代码**；
2. **业务叫法对照表**：把"资费名称/套餐名称/产品名称"等不同叫法对齐到同一字段——这是 LLM 听懂业务人员口语的词典依据；
3. **模板继承**：各类套餐共享公共骨架（基础信息/发布信息/计费信息），子类只定义差异，避免重复维护。

### 3.2 运营知识地图（服务运营场景）

围绕"**产商品**"把运营全要素关联起来：

```
                产商品（如：家庭融合畅享128）
                /      |       |        \
           指标       渠道     促销      竞品     用户行为
         （收入环比-16%）（代理网点）（校园开学季）（友商20元套餐）
```

**关键设计——结论也是图上的"节点"**：归因结论（渠道根因/竞品冲击/促销到期）和风险结论（零元资费/长期零销/低效产品）直接建模为图上的类别——**规则推理命中，商品自动归入对应类别**。查"当前所有渠道根因商品"= 直接查该类节点，归因结果无需额外存储、天然可查。

**数据属性即证据**：每个节点挂运营事实——指标的环比降幅、渠道的订单降幅与贡献占比、竞品的价差与渗透率变化——这些数值是规则推理的输入，也是结论的证据。

### 3.3 规则建模：业务规则 = 机器可执行的知识

- 归因、风险、合规三类业务规则全部**结构化建模**，阈值（如"订单降超 20%"、"价差超 15%"）统一外置在规则配置中，**在线可调、版本可溯**；
- 每条规则带业务说明（这条规则为什么存在、判定逻辑是什么），业务人员可读可审；
- 推理引擎双轨：正式语义推理失败自动降级到等价规则引擎（同一套阈值），保证永远可用。

## 四、本体推理过程：结论是怎么"推"出来的（以两个场景为例）

### 4.1 研发场景：一份配置草稿的"过审"之旅

**输入**：LLM 从用户话术中抽取的要素——{场景=家庭融合, 月费=158, 宽带=500M, 渠道=全渠道}

**① 品类识别**：根据"家庭融合"命中家庭套餐模板，装载该品类的字段清单与规则集。

**② 字段补全（知识推理）**：
- 用户没说渠道 → 按品类知识自动补"全渠道"；语音/流量未提 → 按家庭融合模板默认值补齐；
- 选了"分层优惠=是" → 优惠方式/费用/有效期 5 个关联字段自动显示；选"否" → 自动隐藏；
- 角色数上限 = 手机成员上限 + 宽带成员上限，自动派生。
- **每个补全的值都记录来源**——事后能回答"这个默认值是哪来的"。

**③ 合规裁决（规则逐条执行）**：

| 规则 | 判什么 | 本例结果 |
|------|-------|---------|
| 必填缺失 | 名称/品类/固费/渠道缺一不可 | ✅ 已补全 |
| 互斥冲突 | 与在架套餐同属互斥组不可共存 | ❌ **拦截**：与用户现有主套餐同互斥组 |
| 固费上下限 | 月费在 9~599 元区间 | ✅ 158 元合规 |
| 优惠漏洞 | 全额赠送需约束条件 | ✅ 未触发 |

**④ 结论输出**：`合规不通过 + 拦截原因 + 命中规则编号 + 证据（与哪个在架商品冲突）`——LLM 拿到这个结论只能如实转述"不可提交，原因是 R-C03 互斥冲突"，**无权改判**。

### 4.2 运营场景："收入掉了16%"的自动归因

**事实准备**：该商品关联的运营事实已灌入知识地图——指标环比 -16%、代理渠道订单降 42%（贡献占比 38%）、竞品价差 15% 且渗透率上升、促销距到期还有 30 天。

**推理逐条点火**（规则引擎按外置阈值自动判断）：

| 步骤 | 规则 | 图上的事实 | 推理结果 |
|------|------|-----------|---------|
| 1 | 异动确认（降幅≤-10%） | 收入环比 -16% | ✅ 确认异动 |
| 2 | 渠道归因（订单降≤-20% 且贡献≥30%） | 渠道订单 -42%、贡献 38% | ✅ **渠道是主因** |
| 3 | 竞品冲击（价差≥15% 且渗透率上升） | 价差 15%、渗透率 +2pp | ✅ 竞品是次因 |
| 4 | 促销归因（7 天内到期） | 促销还有 30 天到期 | ✗ 排除 |

**输出**：根因路径（主因渠道 → 次因竞品）+ 每条结论附带事实数值与规则编号 → LLM 生成归因报告。

**可复现的本质**：结论 = 图上的事实 + 显式规则 + 确定性推理——**同样数据，任何人、任何时间跑，结论一致**，且每条都能回放到具体数值和阈值。业务人员对结论有疑问时，可以逐条核对："你说渠道是主因？渠道订单降了多少？——42%，规则要求超 20%，命中。"

### 4.3 同一模型支撑的两个扩展推理

- **全量风险稽核**：每天定时把全量在售商品灌入知识地图 → 风险规则批量执行 → 命中自动归类（零元资费/长期零销/低效产品）→ 风险评分分级 → 处置工单闭环；
- **假设推演**：把"该商品停售"作为**临时假设**注入独立沙箱图 → 规则在假设下重跑 → 量化营收/用户影响 → 结论不碰生产数据。

## 五、工程保障（为什么这套东西敢上生产）

| 机制 | 说明 |
|------|------|
| **可审计** | 每个结论关联：知识地图上的事实 + 命中规则编号 + 阈值版本，全程留痕可回放 |
| **资产治理** | 模板/规则/本体三类知识资产版本化，支持发布、回退、弃用 |
| **防劣化** | 典型业务用例回归门禁——改任何规则先过全链路回归再上线 |
| **热更安全** | 事实数据热重载四步守卫（加载→校验→冒烟→提交），坏数据注入自动回退到最近可用版本 |
| **双轨容错** | 语义推理与规则引擎双轨互备；LLM 不可用自动降级词典抽取 |

## 七、电梯说明（30 秒版）

> 我们给产商品建了**两张业务知识地图**（配置 + 运营）——实体、关系、规则全部显式建模，机器能查、能推理、能校验；再配上懂人话的大模型做翻译层：研发说句话就出合规配置，运营一句"收入为什么掉了"就出可复现的归因报告，风险产品全量自动稽核。
> **大模型负责听懂和表达，本体负责事实与裁决**——效率提升 95%，且每个结论都能回放到"依据哪些事实、命中哪条规则、阈值是多少"，天然满足审计要求。
