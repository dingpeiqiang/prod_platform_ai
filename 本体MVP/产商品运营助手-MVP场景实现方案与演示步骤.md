# 产商品运营助手 MVP：核心场景实现方案与演示步骤

> 依据：《中国移动新一代数智云原生省级业务运营系统规范-产商品中心子册@0126修订版》  
> 对齐规划：《规划举措 | 产商品专题 - 产商品运营助手》（本体图谱 + 大模型）  
> 目标：基于**本体平台推理能力**，落地 2 个最有价值、可演示、可扩展的 MVP 场景

---

## 一、场景选型结论

### 1.1 推荐的 2 个 MVP 场景

| 优先级 | 场景名称 | 对应痛点 | 本体推理价值 | 演示冲击力 |
|--------|----------|----------|--------------|------------|
| **MVP-1** | **运营指标异动智能根因分析** | 问题三：指标异动人工难定位 | ★★★★★ 多跳关联推理 | 高（路径可解释） |
| **MVP-2** | **高风险产商品智能稽核与优胜劣汰** | 问题四：0元资费等靠人工抽检；低效产商品长期在架 | ★★★★★ 规则+图谱联合推理 | 高（风险清单+处置建议） |

### 1.2 为何不优先做问题一/二（市场分析、上新决策）

| 场景 | 暂缓原因 |
|------|----------|
| 市场洞察报告生成 | 强依赖外采/爬虫与非结构化文本，MVP 数据准备重，本体推理占比低 |
| 产商品上新辅助决策 | 需完整评估模型与审批链，演示链路长，短期难形成“秒级闭环” |

> **原则**：MVP 优先选「本体可推理 + 结果可解释 + 数据可 mock + 5 分钟可讲清」的场景；市场分析/上新决策作为 Phase-2。

### 1.3 场景与规范能力映射

| MVP 场景 | 规范关键概念 | 运营助手图谱节点 |
|----------|--------------|------------------|
| MVP-1 根因分析 | 商品、商品定价、销售渠道、优惠规则、融合构成、量纲 | 产商品主体 ↔ 运营指标 ↔ 用户行为 ↔ 竞争分析 ↔ 产品市场 |
| MVP-2 风险稽核 | 商品定价、优惠规则、销售规则、商品状态（上架/下架）、促销活动 | 产商品主体 ↔ 风险特征 ↔ 产品类型 ↔ 运营指标 |

## 二、MVP 总体架构（共用底座）

```
┌─────────────────────────────────────────────────────────────┐
│                    产商品运营助手（演示层）                    │
│   对话入口 / 指标看板 / 根因路径图 / 风险清单 / 处置建议卡片   │
└───────────────┬─────────────────────────────┬───────────────┘
                │ 自然语言意图                 │ 结构化结果展示
┌───────────────▼─────────────┐   ┌───────────▼───────────────┐
│  大模型编排层（轻量）         │   │  本体推理引擎（核心）       │
│  - 意图识别 / 槽位抽取        │   │  - 本体查询（SPARQL/图查询）│
│  - 报告话术生成               │──▶│  - 规则推理（SWRL/规则引擎）│
│  - 不负责核心业务判定         │   │  - 路径解释 / 证据链回传   │
└───────────────┬─────────────┘   └───────────┬───────────────┘
                │                               │
┌───────────────▼───────────────────────────────▼─────────────┐
│                     产商品运营本体知识图谱                      │
│  Product / Offering / PricePlan / Channel / Promo / Metric   │
│  RiskFeature / UserBehavior / Competitor / MarketScope       │
└─────────────────────────────────────────────────────────────┘
```

**分工约定（演示必须说清）**

- **本体平台**：实体关联、规则命中、根因路径、风险定级 —— **权威结论**
- **大模型**：理解问句、汇总证据、生成可读报告 —— **表达层**，不改写推理结果

## 三、本体模型设计（MVP 最小集）

### 3.1 核心类（Class）

| 本体类 | 中文 | 对应规范实体 | 说明 |
|--------|------|--------------|------|
| `Product` | 产品 | PD_PROD_DICT | 面向生产 |
| `Offering` | 商品 | PD_GOODS_DICT | 面向销售（图谱中心节点） |
| `PricePlan` | 商品定价 | PD_GOODSPRC_DICT | 含营业费、账务/计费资费 |
| `Promotion` | 促销活动 | PROMOTION_ACTIVITY_DEFINE | 营销活动升级概念 |
| `FavRule` | 优惠规则 | PD_FAV_DICT | 折扣/直降/赠送 |
| `Channel` | 销售渠道 | 商品销售渠道 | 电渠/厅店等 |
| `Metric` | 运营指标 | （运营扩展） | 留存率、离网率、累计收入等 |
| `RiskFeature` | 风险特征 | （运营扩展） | 0元资费、长期零销、异常优惠等 |
| `UserBehavior` | 用户行为 | （运营扩展） | 订购量、退订量、渠道转化 |
| `CompetitorOffer` | 竞品 | （运营扩展） | 外部对标 |
| `MarketScope` | 产品市场 | （运营扩展） | 市场容量、渗透率 |

### 3.2 核心对象属性（Object Property）

```
Offering --hasProduct--> Product
Offering --hasPricePlan--> PricePlan
Offering --soldOn--> Channel
Offering --hasFavRule--> FavRule
Offering --participatesIn--> Promotion
Offering --hasMetric--> Metric
Offering --hasRiskFeature--> RiskFeature
Offering --influencedBy--> UserBehavior
Offering --competesWith--> CompetitorOffer
Offering --belongsToMarket--> MarketScope
Metric --relatedToChannel--> Channel
Metric --relatedToBehavior--> UserBehavior
RiskFeature --triggeredBy--> PricePlan | FavRule | Promotion
```

### 3.3 核心数据属性（Data Property）

| 属性 | 示例 | 用途 |
|------|------|------|
| `offeringId` / `offeringName` / `state` | G2024001 / 家庭融合128 / 上架 | 主体标识 |
| `monthlyFee` / `oneTimeFee` | 0 / 0 | 0元稽核 |
| `effDate` / `expDate` | 2024-01-01 / 2099-12-31 | 生命周期 |
| `metricCode` / `metricValue` / `metricDelta` | ARPU / 38.2 / -12% | 异动判定 |
| `riskLevel` / `riskScore` | HIGH / 92 | 风险定级 |
| `salesCnt30d` / `revenue30d` | 12 / 860 | 低效判定 |
| `shelfDays` | 287 | 长期在架 |

### 3.4 推理规则清单（MVP 必配）

#### 规则集 A：指标异动 → 候选根因（MVP-1）

| 规则ID | 规则语义（自然语言） | 推理动作 |
|--------|----------------------|----------|
| R-A01 | 若商品指标 `累计收入` 环比下降 ≥10%，标记 `MetricAnomaly=true` | 触发异动实例 |
| R-A02 | 若异动商品在渠道 C 的订购量下降 ≥20%，且该渠道贡献占比 ≥30%，则 C 为**主因候选** | 添加 `rootCauseCandidate(Channel)` |
| R-A03 | 若异动商品关联促销将于 7 日内到期，且历史促销带动订购占比 ≥25%，则促销到期为**主因候选** | 添加 `rootCauseCandidate(Promotion)` |
| R-A04 | 若竞品同档位价格低于本商品 ≥15%，且渗透率上升，则竞争压力为**主因候选** | 添加 `rootCauseCandidate(Competitor)` |
| R-A05 | 对候选根因按「影响权重 × 证据强度」排序，输出 Top3 解释路径 | 生成 `RootCausePath` |

#### 规则集 B：风险稽核与优胜劣汰（MVP-2）

| 规则ID | 规则语义 | 推理动作 |
|--------|----------|----------|
| R-B01 | `monthlyFee=0` 且 `oneTimeFee=0` 且非权益赠送白名单 → `RiskFeature=零元资费` | 风险命中 |
| R-B02 | 零元资费 + 状态=上架 + 无合约约束 → `riskLevel=HIGH` | 定级 |
| R-B03 | 近 30 日销量=0 且在架天数>180 → `RiskFeature=长期零销` | 低效命中 |
| R-B04 | 近 90 日收入贡献排名后 5% 且无战略标签 → `建议下架` | 处置建议 |
| R-B05 | 高风险且已上架超过 30 天未复核 → `预警升级=紧急` | 推送预警 |

> 实现形态可选：本体平台内置规则引擎 / SWRL / 图计算规则表。演示只需保证**规则可配置、命中可追溯**。

## 四、MVP-1：运营指标异动智能根因分析

### 4.1 场景目标

当某产商品运营指标（如累计收入、留存率、离网率）出现异动时，助手在 **30 秒内**自动完成：

1. 异动确认  
2. 多维归因（渠道 / 用户行为 / 促销 / 竞品 / 市场）  
3. 可解释根因路径  
4. 优化建议（话术由大模型生成，建议项由规则给出）

### 4.2 业务价值（对齐规划指标）

- 支撑「问题定位效率提升 35%+」的演示口径  
- 把“人工翻报表”变成“图谱一跳/多跳推理 + 证据链”

### 4.3 演示数据准备（Mock）

准备 **1 个主商品 + 关联图谱**：

**主商品**：`家庭融合套餐-畅享128`（OfferingID: `OF-HF-128`）

| 关联实体 | Mock 数据要点 |
|----------|----------------|
| Metric | 累计收入 环比 -18%；留存率 -3.2pp |
| Channel | 营业厅订购 -35%；电渠 -5%；营业厅贡献占比 42% |
| Promotion | 「家庭融合加装礼」将于 5 日后到期；历史带动订购 31% |
| UserBehavior | 主角成员退订率上升；宽带续约率下降 |
| CompetitorOffer | 友商同档「融合120」月费低 20 元；本地渗透率 +2.1pp |
| MarketScope | 本地家庭融合渗透率接近饱和（78%） |

### 4.4 推理链路（演示时投影）

```
MetricAnomaly(累计收入-18%)
        │
        ├─(R-A02)→ Channel(营业厅) 权重 0.42  ★主因
        ├─(R-A03)→ Promotion(加装礼到期) 权重 0.31  ★次因
        ├─(R-A04)→ Competitor(融合120) 权重 0.18
        └─(行为佐证)→ UserBehavior(续约下降) 权重 0.09
                │
                ▼
        RootCausePath Top3 + 策略建议
```

### 4.5 接口与能力清单（MVP）

| 能力 | 输入 | 输出 | 实现方 |
|------|------|------|--------|
| 异动监测 | metricCode, offeringId, period | anomalyFlag, delta | 规则/指标服务 |
| 根因推理 | offeringId, anomalyId | candidates[], paths[], scores | **本体推理** |
| 报告生成 | paths + evidence | markdown/报告段落 | 大模型 |
| 策略建议 | rootCauseType | actionList（预置模板） | 规则映射表 |

**策略建议映射示例**

| 根因类型 | 建议动作 |
|----------|----------|
| 渠道下滑 | 加强厅店专项激励；检查厅店品类是否被下沉 |
| 促销到期 | 续期或替换促销模板；评估团购/满减替代 |
| 竞品压力 | 启动动态定价/优惠随意搭；输出对标分析 |
| 行为恶化 | 针对退订高发成员角色做挽留包 |

### 4.6 演示步骤（约 6 分钟）

#### 步骤 0：开场（30 秒）

- 展示运营助手首页看板：今日异动商品数、高风险商品数  
- 一句话定位：「本体负责推理，大模型负责表达」

#### 步骤 1：触发异动（40 秒）

- 操作：点击看板告警「OF-HF-128 累计收入环比 -18%」  
  或对话输入：`分析家庭融合畅享128本月收入下滑原因`  
- 期望：系统识别意图=`根因分析`，槽位=`OF-HF-128`、`累计收入`

#### 步骤 2：展示本体检索范围（50 秒）

- 高亮图谱：产商品主体为中心，展开指标/渠道/行为/促销/竞品节点  
- 讲解：不是全文检索，而是沿本体关系做受控遍历

#### 步骤 3：执行推理并展示路径（120 秒）**【高潮】**

- 展示规则命中列表：R-A01 → R-A02/A03/A04  
- 展示 Top3 根因卡片（带权重与证据）  
- 点击主因「营业厅渠道」下钻：订购量趋势 + 贡献占比

#### 步骤 4：生成分析报告（60 秒）

- 大模型基于**固定证据 JSON**生成报告（禁止模型自行编造数字）  
- 报告结构固定：异动结论 → 根因排序 → 证据 → 建议

#### 步骤 5：闭环动作（40 秒）

- 一键生成「产品优化工单草稿」：续促销 / 厅店激励 / 竞品对标定价  
- 强调：工单字段来自规则，可回写产商品中心/运营流程（MVP 可 mock）

#### 步骤 6：可解释性收尾（30 秒）

- 打开「证据链」面板：规则ID、命中三元组、数据快照时间  
- 金句：「每个结论都能点回图谱边」

### 4.7 验收标准

- [ ] 异动商品 30 秒内给出 Top3 根因  
- [ ] 每条根因至少 1 条可追溯图谱路径  
- [ ] 报告中的关键数字与图谱/规则输出一致  
- [ ] 演示话术不超过 6 分钟讲完主路径

## 五、MVP-2：高风险产商品智能稽核与优胜劣汰

### 5.1 场景目标

对在架产商品做**全量规则稽核**（演示可用 50～200 条样本），自动识别：

1. **高风险**：0 元资费、异常优惠、无合约约束的高危组合  
2. **低效**：长期零销、收入贡献极低、无战略标签  
3. 输出：**风险清单 + 风险等级 + 处置建议（复核/限售/下架）**

### 5.2 业务价值

- 对齐规划：「0元资费等高危业务自动全量筛查」「缩短评估优化链路 40%+」「识别低效产商品减负」  
- 规范对齐：商品定价上移、优惠规则、上下架状态、销售规则/合约约束

### 5.3 演示数据准备（Mock）

准备三类样本（建议共 80 条）：

| 类型 | 数量 | 示例 |
|------|------|------|
| 正常商品 | 60 | 标准月费套餐、有合约终端 |
| 高风险-0元 | 8 | `月费=0` 且上架，无合约；名称含「体验」「测试」 |
| 高风险-异常优惠 | 5 | 折扣 100% + 可重复订购 + 无目标客户群 |
| 低效长期零销 | 7 | 在架 >180 天，30 日销量=0，无战略标签 |

**重点演示商品 A**：`校园体验流量包0元`（OF-RISK-001）  
**重点演示商品 B**：`旧版彩铃包-2019`（OF-LOW-019）

### 5.4 推理链路

```
Offering(上架)
   ├─ hasPricePlan(monthlyFee=0, oneTimeFee=0)
   ├─ not in Whitelist(权益赠送)
   ├─ hasContract = false
   └─(R-B01+R-B02)→ RiskFeature(零元资费, HIGH)
            │
            ├─ shelfDays>30 未复核 → 紧急预警
            └─ 建议动作：立即下架 / 转内部测试渠道 / 补合约约束

Offering(上架)
   ├─ salesCnt30d=0
   ├─ shelfDays>180
   └─(R-B03+R-B04)→ 低效产商品 → 建议下架（减负）
```

### 5.5 处置策略矩阵

| 风险类型 | 等级 | 默认处置 | 人工确认 |
|----------|------|----------|----------|
| 零元资费且无合约 | HIGH | 建议立即下架或转验证渠道 | 必须 |
| 异常全额赠送可重复订购 | HIGH | 限售 + 复核优惠规则 | 必须 |
| 长期零销 | MEDIUM | 建议下架/归档 | 可选 |
| 收入后 5% 且无战略标签 | MEDIUM | 纳入优胜劣汰池 | 可选 |

### 5.6 演示步骤（约 5 分钟）

#### 步骤 0：切到「风险稽核」页（20 秒）

- 展示：全量稽核按钮、上次稽核时间、规则版本号（如 `RiskRules-v1.2`）

#### 步骤 1：一键全量稽核（40 秒）

- 点击「执行智能稽核」  
- 动画：图谱节点扫描 → 规则批次命中计数（R-B01…B05）  
- 结果汇总：高风险 13 / 中风险 7 / 建议下架 7

#### 步骤 2：高风险下钻 —— 0 元资费（90 秒）**【高潮 1】**

- 打开 `OF-RISK-001`  
- 展示命中三元组：  
  - `(OF-RISK-001)-hasPricePlan->(PP-0)`  
  - `(PP-0)-monthlyFee->0`  
  - `(OF-RISK-001)-hasContract->false`  
- 展示风险等级 HIGH + 紧急预警原因（上架未复核超 30 天）  
- 一键生成处置建议卡片

#### 步骤 3：低效优胜劣汰（70 秒）**【高潮 2】**

- 切换筛选「建议下架」  
- 打开 `OF-LOW-019`：在架 287 天、销量 0、无战略标签  
- 展示与运营指标关联：近 90 日收入贡献 ≈0  
- 给出「减负」建议：下架归档，释放目录与配置成本

#### 步骤 4：对比人工抽检（40 秒）

- 同屏对比：人工抽检覆盖率 vs 规则全量覆盖  
- 强调：MVP 已实现「全量自动筛查」闭环雏形

#### 步骤 5：规则可配置亮点（30 秒）

- 打开规则配置页，临时调高「零销天数阈值」180→90  
- 重新推理，清单变化（证明不是写死页面）

### 5.7 验收标准

- [ ] 样本集中所有 0 元高危商品 100% 命中  
- [ ] 白名单权益赠送商品不误报  
- [ ] 每条风险结论可回溯到规则ID与图谱证据  
- [ ] 可导出风险清单（Excel/JSON）供业务确认

## 七、演示话术脚本（可直接照读）

### 7.1 开场（通用）

> 「产商品运营助手以产商品主体为中心，构建运营指标、渠道行为、促销、竞品与风险特征的本体图谱。大模型负责理解问题和生成报告，**判定与归因由本体推理完成**，保证结论可解释、可审计。」

### 7.2 MVP-1 收束金句

> 「收入下滑不再靠人工翻多张报表，而是沿着商品—指标—渠道—促销—竞品的本体关系自动推理，给出带权重的根因路径和可落地的优化建议。」

### 7.3 MVP-2 收束金句

> 「0 元资费、长期零销这类高风险与低效问题，从人工抽检升级为规则全量稽核；命中即给处置建议，支撑产商品目录减负和风险闭环。」

## 八、风险与应对

| 风险 | 应对 |
|------|------|
| 现场无真实经分数据 | 全链路 Mock，但数字口径与规则一致；强调「接口可替换」 |
| 大模型幻觉改写结论 | 报告生成采用「证据 JSON 填槽」，禁止自由发挥关键指标 |
| 规则过严误报 | 配置白名单（权益赠送、内部验证渠道） |
| 图谱关系过深演示超时 | 演示只展开 2 跳，完整路径放「高级视图」 |
| 与产商品中心规范口径不一致 | 实体命名对齐规范：产品/商品/定价/优惠/促销/渠道 |

## 九、Phase-2 扩展（演示时可口头展望）

1. **市场洞察报告**：引入政策/竞品非结构化知识，接问题一
