# 产商品运营场景「大模型+本体」可落地方案与演示手册
本方案基于融合推理智能体平台（LLM + 规则引擎 + 本体图谱）能力，针对产商品运营的市场分析、立项决策、异动归因、风险稽核四大核心场景，提供可直接落地的本体建模、规则设计、工作流编排方案，并配套端到端可演示操作步骤。

## 一、方案整体定位与目标
### 1.1 业务目标
精准对应产商品运营四大核心痛点：
1.  **统一数据口径**：以本体为唯一事实源，打通内部运营、外部竞品、政策数据，消除跨系统数据壁垒
2.  **提升立项效率**：本体数据+规则引擎自动校验立项条件，替代人工汇总报表，缩短决策链条40%+
3.  **加快异动响应**：指标异常后自动下钻归因，替代人工逐维度排查，问题定位效率提升35%+
4.  **消除稽核盲区**：全量自动化筛查高风险产品，实现零资费、低效产品的常态化闭环管控

### 1.2 核心能力分工
| 能力组件 | 职责边界 | 不可替代价值 |
|---------|---------|-------------|
| **产商品领域本体** | 结构化存储产品、指标、渠道、竞品、用户、风险等实体及关联关系，作为唯一事实源 | 保证数据一致性、可追溯，知识沉淀不随人员流动流失 |
| **Drools规则引擎** | 执行确定性业务规则（立项门槛、风险阈值、合规校验），结果不可被大模型覆盖 | 保证决策合规性、确定性，避免大模型幻觉导致业务风险 |
| **SWRL语义推理** | 基于本体属性推导隐性结论（如低效产品判定、潜在痛点识别） | 挖掘显性数据背后的隐性业务特征 |
| **大语言模型** | 自然语言交互、候选方案生成、结果解释、分析报告生成 | 降低使用门槛，替代人工文案类、汇总类工作 |

整体遵循「本体存事实、规则做校验、大模型做交互与生成」的核心原则，全程可追溯、可审计。

## 二、落地基础：产商品领域本体建模
### 2.1 核心实体类设计
基于产商品运营全链路，设计7大类核心实体，完全对应业务本体图谱的核心节点：

| 实体类 | 业务含义 | 核心作用 |
|-------|---------|---------|
| `Product` | 产商品主体 | 核心枢纽实体，关联所有运营、市场、风险属性 |
| `OperationIndicator` | 运营指标 | 营收、用户量、流失率、转化率等量化指标 |
| `SalesChannel` | 销售渠道 | 线上营业厅、线下网点、第三方渠道等 |
| `MarketSegment` | 目标市场/用户群 | 个人客户、家庭客户、政企客户、细分档位 |
| `CompetitorProduct` | 竞品产品 | 友商同类型套餐、资费、定价信息 |
| `RiskRule` | 风险规则 | 零资费、低效、违规定价等风险判定标准 |
| `OperationActivity` | 运营活动 | 营销活动、促销政策、推广动作 |

### 2.2 核心属性定义（示例）
**Product 产品实体核心属性**
| 属性名 | 类型 | 说明 |
|-------|------|------|
| `productId` | string | 产品唯一编码 |
| `productName` | string | 产品名称 |
| `productType` | string | 产品类型：5G套餐/宽带/增值业务/物联网 |
| `status` | string | 状态：待上线/在售/停售/已退市 |
| `price` | float | 标准资费（元/月） |
| `isZeroFee` | boolean | 是否零资费产品 |
| `onlineDate` | date | 上线日期 |
| `lifecycleStage` | string | 生命周期：引入期/成长期/成熟期/衰退期 |

**OperationIndicator 指标实体核心属性**
| 属性名 | 类型 | 说明 |
|-------|------|------|
| `indicatorCode` | string | 指标编码 |
| `indicatorName` | string | 指标名称 |
| `currentMonthValue` | float | 当月值 |
| `lastMonthValue` | float | 上月值 |
| `yearOnYearGrowth` | float | 同比增长率 |
| `monthOnMonthGrowth` | float | 环比增长率 |
| `targetCompletionRate` | float | 目标完成率 |

### 2.3 实体关系映射
| 关系谓词 | 主体 → 客体 | 业务含义 |
|---------|------------|---------|
| `hasIndicator` | Product → OperationIndicator | 产品关联运营指标 |
| `soldThrough` | Product → SalesChannel | 产品通过渠道销售 |
| `targets` | Product → MarketSegment | 产品面向目标市场 |
| `competesWith` | Product → CompetitorProduct | 产品与竞品对标 |
| `compliesWith` | Product → RiskRule | 产品适用风险规则 |
| `promotedBy` | Product → OperationActivity | 产品关联运营活动 |

### 2.4 存储与命名规范
- 命名空间：`http://example.org/product/{实体ID}`，例如 `http://example.org/product/PROD_5G_001`
- 存储引擎：Apache Jena / RDF4J 本体库，支持 SPARQL 查询
- 更新机制：T+1 同步 BOSS、CRM、渠道系统数据，核心指标支持小时级增量更新

## 三、双规则推理体系设计
### 3.1 SWRL 语义推理规则（本体层隐性知识推导）
用于从已知属性中推导隐性业务标签，丰富本体知识维度。

**规则1：低效产品自动判定**
```
Product(?p) ∧ hasIndicator(?p, ?i1) ∧ indicatorCode(?i1, "REVENUE_GROWTH") 
∧ currentValue(?i1, ?v1) ∧ lessThan(?v1, 0.03)
∧ hasIndicator(?p, ?i2) ∧ indicatorCode(?i2, "USER_CHURN") 
∧ currentValue(?i2, ?v2) ∧ greaterThan(?v2, 0.08)
→ productTag(?p, "低效待优化产品")
```
> 业务含义：营收同比增速低于3% 且 用户流失率高于8% 的产品，自动标记为低效待优化产品。

**规则2：高市场潜力产品推导**
```
Product(?p) ∧ productType(?p, "5G套餐") ∧ lifecycleStage(?p, "成长期")
∧ hasIndicator(?p, ?i) ∧ indicatorCode(?i, "NEW_USER_MONTH")
∧ currentValue(?i, ?v) ∧ greaterThan(?v, 5000)
→ productTag(?p, "高潜力明星产品")
```

### 3.2 Drools 业务决策规则（确定性合规校验）
用于业务红线、合规门槛、风险阈值的刚性校验，结果不可被大模型篡改。

**规则R-ONLINE-001：新品立项门槛校验**
```java
rule "新品立项基础门槛校验"
when
    $p : ProductDraft(productType == "5G套餐", targetMarket == "个人客户")
    $market : MarketSegment(scaleEstimate < 100000) from $p.targetMarkets
then
    decision.setVerdict("deny");
    decision.addTriggeredRule("R-ONLINE-001");
    decision.setReason("目标市场规模预估不足10万户，不满足新品立项基础门槛");
end
```

**规则R-RISK-002：零资费产品高风险判定**
```java
rule "零资费产品高风险稽核"
when
    $p : Product(isZeroFee == true, status == "在售", onlineMonths >= 3)
    $ind : OperationIndicator(indicatorCode == "NEW_USER_MONTH", currentValue < 50) from $p.indicators
then
    decision.setVerdict("review");
    decision.addTriggeredRule("R-RISK-002");
    decision.setReason("零资费产品连续3个月单月新增不足50户，触发高风险人工复核");
end
```

## 四、四大业务场景融合推理落地方案
### 4.1 场景1：市场分析智能洞察（解决数据口径割裂）
**核心能力组合**：`nl_query` + `nl_discover_and_retrieve` + 报告生成
**业务流程**：
1.  运营人员输入自然语言问题（如“今年二季度增速最慢的3款在售5G套餐是什么？对标竞品有什么差异？”）
2.  大模型调用本体 schema 目录，识别涉及的实体类与属性，生成 SPARQL 查询
3.  本体库执行查询，返回产品列表、指标数据、竞品对标信息
4.  大模型基于查询结果生成结构化分析结论，支持一键导出分析报告
5.  全程自动写入审计日志，支持追溯数据来源

**落地价值**：无需跨系统取数、统一口径，市场分析耗时从「天级」缩短到「分钟级」。

### 4.2 场景2：新品立项合规研判与方案对比（解决决策低效）
**核心能力组合**：`retrieve_facts` + `evaluate_policy` + `compare_state`
**业务流程**：
1.  产品经理录入新品基础信息（资费、目标市场、预期用户规模）
2.  系统自动检索同类产品、目标市场、竞品等本体事实数据
3.  调用规则引擎执行立项门槛校验，输出 `allow/deny/review` 裁决
4.  针对多套定价/资费方案，调用内存假设推理 `compare_state`，批量对比不同方案的合规性、预期收益
5.  生成立项决策建议报告，附带规则依据与数据来源

**落地价值**：替代人工跨部门取数、撰写分析报告，立项决策周期缩短40%以上。

### 4.3 场景3：运营指标异动智能归因（解决响应滞后）
**核心能力组合**：实时指标接入 + `retrieve_facts` + `evaluate_policy` + `explain`
**业务流程**：
1.  运营指标监控系统触发异动告警（如某产品营收环比下降15%）
2.  自动调用本体接口，下钻拉取关联的渠道数据、用户数据、竞品数据、运营活动数据
3.  规则引擎匹配异动归因规则，定位根因类别（渠道流失/竞品冲击/活动到期/资费争议）
4.  大模型基于审计日志生成自然语言归因报告，包含问题定位、影响范围、处置建议
5.  推送至运营人员，支持一键跳转处置工单

**落地价值**：替代人工逐维度排查溯源，问题定位效率提升35%以上。

### 4.4 场景4：高风险产品批量稽核与退市研判（解决稽核盲区）
**核心能力组合**：批量 `evaluate_policy_with_facts` + `hypothetical_evaluate`
**业务流程**：
1.  每日定时批量拉取全量在售产品本体数据
2.  调用风险规则集批量执行稽核，输出高风险产品清单（零资费、低效、违规等）
3.  针对高风险产品，调用本体版假设推理 `hypothetical_evaluate`，推演「产品退市」「资费调整」两种方案对营收、用户、渠道的影响
4.  生成风险处置建议，同步至产品优化流程
5.  处置结果回写本体，形成闭环

**落地价值**：实现高风险业务全量自动化筛查，消除人工稽核遗漏，低效产品治理效率显著提升。
