# 销售品自动化测试用例设计规范（正式版）

> 分类：K3 测试规范库 | 版本：V2.0（正式版，对齐《销售品自动化测试报告（正式版模板）》三大验证 31 条固定用例）
> 用途：程序B 环节4 自动测试（用例映射 + 判定标准 + 报告生成前知识库检索）；受理/计费/客服三维度测试标准。

## 1. 测试维度与等级定义

### 1.1 三大验证维度
| 维度 | 用例段 | 覆盖内容 |
| --- | --- | --- |
| 受理验证 | ACC-001~012 | CRM 客户准入、互斥依赖、订购/变更/退订能力、受理字段、限购地域、模拟受理接口 |
| 计费验证 | BILL-001~010 | 资费合法性、计费周期、起算规则、资源扣减、优惠叠加、账单试算、退订结算、启停计费 |
| 客服验证 | CUST-001~009 | 客服工作台产品视图、订单查询、操作权限、资费/生效/退订话术、对外展示合规、FAQ 完备性 |

### 1.2 测试等级定义
| 等级 | 名称 | 判定影响 |
| --- | --- | --- |
| P0 | 阻断 | 严重缺陷，影响业务正常受理/计费/服务；任一 P0 ❌ → 整体结论"禁止上线"，必须修复重测 |
| P1 | 警告 | 业务风险点，不阻断上线；P1 ❌ → 整体结论"评估风险后上线"，需业务评估、后续优化 |
| P2 | 提示 | 信息类提示，无业务影响，无需整改，不改变整体结论 |

## 2. 测试场景定义（测试引擎执行口径）
| 场景编码 | 场景名称 | 说明 |
| --- | --- | --- |
| S_O_TC | 套餐新装 | 新号码/老用户订购销售品，验证受理与计费生效 |
| S_ADD_CARD | 副卡加装 | 主套餐下加装副卡，验证共享规则与副卡功能费 |
| S_U_TC | 套餐退订 | 退订销售品，验证退订生效与费用处理 |

## 3. 测点定义（10 测点，预期值核对基准）
| 测点编码 | 测点名称 | 校验内容 |
| --- | --- | --- |
| P_EFF_DATE | 生效时间 | 新入网立即生效（当月过渡期）；老用户次月1日生效 |
| P_EXP_DATE | 失效时间 | 有效期（如2年自动续展）/订购24个月后自动失效 |
| P_STATUS | 状态 | 订购后状态为在用；退订后状态正确流转 |
| P_MAIN_PROD | 主产品 | 主产品关系登记正确 |
| P_RELY_REL | 依赖关系 | 依赖/可选依赖关系与登记一致 |
| P_MUTEX_REL | 互斥关系 | 互斥销售品不可同时订购 |
| P_ORD_CNT | 订购数量 | 数量限制（如权益随心选同一号码仅1个） |
| P_OFFER_NAME | 销售品名称 | 与配置名称一致 |
| P_OFFER_TYPE | 销售品类型 | 类型编码正确 |
| P_PAY_MODE | 付费方式 | 后付费/预付费与配置一致 |

## 5. 用例设计要求
1. **覆盖要求**：每个销售品至少覆盖 S_O_TC（必选）+ S_U_TC（必选）；允许副卡的销售品增加 S_ADD_CARD；三大验证 31 条用例逐条出具结果（无对应出参项的用例标"本销售品未覆盖"，不判 ❌、不计入阻断）。
2. **预期值要求**：每个测点必须填写预期值 presetValue；预期值取值依据为《产品信息》对应销售品规则（K4 存量资料），禁止凭空编造。
   - 示例：900102308 5G-A套餐199元 → P_PAY_MODE 预期"后付费、预付费"；900117022 权益随心选 → P_ORD_CNT 预期"1"。
3. **测试值要求**：testValue 为测试执行实际返回值，与 presetValue 逐项比对，不一致即该测点不通过（resultCode=1），并计入第五章缺陷清单。
4. **18 销售品全量兼容**：测试发起接口须兼容全部 18 个存量销售品（5G-A 10 个 + 权益随心选 8 个）；未收录销售品返回"未匹配到测试场景"。
5. **受理验证**：测试完成后取 orderId/offerInstId 做受理凭证核验（ACC-011/CUST-002）；未获取到受理凭证时，报告结论标注"未获取到受理凭证，需人工核实"（不算测试失败，按 E14 处理）。

## 6. 通过标准（与报告模板第三/八章判定一致）
- **通过分级**：
  - 全部 P0 用例 ✅ 且无未闭环阻断缺陷 → 整体结论"✅ 建议上线"；
  - P0 全部 ✅ 但存在 P1 ❌ 或 risk_list 非空 → 整体结论"⚠️ 评估风险后上线"；
  - 任一 P0 用例 ❌ → 整体结论"❌ 禁止上线"。
- 测点级：任一测点 resultCode=1 → 该测点对应用例 ❌，须整改配置后重新发起测试。
- 流程级：测试发起失败（resultCode=1）或场景为空 → 主干中断（E10/E11），按异常引导处理，不出报告。

## 7. 轮询与超时
- 测试发起后按轮询查询进度（`poll_test_progress.py`，间隔 5s）；连续 5 次查询失败视为异常（E12）。
- 测试执行超时时限 30 分钟（E13）；超时后提示凭 globalId 人工续查。
