**产品名称合并规则（程序A 步骤3 强约束，实测教训 V2.8）**：
1. 步骤3 合并时**禁止把口语化名称直接作为合并值**传入步骤4——先按本表归一为 K1 模板名再合并：
   - 需求"5G套餐 + 档位金额" → 合并值填 `5G-A套餐{档位}元`（引擎会修正为 `5G-A单品套餐{档位}元`）；
   - 口语化原文（如"5G套餐"）仅保留在 need_summary，不进入 fields；
   - 引擎可自动修正的形态：`5G-A套餐599元`→`5G-A单品套餐599元`、`5G-A套餐`（无档位）→`5G-A单品套餐待定档位元`、权益随心选缺"版"后缀等；
   - 引擎**无法**修正的形态（直接 violations）：完全脱离模板的口语名（"5G套餐599元""流量套餐"等，因为无法判断融合/单品属性）——**由合并规则前置规避，而非依赖引擎兜底**；
2. violations 处置（步骤4 后）：仅"产品名称"类格式 violation 不中断流程，但**必须在步骤8 输出中如实附 violations 原文**并提示用户确认命名；其余字段 violation 一律按异常中断；
3. 禁止在对话中自行改写用户原始命名后不再提示（用户对命名有最终决定权）。

**提取自检清单（步骤1 完成后逐项过一遍，全部通过才进入步骤2）**：
- [ ] 原文出现"月费/月租/套餐费+金额"→ 套餐固定费已填（防漏提，实测曾漏）；
- [ ] 流量/语音/短信仅填数值+单位，不带修饰语（"国内""可结转"等修饰语不入 value，可入 need_summary）；
- [ ] 渠道按同义词表拆分为枚举值而非原文照抄；
- [ ] 日期格式为 yyyy-MM-dd 或"立即生效"；
- [ ] 18 项字段齐全，未提及的 value=""（禁止填"无"——"无"是引擎默认值口径，提前填会屏蔽引擎补全）。

## 来源标注规则
- 原始需求：需求要素拆解阶段填入（LLM 标注）；
- AI推理：相似产品 offerInfo 同名字段取值（LLM 标注）；
- 本体推理：引擎补全/修正后自动标注（LLM 禁止自行标注）；
- 来源枚举校验：出现其他值 → 校验失败重新生成。

## req_id 生成规则（build_plan 脚本内实现）
```
req_id = "PLAN" + datetime.now().strftime("%Y%m%d%H%M%S") + 3位随机数(%03d)
示例：PLAN20260913143025087
后端硬校验：格式 PLAN\d{17}（非法返回 5002）；
requirement 环节同键不同内容拦截（返回 5006，防旧方案被静默覆盖；同内容覆盖写不受影响）
```
