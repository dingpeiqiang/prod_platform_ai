## 取值链（逐级降级，禁止跳级虚构）
```
单商品：原始需求 → 相似产品（最高相似度，source=AI推理） → 本体默认值（引擎补全，source=AI补全） → 待补充（仅价格类）
融合组：原始需求（成员级提取） → 相似融合品 offer_group（组级下发，成员逐一对位）
        → 本体默认值（引擎逐成员补全） → 待补充（仅各成员价格类字段，判定按成员独立）
```

- 需求提及但组定义不含的成员 → 组级 violation（不走 E 中断，按 violation 流程引导修改需求）。

# 融合组结构（V4.0 新增；**@deprecated V7.0 起旧轨存档**——模板轨成员表述经提取提示词归入成员容器，成员构成不再依赖 seed_offer_groups 下发）

## plan_json 组结构（offer_type=融合 时；build_plan 脚本生成，模型不手拼）
```json
{
  "req_id": "PLAN20260916100000000",
  "offer_type": "融合",
  "main_offer": {
    "role": "主卡套餐",
    "fields": [ /* 原 24 字段数组（子集），套餐属性=主资费 */ ]
  },
  "member_offers": [
    {"role": "宽带",       "fields": [ /* 24 字段子集（按成员适用性），未涉及字段不出现 */ ]},
    {"role": "天翼高清",   "fields": [ /* ... */ ]},
    {"role": "副卡功能费", "fields": [ /* ... */ ]}
  ],
  "group_rules": {
    "共享规则": "副卡可共享主卡套餐内的语音、流量、网速权益和卫星权益。应用权益主副卡不共享，副卡可单独办理",
    "互斥": [],
    "依赖": [{"member": "副卡功能费", "type": "OPTIONAL_DEPEND", "target": "主卡套餐"}],
    "退订联动": "如主套餐退订，套餐中涉及权益功能同步退订"
  },
  "pending_fields": [ {"role": "宽带", "field": "宽带月功能费"} ]
}
```
- 成员关系与 group_rules **逐字取自** `similar_offer` 出参 `offer_group`（数据源=seed_offer_groups.json），模型禁止自行推理/增删成员（SKILL.md 纪律9）；
- `pending_fields` 每项携带 `role` 定位成员；任一成员价格类字段待补充 → 整体出口A（不保存不产 req_id，口径与单商品一致）；
- 单商品（offer_type=单品）时组结构退化为扁平 fields 数组，`offer_type/main_offer/member_offers/group_rules` 键全部不出现。

## 组结构入参形态（ontology_reason / build_plan 共用识别规则）
```
fields_json 入参：
├─ 扁平 fields 数组 或 {"fields": [...]}   → 单商品（行为与 V2.7 逐字节一致）
└─ {"offer_type": "融合", "main_offer": {...}, "member_offers": [...], "group_rules": {...}}
   → 融合组：逐成员推理（成员内复用单商品逻辑）+ 组级校验（action=group_check）
     出参新增 group.group_violations[]（item/level/desc/suggest，格式与 violations 一致）
```

## plan_md 六列表格（融合组专属，build_plan 按组结构生成）
```markdown
| 商品 | 模块 | 分类 | 字段名称 | 字段值 | 备注 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **主卡套餐**（5G-A融合套餐199元） | 基础信息 | 产品属性 | 套餐名称 | **5G-A融合套餐199元** | 【原始需求】 |
|  |  |  | 套餐档位 | **29元** | 【原始需求】 |
| 宽带 | 资源配置 | 套餐内基础资源 | 宽带速率 | 1000M起 | 【原始需求】 |
| 副卡功能费 | 资源配置 | 套外资费标准 | 月功能费 | 10元 | 【原始需求】 |
```
- 主商品行：商品列加粗（角色+套餐名），字段值整块加粗；成员分组展示，成员名仅在该成员首行显示；
- 模块/分类跨行合并**仅成员块内生效**（不跨成员合并）；
- 六列表头已纳入 validate_output.py 白名单（五列/六列二选一）。

## 引擎两轮推理（V4.0）
1. **成员内推理**（action=reason，逐成员）：复用现有 24 字段校验/修正/补全，`remark_excluded` 剔除按成员内生效；
2. **组级校验**（action=group_check）：互斥/依赖/共享/退订联动对照 `group_rules` + K2 约束表，输出 `group_violations[]`；处置规则与 violations 相同（仅名称类不中断，其余中断引导）。

# 变量命名与枚举值约定

## 1. 变量命名
| 风格 | 适用 | 示例 |
| --- | --- | --- |
| 小写下划线 | 程序步骤变量/脚本参数名/JSON 键 | `requirement_text`、`req_id`（统一键）、`plan_json`、`pending_fields`、`resume_action`、`fail_node`、`approve_confirmed` |
| 驼峰 | 接口原始出参字段（与接口清单保持一致；特例 `offerId` 保持 camelCase） | `globalId`、`offerId`、`testScenes`、`orderId`、`offerInstId` |
| 环节产出引用 | 上一环节出参作为下一环节入参 | 环节1 `offer_id` → 环节2 `--offer-id`（环节1 起该值须在后续环节输出中**显性回显**，见 flow-B"offer_id 显性回显纪律"） |

## 2. 存储与流水
| 变量 | 规则 | 示例 |
| --- | --- | --- |
| `req_id` | `PLAN` + yyyyMMddHHmmss + 3位随机数（build_plan 系统时钟生成；会话内沿用最近值禁止重新生成） | `PLAN20260914174633293` |
| `globalId`（测试流水） | 接口返回原值，不得重生成 | `50202608252017364447983718` |
| node_name 枚举 | requirement / config / spec / fee / test / report | `report` |
| 存储介质 | 后端 `pd_ai_node_results` 表持久化，同键覆盖 | — |

## 3. 枚举值约定（SKILL.md/判定逻辑统一使用）
| 枚举 | 取值 |
| --- | --- |
| 字段来源（备注列） | 原始需求 / AI补全（两态；AI推理/本体推理由 build_plan 归一为 AI补全） |
| 待补充范围 | 仅价格类字段未提取到时填"待补充"；单商品待补充范围=套餐档位；融合组**逐成员独立判定**（主套餐档位与各成员月功能费互相独立，价格禁止跨成员照搬——价格禁止推理纪律延伸到组级）；其余缺失字段一律按相似产品/引擎默认值/seed preset 补全 |
| 成员角色（V4.0） | 主卡套餐 / 宽带 / 天翼高清 / 副卡功能费 / 权益包 / 其他（封闭集合，取值以 offer_group 出参为准） |
| offer_type（V4.0） | 单品 / 融合（需求含宽带/高清/副卡/权益包任一非主资费成员 → 融合；否则单品，plan_json 退化为 V3.0 扁平结构） |
| 套餐编码 | 不补全：由智能配置环节落地后生成，需求未提供时值填"系统待生成" |
| 稽核场景 | spec / fee / all |
| 资费校验场景 | fee / overlay / superposition / all |
| 告警级别 | high / middle / low |
| 确认状态 | SKILL.md 确认语义识别（"确认配置/确认执行/同意/可以/执行吧"）；node_name 枚举不使用 CONFIRMED |

## 4. 请求报文约定（V2.7 起：全部接口裸报文）
请求体直接为业务参数 JSON（置于顶层），无 contractRoot/tcpCont 包裹；出参侧 `_unwrap` 兼容解包保留。
