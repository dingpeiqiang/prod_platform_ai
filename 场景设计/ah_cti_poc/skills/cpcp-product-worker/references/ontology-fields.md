# 销售品字段本体注册表（V3.0：3 模块 / 9 分类 / 24 字段，自样例《加载方案》表格口径）

> 说明：本表为**参考文档**，供需求整合与人工核对使用；运行时单一事实源=后端字段本体推理引擎（工具14 `ontology_reason`，action=reason），引擎校验/修正/补全结果优先于本表。
> V3.0 字段重构：字段名/分类对齐《平台配置清单》输出样例（套餐名称/套餐编码/套餐档位/...）；来源标注收敛为两态【原始需求】/【AI补全】。

## 取值链（逐级降级，禁止跳级虚构）
```
原始需求 → 相似产品（最高相似度，source=AI推理） → 本体默认值（引擎补全，source=AI补全） → 待补充（仅价格类）
```

## 字段本体明细

### 产品属性
| 字段 | 枚举/格式 | 默认值/兜底口径 |
| --- | --- | --- |
| 套餐名称 | 文本；用户命名原样保留（自命名如"校园青春卡"不强制归一模板） | 必填，无默认 |

## 同义词提取映射（需求要素拆解阶段）
| 需求表述 | 映射字段 |
| --- | --- |
| 套餐固定费/月费/月租/月租费/套餐费+金额 | 套餐档位（金额原样填入，缺"元"由引擎补全） |
| 每月30G/月享XX G/含XX流量/XX GB国内流量 | 国内通用流量（原样填"30GB"或"30G"，引擎补单位） |
| XX分钟本地语音/省内语音/通话 | 本地语音 |
| XX条短信 | 短信 |
| 超套后X元/GB、套外流量X元/GB | 套外流量-计费标准 |
| 套外语音X元/分钟 | 套外语音-国内通话 |
| 短信X元/条 | 套外短彩信-短/彩信 |
| 长期有效/有效期X年 | 套餐有效期 |
| 支持副卡/可办副卡 | 是否允许办理副卡=允许 |
| 营业厅/门店 | 销售渠道含"实体渠道"（引擎归一） |
| APP/网厅/线上 | 销售渠道含"电子渠道"（引擎归一） |
| 后付费/预付费 | 付费方式（月付/包月归一为后付费） |
| 流量可结转/当月不清零 | 流量结转规则=结转 |

**语义备注（remark，V2.9）**：需求中与字段枚举冲突但用户已澄清语义的值（如"11月1日生效=商品发布时间，非生效方式"），提取时在该字段项附加 `remark` 键（值为用户原话澄清），引擎识别"非/不属于"类排他备注后跳过本字段校验（不产生 violation），并从方案字段中剔除该值（脚本自动剔除并在出参 `remark_excluded_fields` 列出）；发布时间类信息仅入 need_summary，不占 24 字段。

**提取自检清单（步骤1 完成后逐项过一遍，全部通过才进入步骤2）**：
- [ ] 原文出现"套餐固定费/月费/月租+金额"→ 套餐档位已填（防漏提）；
- [ ] 流量/语音/短信仅填数值+单位，不带修饰语（"国内""可结转"等修饰语不入 value，可入 need_summary）；
- [ ] 渠道按同义词表拆分为枚举值而非原文照抄；
- [ ] 套外资费三项齐全提取（超套表述勿漏）；
- [ ] 24 项字段齐全，未提及的 value=""（禁止填"无"——"无"是引擎默认值口径，提前填会屏蔽引擎补全）。

## 来源标注规则（两态）
- 原始需求：需求要素拆解阶段填入（LLM 标注）；
- AI补全：相似产品 offerInfo 同名字段取值（标"AI推理"，脚本 build_plan 归一显示）或引擎默认值补全/修正（引擎标注）；
- 备注列固定两态：【原始需求】/【AI补全】，出现其他值由 build_plan 自动归一。

## req_id 生成规则（build_plan 脚本内实现）
```
req_id = "PLAN" + datetime.now().strftime("%Y%m%d%H%M%S") + 3位随机数(%03d)
示例：PLAN20260914174633293
后端硬校验：格式 PLAN\d{17}（非法返回 5002）；
requirement 环节同键不同内容拦截（返回 5006，防旧方案被静默覆盖；同内容覆盖写不受影响）
```

# 变量命名与枚举值约定

## 1. 变量命名
| 风格 | 适用 | 示例 |
| --- | --- | --- |
| 小写下划线 | 程序步骤变量/脚本参数名/JSON 键 | `requirement_text`、`req_id`（统一键）、`plan_json`、`pending_fields`、`resume_action`、`fail_node`、`approve_confirmed` |
| 驼峰 | 接口原始出参字段（与接口清单保持一致；特例 `offerId` 保持 camelCase） | `globalId`、`offerId`、`testScenes`、`orderId`、`offerInstId` |
| 环节产出引用 | 上一环节出参作为下一环节入参 | 环节1 `offer_id` → 环节2 `--offer-id`（环节1 起该值须在后续环节输出中**显性回显**，见 flow-B"offer_id 显性回显纪律"） |

## 2. 存储与流水
| 变量 | 规则 | 示例 |
| --- | --- | --- |
| `req_id` | `PLAN` + yyyyMMddHHmmss + 3位随机数（build_plan 系统时钟生成；会话内沿用最近值禁止重新生成） | `PLAN20260914174633293` |
| `globalId`（测试流水） | 接口返回原值，不得重生成 | `50202608252017364447983718` |
| node_name 枚举 | requirement / config / spec / fee / test / report | `report` |
| 存储介质 | 后端 `pd_ai_node_results` 表持久化，同键覆盖 | — |

## 3. 枚举值约定（SKILL.md/判定逻辑统一使用）
| 枚举 | 取值 |
| --- | --- |
| 字段来源（备注列） | 原始需求 / AI补全（两态；AI推理/本体推理由 build_plan 归一为 AI补全） |
| 待补充范围 | 仅价格类字段（套餐档位）未提取到时填"待补充"；其余缺失字段一律按相似产品/引擎默认值补全 |
| 套餐编码 | 不补全：由智能配置环节落地后生成，需求未提供时值填"系统待生成" |
| 稽核场景 | spec / fee / all |
| 资费校验场景 | fee / overlay / superposition / all |
| 告警级别 | high / middle / low |
| 确认状态 | SKILL.md 确认语义识别（"确认配置/确认执行/同意/可以/执行吧"）；node_name 枚举不使用 CONFIRMED |

请求体直接为业务参数 JSON（置于顶层），无 contractRoot/tcpCont 包裹；出参侧 `_unwrap` 兼容解包保留。
