# 异常处理矩阵（自原细化设计第 7 章迁移，V2.3 口径）

> 程序执行中发生异常时，按本矩阵处置后**中断并引导**，输出模板见 SKILL.md。下表"技能N"为历史编号，对应关系：技能1→程序A、技能2/3/5/4→程序B 环节1~4、技能6→程序C、技能7/8→程序D、技能0→SKILL.md 总调度。
>
> **串行中断总则**：除明确标注"提示型异常（保留项）"的 E14/E27/E28 及脚本内置传输层重试（E29 口径，共尝试 3 次）外，任何异常一律终止当前链路并询问用户，禁止自主判断后继续执行其他环节/链路、禁止自主重试、禁止自主降级。**V5.0 起：执行主干四环节的串行中断由 `run_pipeline.py` 状态机代码强制执行（失败即停、e_code 归一返回），模型按出参 e_code 直接对照本矩阵引导即可，无自主判断空间。** **V6.0 起：入口意图/确认门禁/实体抽取由 `dispatcher.py` 确定性执行（规则优先，LLM 仅在其 `needs_llm` 时做封闭枚举兜底），模型按出参 intent/confirmed 加载流程，无自主判断空间。**
>
> 环节3/4 新增异常判定引用：E27 见 flow-B 环节3"desc 系统性为空处置"；E26 见 flow-B 环节4"被测一致性预校验"（先于场景覆盖核对执行）。
>
> **V9.1 审批双轨门禁**：环节1 需求提报（flow-A0）在需求分析前设**需求工单审批门禁**（approval-type=requirement），未通过（或未授权跳过）不得进入需求分析（flow-A 前置检查）——对应 E35；上线审批（approval-type=launch）仍属环节8，门禁见 E15/E16。两类审批单查询均走 flow-D 支线D-1，E21/E22 对两类通用。
