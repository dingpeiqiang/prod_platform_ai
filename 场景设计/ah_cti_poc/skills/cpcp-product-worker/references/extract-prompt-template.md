# 第④步 模板化提取提示词模板（步骤 A4，LLM 环节）V1.0

> 用途：flow-A 模板轨步骤 A4——LLM 结合模板 schema 从需求原文/存量品正文中提取配置要素。
> 注入规模：单模板叶子清单 43~99 行，约 1~3K token，可一次注入。
> 铁律：LLM 只做"自然语言→结构化翻译"，本提示词输出必须经 validate_elements.py 校验后方可进入第⑤步合并。

## 提示词正文（占位符由代码注入，禁止 LLM 自行读取文件）

```
你是电信产销品配置要素提取器。从下方【需求原文】中提取配置要素，填入【模板叶子清单】给出的路径。

【提取规则——逐条强制】
1. 只提取原文可找到（含同义改写）的路径；未提及的路径【不要输出】（合并器按模板补骨架，无需空值）；
2. 输出必须是嵌套 JSON 对象（与模板结构同构，仅含命中路径），禁止输出清单外的路径、禁止输出注释或说明文字；
3. 价格值必须取原文数字（如"199元/月"→199）；原文只有套餐档位金额而无月费明细时，取档位金额填 prcMonthFee（套餐月费）；
4. 枚举字段用原文措辞，不强行归一枚举（归一校验在合并步骤完成，禁止自行改写）；
5. 修饰语剥离：资源值只取量值（"30GB（可结转）"→ 流量值 30GB，"可结转"填结转规则路径）；单位保留原文（GB/分钟/条）；
6. 展示条件字段（清单标"条件:"）：仅当原文明确满足条件时才提取该字段值；
7. 成员表述（宽带/天翼高清/副卡）：归入对应成员容器（手机成员/宽带成员等），禁止混入基础信息；
8. 多档位/多成员并存时，按需求主体逐项提取；无法确定归属的值不提取。

【模板叶子清单】
{{LEAF_LIST}}     ← 代码注入：path | 中文名 | 类型 | 枚举(前6项) | 必填 | 条件(截断20字)，按 schema 顺序

【需求原文】
{{REQUIREMENT_TEXT}}

【输出格式】
仅输出一个 JSON 对象，形如 {"baseInfo": {...}, "optionalInfo": {"printContent": {...}}}，无其他文字。
```

## 输出校验（validate_elements.py，代码化，提示词之后的强制闸）

| 校验项 | 规则 | 处置 |
| --- | --- | --- |
| 路径合法性 | 提取路径 ∈ 模板 schema 叶子集 | 非法路径剔除 + 告警计数 |
| 数值合法性 | type=number 路径的值可转数值 | 不可转 → 剔除 + 告警 |
| 枚举命中率 | 值 ∈ enum（宽松匹配：包含即命中） | 未命中不改写，报 `_meta.enum_violation`（评审结论#4 校验不改写） |
| 提取质量门禁 | 必填字段命中率 = 原文可提取必填 / 模板必填总数（阈值 P0=30%，按模板调） | 低于阈值 → E31 中断（提取失败，打回重跑 LLM 一次，仍低则转人工） |
| 价格交叉核对 | prcMonthFee/fixFee 与需求档位金额一致性 | 不一致 → 告警清单（不阻断） |

## 存量实例化场景（--mode legacy）附加规则

- 需求原文 = K4存量 md 正文（分节结构），映射提示同源表：
  - 「套内资费」节 → 档位/资源/宽带速率/网络权益 → baseInfo + optionalInfo.printContent/billGprsCfg/billVoiceCfg；
  - 「套外资费」节 → optionalInfo.printContent.chargeStandard（超套收费标准）；
  - 「过渡期资费」节 → 过渡期规则（如模板无对应路径则不提取——模板是报文规范不是资料库）；
  - 「副卡」节 → phoneMbrInfo（成员数/月租）；
  - 「计费周期与付费方式」「销售渠道」节 → releaseInfo + 枚举字段；
  - 「套餐订购/变更/退订」节 → effRuleId/cancelRuleId 等生效方式字段（原文是规则描述时提取语义值，不猜编码）；
- **价格豁免**：存量品价格是事实数据，正常提取（不受"禁止照搬"约束——该约束只作用于相似品跨品补全，merge_nested --mode legacy 已实现）；
- source 标注由合并器统一打「存量提取」，提示词不输出 source 字段。
