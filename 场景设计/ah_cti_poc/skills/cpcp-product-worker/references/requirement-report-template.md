# 需求提报文档模板（需求提报 —— 解读用户需求生成）

> 分类：需求提报模板（flow-A0 环节1 需求提报专用）| 版本：V1.1
> 用途：用户在确认意图为【配置】后，触发需求提报；数字员工按本模板解读用户需求，生成**《销售品需求提报单》**，并据此发起**需求工单审批**。
> 关联：本模板产物即"需求提报文档"，是需求提报环节的输出；审批通过后才允许进入下一流程【需求分析】（flow-A）。
> **渲染方式（V1.1 模板引擎接管）**：本模板仅定义**需求字段集合 + 业务示例形态**；LLM **只做"自然语言→结构化字段"翻译**（输出 snake_case 平面 JSON），《销售品需求提报单》最终由确定性脚本 `scripts/render_requirement_report.py` **模板引擎渲染**（业务可读、逐字节可回归），**禁止 LLM 手工渲染中文文档**。字段集合与脚本 FIELDS 保持一致。

## 一、模板结构（解读需求后按此填充，业务人员可读、数据逐字引用用户描述）

> 生成原则：只填充用户在需求描述/文档中明确给出的内容；未提及项留空待补充，**禁止凭空臆造或从相似产品照搬**（价格纪律延用）。
> **待补充判定口径（从宽，仅必要字段）**：仅**必要的资费价格（套餐档位 price）与资费免费资源（套内资源 resources）**缺失才判待补充；其余字段（产品类型/所属系列/融合成员/套外资费/计费周期/生效方式/有效期/变更规则/退订规则）缺失**不判待补充**，按用户原话引用（缺则对应行不渲染，套外资费缺省亦不渲染）。判定唯一事实源=`render_requirement_report.py` 的 `REQUIRED_FIELDS`。
> 字段与 `render_requirement_report.py` 的入参键一一对应（snake_case）：name/product_type/series/members/price/resources/out_price/billing_cycle/effective_way/validity/change_rule/cancel_rule；需求基本信息（req_id/提报人/日期/需求概述 need_summary）由系统注入。
> **业务模板分支（单商品/融合品模板不同，禁止混用）**：`product_type` 为**融合品类型**（家庭基础套餐，schema 顶层含成员块 phoneMbrInfo/broadBandMbrInfo）时字段集含"融合成员"（有值渲染，缺失从宽不催补）；为**单商品类型**（个人主套餐/个人附加资费/宽带主套餐/宽带附加资费/家庭附加资费）时字段集**不含"融合成员"**——既不渲染该行也不判其待补充。单商品类型下 LLM 若误填 members，渲染脚本忽略其对待补充/渲染的影响（分支判定唯一事实源=product_type，见 `render_requirement_report.py::fields_for`）。

> **收尾行归属说明（V11.0）**：`render_requirement_report.py` 只渲染**单据本体**（标题头 `## 销售品需求提报单` + 1~4 分节表 + 待补充字段节），`report_text` **不含**"建议处理"行——此为正确设计。单据之后**必须由 flow-A0 输出模板追加收尾固定块**（`> **建议处理：** …`，SKILL.md 纪律5.1），收尾块是整条回复的最后一个内容块。若截图/回放中回复以"待补充字段：无"或表格结束，属 flow-A0 输出模板遗漏收尾块，**非渲染脚本缺陷**，不得通过改脚本"补页脚"。

## 二、需求工单审批（需求提报后必接，非必选跳过）
- 需求提报文档生成后，**必须提示用户是否发起【需求工单审批】**；
- 用户明确回复"发起需求审批"/"提交需求审批"→ 调用审批接口（approval-type=requirement，复用 submit_approval 机制）；
- 审批状态查询复用 flow-D 支线D-1（approval_id 区分需求工单审批单与上线审批单）；
- **需求工单审批通过后**，才允许用户触发【配置流程】（需求分析 → 智能配置 → 上线审批 → 监控运维）；
- 需求工单审批未通过/未发起 → 不进入需求分析，停留在需求提报环节（可修改需求重新提报）。

## 三、禁止事项
- 禁止在需求提报文档中臆造未提及的资费/规则值（价格纪律延用：价格类字段待补充即整体待补充）；
- 禁止跳过需求工单审批直接进入需求分析（门禁由 flow-A0 硬性前置检查保证）；
- 禁止把相似产品的配置值抄入需求提报文档（需求提报只反映用户原始表述）。
