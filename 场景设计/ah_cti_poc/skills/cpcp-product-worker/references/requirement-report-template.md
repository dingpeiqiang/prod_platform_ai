# 需求提报文档模板（需求提报 —— 解读用户需求生成）

> 分类：需求提报模板（flow-A0 环节1 需求提报专用）| 版本：V1.0
> 用途：用户在确认意图为【配置】后，触发需求提报；数字员工按本模板解读用户需求，生成**《销售品需求提报单》**，并据此发起**需求工单审批**。
> 关联：本模板产物即"需求提报文档"，是需求提报环节的输出；审批通过后才允许进入下一流程【需求分析】（flow-A）。

## 一、模板结构（解读需求后按此填充，业务人员可读、数据逐字引用用户描述）

> 生成原则：只填充用户在需求描述/文档中明确给出的内容；未提及项留空待补充，**禁止凭空臆造或从相似产品照搬**（价格纪律延用）。

### 1. 需求基本信息
| 字段 | 内容 |
| --- | --- |
| 需求单号 | req_id（PLAN + 时间戳 + 随机，系统生成） |
| 提报人 | （会话用户，未提供留空） |
| 提报日期 | （系统当前日期） |
| 需求概述 | （1~2 句需求理解摘要） |

### 2. 产品/销售品信息
| 字段 | 内容 |
| --- | --- |
| 销售品名称 | （用户描述中的套餐/产品名） |
| 产品类型 | 个人主套餐 / 宽带主套餐 / 个人附加资费 / 宽带附加资费 / 家庭基础套餐 / 家庭附加业务 |
| 所属系列 | （如 5G-A 融合套餐 / 5G-A 单品 / 权益包，未提及留空） |
| 融合成员 | （如 宽带 / 天翼高清 / 副卡功能费，单商品留空） |

### 3. 资费方案要点（各价格字段独立判定，禁止跨成员照搬）
| 字段 | 内容 |
| --- | --- |
| 套餐档位（月费） | 元/月 |
| 套内资源（流量/语音/短信/副卡等） | （逐项列出） |
| 套外资费 | （如套外流量阶梯计价/套外语音 X 元/分钟） |
| 计费周期 | （周期型缴费：月 / 年等） |

### 4. 订购 / 变更 / 退订规则
| 字段 | 内容 |
| --- | --- |
| 生效方式 | （新入网立即生效 / 老用户次月 1 日生效等） |
| 套餐有效期 | （如 2 年，届满自动续展等） |
| 变更规则 | （可否变更至在售其他套餐/生效时点） |
| 退订/拆机规则 | （可否退订/生效时点/费用是否退还） |

### 5. 需求提报文档示例形态（渲染示意）
```
【需求提报单】{{套餐名称}}
- 需求单号：{{req_id}}｜提报日期：{{日期}}
- 产品类型：{{产品类型}} ｜ 所属系列：{{系列}}
- 套内资源：流量 {{X}}GB / 语音 {{X}}分钟 / 短信 {{X}}条
- 套餐月费：{{X}} 元/月
- 套外资费：{{套外描述}}
- 计费周期：{{周期}}
- 生效方式：{{生效方式}}｜有效期：{{有效期}}
- 变更/退订：{{变更规则}}；{{退订规则}}
- 待补充字段：{{未提及项，逐项列出；无则"无"}}
```

## 二、需求工单审批（需求提报后必接，非必选跳过）
- 需求提报文档生成后，**必须提示用户是否发起【需求工单审批】**；
- 用户明确回复"发起需求审批"/"提交需求审批"→ 调用审批接口（approval-type=requirement，复用 submit_approval 机制）；
- 审批状态查询复用 flow-D 支线D-1（approval_id 区分需求工单审批单与上线审批单）；
- **需求工单审批通过后**，才允许用户触发【配置流程】（需求分析 → 智能配置 → 上线审批 → 监控运维）；
- 需求工单审批未通过/未发起 → 不进入需求分析，停留在需求提报环节（可修改需求重新提报）。

## 三、禁止事项
- 禁止在需求提报文档中臆造未提及的资费/规则值（价格纪律延用：价格类字段待补充即整体待补充）；
- 禁止跳过需求工单审批直接进入需求分析（门禁由 flow-A0 硬性前置检查保证）；
- 禁止把相似产品的配置值抄入需求提报文档（需求提报只反映用户原始表述）。
