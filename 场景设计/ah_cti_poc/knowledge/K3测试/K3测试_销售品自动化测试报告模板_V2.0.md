# 销售品自动化测试报告模板（正式版）

> 分类：K3 测试规范库 | 版本：V2.0（正式版，对齐《销售品自动化测试报告（正式版模板）.docx》9 章节结构）
> 用途：程序B 环节4 自动测试报告生成 + 程序C 上线审批报告归档；报告结构基准。
> 数据源纪律：报告内容**只基于脚本出参生成**（`test_result` / `test_scenes` / `billing_verify` / `spec_audit` / 存储环节结果），逐字引用禁止加工；出参不存在的字段该行省略，禁止虚构。

## 报告结构模板（9 章节）

```
【销售品自动化测试报告】TEST-REP-{yyyyMMdd}-{4位序号}

一、报告概述
- 报告目的：本报告为销售品上线前自动化测试输出文档，通过受理验证、计费验证、客服验证三大核心维度，
  对销售品配置完整性、业务合规性、系统可用性进行全自动校验，用于判定产品是否满足
  上线投产、进入审批流程的质量准入标准。
- 测试范围：销售品全量上线校验（CRM 受理订购/变更/退订规则、产品互斥依赖、资费计费规则、
  资源扣减、客服视图展示、订单查询、客服话术与知识库合规性）。
- 测试依据：产销品加载执行方案（req_id）、产品业务规范（K1）、计费引擎配置规范、
  CRM 受理约束规则、客服展示规范、本体库业务校验规则。
- 测试等级定义：
  - 阻断（P0）：严重缺陷，影响业务正常受理/计费/服务，禁止上线，必须修复重测；
  - 警告（P1）：业务风险点，不阻断上线，但需业务评估、后续完善优化；
  - 提示（P2）：信息类提示，无业务影响，无需整改。

二、基础信息

| 报告编号 | TEST-REP-{yyyyMMdd}-{4位序号} |
| 测试任务ID | {testRequestId} |

| 销售品编码 | {offerId} |
| 产品类型 | {主套餐 / 流量包 / 增值业务，取配置 plan_json 套餐属性} |

| 所属部门 | 产商品中心（CRM_POS） |
| 生效时间 | {配置套餐生效规则摘要} |
| 测试方式 | 全自动智能测试（数字员工） |
| 测试时间 | {报告生成时间} |
| 关联加载方案 | {req_id} |
| 测试流水号 | {globalId} |

三、测试总体结论
| 统计项 | 数量 |
| 总校验用例数 | {各场景 testCaseCount 合计，逐字引用出参统计} |
| 通过用例 | {各场景 successTestCaseCount 合计} |
| 警告用例 | {warning 级明细数，出参无则填 0} |
| 阻断用例 | {各场景 failTestCaseCount 合计} |
| 通过率 | {通过用例/总用例，百分比} |
| 整体上线结论 | 【建议上线 / 评估风险后上线 / 禁止上线】（判定规则见填写规范5） |
```

## 填写规范

1. **数据源唯一**：报告内容只基于脚本出参与存储环节结果生成；出参没有的数据该行省略或标注"本销售品未覆盖"，禁止虚构统计值、凭证、结论。
2. **用例等级固定**：ACC/BILL/CUST 三表用例 ID/名称/等级为模板固定项，禁止增删改；"测试结果"列仅依据出参字段判定（测点 resultCode==0 为 ✅，1 为 ❌；场景 failTestCaseCount==0 为 ✅，否则 ❌）；无对应出参项的用例行结果标注"本销售品未覆盖"（不判 ❌、不计入阻断）。
3. **测点-用例映射**：P_MUTEX_REL→ACC-002、P_RELY_REL→ACC-003、P_ORD_CNT→ACC-008、P_EFF_DATE→ACC-010、P_EFF_DATE/P_EXP_DATE→BILL-010/CUST-005、P_OFFER_NAME/P_OFFER_TYPE/P_PAY_MODE→ACC-007/CUST-001；资费 8 项 compare_list→BILL-001~005；risk_list→BILL-006。
4. **受理凭证（E14）**：orderId/offerInstId 为空时报告正常生成，4.1 节受理凭证行标注"未获取到受理凭证，需人工核实"，不算异常、不中断主干；ACC-011 同步标注。
5. **整体上线结论判定（第3/8章一致）**：
   - 全部 P0 用例 ✅ 且无未闭环阻断缺陷 → **✅ 建议上线**；
   - P0 全部 ✅ 但存在 P1 ❌ 或 risk_list 非空 → **⚠️ 评估风险后上线**；
   - 任一 P0 用例 ❌（含测试不通过 test_passed=失败）→ **❌ 禁止上线**。
6. **缺陷清单溯源**：第五章每行必须可追溯到出参原文（测点编码/风险项/场景名），禁止凭语义猜测编造缺陷。
7. **报告存储**：报告生成后存入节点结果存储（node=report，程序C 步骤4），供上线审批环节引用与 `submit_approval --report-file` 推送。

## 与旧版（试用版）差异

| 项 | 试用版 V1.0 | 正式版 V2.0 |
| --- | --- | --- |
| 章节结构 | 5 节（概要/场景执行/测点核对/受理验证/结论） | 9 章节（概述/基础信息/总体结论/三大验证分项/缺陷清单/风险汇总/整改建议/最终结论/版本说明） |
| 验证维度 | 测点比对（10 测点） | 三大验证：受理（ACC 12 条）/ 计费（BILL 10 条）/ 客服（CUST 9 条），共 31 条固定用例 |
| 缺陷分级 | 无分级 | P0 阻断 / P1 警告 / P2 提示 三级 |
| 上线结论 | 通过 / 不通过 | 建议上线 / 评估风险后上线 / 禁止上线（三选一） |
| 基础信息 | 5 项 | 12 项（含报告编号/测试任务ID/关联加载方案等） |
