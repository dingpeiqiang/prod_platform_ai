# 销售品测试报告模板（试用版）

> 分类：K3 测试规范库 | 版本：V1.0（试用版，供 AI 应用知识库冷启动使用）
> 用途：wf_sub_04 自动测试（节点6 受理验证报告生成）；报告结构基准，与细化设计 3.4.5 提示词对齐。

## 报告结构模板

```
【销售品自动测试报告】
一、报告基本信息
- 销售品ID / 名称：{offerId} / {offerName}
- 测试流水号：{globalId}
- 订单号 / 销售品实例：{orderId} / {offerInstId}（未获取时标注"未获取到受理凭证，需人工核实"）
- 执行编号：{execution_id}
- 报告生成时间：{timestamp}

二、测试场景与执行情况
- 发起场景：{testScenes}（S_O_TC / S_ADD_CARD / S_U_TC）
- 发起结果：resultCode / resultMsg
- 轮询进度：{progress}（终态：完成 / 超时30分钟 / 连续5次查询失败）

三、测点核对结果（逐项列出）
| 测点 | 测点名称 | 预期值 presetValue | 实际值 testValue | 比对结论 |
| P_EFF_DATE | 生效时间 | ... | ... | 通过/不通过 |
| P_EXP_DATE | 失效时间 | ... | ... | ... |
| P_STATUS | 状态 | ... | ... | ... |
| P_MAIN_PROD | 主产品 | ... | ... | ... |
| P_RELY_REL | 依赖关系 | ... | ... | ... |
| P_MUTEX_REL | 互斥关系 | ... | ... | ... |
| P_ORD_CNT | 订购数量 | ... | ... | ... |
| P_OFFER_NAME | 销售品名称 | ... | ... | ... |
| P_OFFER_TYPE | 销售品类型 | ... | ... | ... |
| P_PAY_MODE | 付费方式 | ... | ... | ... |

四、受理验证结论
- 受理单据核对：{受理验证描述}
- 阻塞问题：{无 / 问题清单}

五、测试结论
- 结论：通过 / 不通过
- 整改建议：{不通过时给出，指向需整改的测点与配置项}
```

## 填写规范
1. 测点核对表必须逐项列出（10 个测点全覆盖），不得省略。
2. 预期值必须来源于 K4 存量资料（产品信息规则），并在必要时注明依据切片（如"依据 [900102308] [套外资费]"）。
3. 比对结论仅两种：通过（testValue=presetValue）/ 不通过。
4. orderId/offerInstId 为空时按 E14 处理：报告正常生成，受理验证结论标注"未获取到受理凭证，需人工核实"，不算异常、不中断主干。
5. 测试不通过时，整改建议必须可执行（指明测点、预期与实际的差异、涉及的配置字段）。
6. 报告生成后存入节点结果存储（key 规范见存储插件），供上线审批环节引用。

## 附则
- 本模板为试用版，正式版以测试部门发布的《销售品测试报告模板》为准。
