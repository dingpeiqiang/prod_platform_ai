# 营销服超级数字员工 - 产销品场景 接口文档（含模拟入参）

> 本文件描述**平台对外 REST 接口**（`AppStoreV16Controller`，前缀 `/api/v1/appstore`），
> 即自研插件集 / 工作流 / 前端实际调用的接口层；底层经适配层 `InterfaceFacade`
> 在 `MockInterfaceAdapter`（开发）与 `EopInterfaceAdapter`（现场 EOP）间切换。
>
> 来源：`AppStoreV16Controller.java`、`InterfaceFacade.java`、`MockInterfaceAdapter.java`、
> `OfferSimV16Service.java`、`EopInterfaceAdapter.java`
>
> 与之对应的 EOP 网关原始接口见《营销服超级数字员工-产销品场景接口规范.md》。

## 一、总体说明

| 项目 | 说明 |
| --- | --- |
| 服务名 | 产销品加载 AI 应用 V1.6 · 自研模拟接口 |
| 服务基础地址 | `http://{host}:6174`（本地默认端口 `6174`，无 context-path） |
| 路由前缀 | `/api/v1/appstore` |
| 出参命名 | 统一 snake_case（部分业务字段保留 camelCase，与导出契约一致） |
| 模式切换 | `prodai.appstore.interface.mode = mock \| real`（改配置即切换，接口签名不变）；混合模式用 `real-list` 白名单逐接口路由 |
| real 调用方式 | 业务报文直接 POST 到业务地址 `{eop.base-url}{eop.paths.<key>}`；**HTTP 请求头**携带鉴权 `X-APP-ID` / `X-APP-KEY` / `Api-Key`（= 该接口 EOP ApiID） / `Staff-Code` |
| real 失败策略 | **严格报错，不回退 mock**：连接/超时/解析异常或 EOP 业务错误（如鉴权失败）均返回 `resultCode=REAL_CALL_FAILED`，`resultMsg` 带失败原因与 EOP 原始 `errcode/errmsg` |

| 平台路由 | EOP ApiID（Api-Key） | EOP 业务地址 | 接口键 | 说明 |
| --- | --- | --- | --- | --- |
| `POST /similar/offer/query` | 2069789780752355328 | `/api/ah/cpcp/similar` | `similar` | A1 相似度分析（信封） |
| `POST /audit/file/upload` | 2069625643688792064 | `/api/ah/cpcp/upload` | `upload` | B1 稽核文件上传 |
| `GET\|POST /audit/async/notify` | 2069670925484838912 | `/api/ah/cpcp/async_report_notify_direct` | `notify` | B2 异步报告生成 |
| `POST /audit/result/insert` | 2092438683005603840 | `/api/ahhui/cpcp/insertAiAuditResult` | `insert` | B3 插入 AI 稽核结果（裸体） |
| `POST /audit/sql-query` | 2077203852248748032 | `/api/ah/slzx/invokeInfo/executeSqlService` | `sql` | B4 通用 SQL 查询（信封） |
| `POST /test/offer/start` | 2070425775141294080 | `/api/anhui/cpcp/offerTest` | `testStart` | C1 测试发起（裸体） |
| `POST /test/offer/scenes` | 2070440544124538880 | `/api/anhui/cpcp/getTestScenes` | `testScenes` | C2 测试场景（裸体） |

| `POST /test/offer/result` | 2070435348195577856 | `/api/anhui/cpcp/getTestResult` | `testResult` | C4 测试结果（裸体） |

**鉴权请求头**

| Header | 示例值 | 来源 |
| --- | --- | --- |
| `X-APP-ID` | `91382a43511f4f7e037856c280f0a1f1` | `eop.app-id`（默认示例值，`EOP_APP_ID` 可覆盖） |

### 接口1 相似度分析

| 项目 | 内容 |
| --- | --- |
| 路径 | `POST /api/v1/appstore/similar/offer/query` |
| Content-Type | `application/json` |
| 说明 | 以 18 销售品为相似库，按业务需求描述返回相似销售品列表及相似度评分 |

**请求入参**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `business_desc` | string | 是 | 业务需求描述文本（兼容 `businessDesc`） |
| `template_id` | string | 否 | 需求分析模板轨传入，为相似品附存量逻辑模型报文（兼容 `templateId`） |

**模拟入参**

```json
{
  "business_desc": "面向青年用户，主推大流量、低月租的5G套餐，可叠加视频会员权益"
}
```

**curl**

```bash
curl -X POST "http://127.0.0.1:6174/api/v1/appstore/similar/offer/query" ^
  -H "Content-Type: application/json" ^
  -d "{\"business_desc\":\"面向青年用户，主推大流量、低月租的5G套餐，可叠加视频会员权益\"}"
```

**响应出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `resultCode` | string | `0` 成功 |
| `resultMsg` | string | 摘要（命中数 + 主推荐） |
| `similarOffer` | object | 主推荐销售品 |
| `similarOfferList` | array | 相似销售品列表（按相似度降序，最多 3 条） |
| `similarOfferList[].similarOfferId` | string | 相似销售品 ID |
| `similarOfferList[].similarOfferName` | string | 相似销售品名称 |
| `similarOfferList[].similarityScore` | string | 相似度评分（0~1） |
| `similarOfferList[].similarityDesc` | string | 相似原因描述 |
| `offer_group` | object | 命中融合商品时内嵌（组定义逐字引用），单品无该键 |

**响应示例**

```json
{
  "resultCode": "0",
```

### 接口2 智能稽核文件上传

| 项目 | 内容 |
| --- | --- |
| 路径 | `POST /api/v1/appstore/audit/file/upload` |
| Content-Type | `multipart/form-data` |
| 说明 | 上传稽核需求文档（Excel），解析销售品清单，返回 `file_id` 与 `sales_id` |

**请求入参**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | file | 是 | 销售品稽核需求 Excel（xls/xlsx），最大 10MB |
| `mode` | string | 否 | `real` / `mock`，覆盖本次调用的适配层模式 |

**curl**

```bash
curl -X POST "http://127.0.0.1:6174/api/v1/appstore/audit/file/upload" ^
  -F "file=@需求文档5G畅享融合套餐销售品.xlsx"
```

**响应出参**

| 字段 | 类型 | 说明 |

| `resultCode` / `resultMsg` | string | 处理结果与摘要 |

**响应示例**

```json
{
  "file_id": "file_20260623120000_mock0001",
  "sales_id": {
```

### 接口3 异步报告生成并通知

| 项目 | 内容 |
| --- | --- |
| 路径 | `GET|POST /api/v1/appstore/audit/async/notify` |
| 说明 | 每个销售品调用一次，通知 AI 能力中心启动稽核报告生成，返回 `request_id` 供轮询 |

**请求入参**（GET 查询参数与 POST JSON 体均支持，体参数优先）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sales_id` | string | 是 | 销售品 ID（兼容 `salesId`） |
| `location` | string | 否 | 数据位置索引（非负整数，默认 `0`） |
| `sheet_name` | string | 否 | 销售品类型：套餐/可选包/促销包（默认 `套餐`） |
| `file_id` | string | 否 | 文件唯一标识，不传则使用最新上传文件 |

**模拟入参**

```json
{
  "sales_id": "900117029",
  "location": "0",
  "sheet_name": "套餐",
  "file_id": "file_20260623120000_mock0001"
}
```

**curl**

```bash
curl -X POST "http://127.0.0.1:6174/api/v1/appstore/audit/async/notify" ^
  -H "Content-Type: application/json" ^
  -d "{\"sales_id\":\"900117029\",\"location\":\"0\",\"sheet_name\":\"套餐\",\"file_id\":\"file_20260623120000_mock0001\"}"
```

**响应出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `success` | boolean | 是否受理成功 |
| `message` | string | 受理提示 |
| `request_id` | string | 请求唯一标识，供 B3 落库与 B4 轮询 |
| `sales_id` | string | 销售品 ID 回显 |

**响应示例**

```json
{
  "success": true,
  "message": "稽核任务已开始处理，完成后将自动通知外部系统",
  "request_id": "20260331123456_mock1234",
  "sales_id": "900117029",
  "resultCode": "0",
  "file_id": "file_20260623120000_mock0001"
}
```

### 接口4 插入 AI 稽核结果

| 项目 | 内容 |
| --- | --- |
| 路径 | `POST /api/v1/appstore/audit/result/insert` |
| Content-Type | `application/json` |
| 说明 | 每个销售品拿到 `request_id` 后立即调用，插入 `AI_AUDIT_RESULT`、`AI_AUDIT_RECORD`，状态 `1000` 处理中 |

**请求入参**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `records` | array | 是 | 待落表稽核记录数组（兼容批量） |
| `records[].batchId` | string | 是 | 稽核批次号，`yyyyMMddHHmmss + 4位随机数` |
| `records[].reqOrderId` | string | 否 | 需求单 ID，默认 `-1` |
| `records[].offerId` | string | 是 | 销售品 ID |
| `records[].offerName` | string | 是 | 销售品名称 |
| `records[].requestId` | string | 是 | B2 返回的 `request_id` |
| `records[].staffId` | string | 否 | 员工 ID |

**模拟入参**

```json
{
  "records": [
    {
      "batchId": "202608241024501234",
      "reqOrderId": "-1",
      "offerId": "900117029",
      "offerName": "5G畅享融合套餐129元档",
      "requestId": "20260331123456_mock1234",
      "staffId": ""
    }
  ]
}
```

**curl**

```bash
curl -X POST "http://127.0.0.1:6174/api/v1/appstore/audit/result/insert" ^
  -H "Content-Type: application/json" ^
  -d "{\"records\":[{\"batchId\":\"202608241024501234\",\"reqOrderId\":\"-1\",\"offerId\":\"900117029\",\"offerName\":\"5G畅享融合套餐129元档\",\"requestId\":\"20260331123456_mock1234\",\"staffId\":\"\"}]}"
```

**响应示例**

```json
{
  "resultCode": "0",
  "resultMsg": "处理成功（mock 落表 1 条，状态 1000 处理中）"
}
```

### 接口5 通用 SQL 查询

| 项目 | 内容 |
| --- | --- |
| 路径 | `POST /api/v1/appstore/audit/sql-query` |
| Content-Type | `application/json` |
| 说明 | 轮询稽核任务完成状态（`sql_id=20260626001`）或查询最终稽核结果（`sql_id=20260626002`） |

**请求入参**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sql_id` | string | 是 | `20260626001` 查完成状态；`20260626002` 查稽核结果 |
| `params` | string | 是 | 业务参数，格式 `requestIds:id1,id2,id3`（逗号分隔） |

**模拟入参（轮询完成状态）**

```json
{
  "sql_id": "20260626001",
  "params": "requestIds:20260331123456_mock1234"
}
```

**curl**

```bash
curl -X POST "http://127.0.0.1:6174/api/v1/appstore/audit/sql-query" ^
  -H "Content-Type: application/json" ^
  -d "{\"sql_id\":\"20260626001\",\"params\":\"requestIds:20260331123456_mock1234\"}"
```

**响应出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `resultCode` / `resultMsg` | string | 处理结果 |

| `execute_sql_resp[].isAllFinished` | string | `Y` 全部完成 / `N` 未完成 |

```json
      "totalCount": "1"

  ]
}
```

```json
{
  "resultCode": "0",
  "resultMsg": "成功",
  "execute_sql_resp": [
    {
      "finishedCount": "1",
      "isAllFinished": "Y",
```

### 接口8 查询测试进度

| 项目 | 内容 |
| --- | --- |
| 路径 | `POST /api/v1/appstore/test/offer/progress` |
| Content-Type | `application/json` |
| 说明 | 轮询测试任务当前步骤、是否完成、是否失败，驱动前端步骤版 thinking |

**请求入参**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `global_id` | string | 是 | 测试流水号，取接口6 返回的 `globalId` |

**模拟入参**

```json
{ "global_id": "50202608252017364447983718" }
```

**curl**

```bash
curl -X POST "http://127.0.0.1:6174/api/v1/appstore/test/offer/progress" ^
  -H "Content-Type: application/json" ^
  -d "{\"global_id\":\"50202608252017364447983718\"}"
```

**响应出参**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `totalSteps` | string | 总步骤数 = 场景数 + 2（前 2 步固定为「智能匹配测试场景&用例」「智能匹配测试资源」） |
| `activeIndex` | string | 当前应高亮步骤下标（从 0 计） |
| `done` | string | `true` 全部完成 |
| `failed` | string | `true` 存在失败/中止场景 |
| `failIndex` | string | 首个失败场景步骤下标，无失败为 `-1` |
| `totalSceneCount` / `finishedSceneCount` / `failedSceneCount` | string | 场景总数 / 已完成数 / 失败数 |

**响应示例（进行中）**

```json
{
  "resultCode": "0",
  "totalSteps": "5",
  "activeIndex": "3",
```

## 四、错误码约定

| resultCode | 含义 | 出现位置 |
| --- | --- | --- |
| `0` | 成功 | 全部接口 |
| `1` | 处理失败 | B2/B4 参数缺失等 |
| `4001` | 销售品未收录 | 测试发起 |
| `4002` | 参数必填/查无任务 | 测试场景/进度/结果 |
| `4003` | 测试未完成（`done!=true`） | 测试结果 |
| `PARAM_MISSING` | 必填参数缺失 | 相似度分析 |
| `REAL_CALL_FAILED` | real 调用失败（不回退）：网关不可达/超时/响应非 JSON/EOP 业务错误（含鉴权失败 errcode=242）/出参缺字段 | real 模式全部接口 |

> real 模式严格报错示例（EOP 鉴权失败时）：
> ```json
> { "resultCode": "REAL_CALL_FAILED", "resultMsg": "真实接口调用失败：EOP 业务错误 [similar] errcode=242 errmsg=鉴权码无效", "key": "similar" }
> ```

## 五、联调建议

1. 先调 `interface/mode` 确认模式；开发环境应为 `mock`。
2. 稽核链路顺序：`audit/file/upload` → `audit/async/notify`（逐销售品）→ `audit/result/insert` → 轮询 `audit/sql-query`（`20260626001`）→ `20260626002` 取结果。
3. 测试链路顺序：`test/offer/start` → `test/offer/scenes` → 轮询 `test/offer/progress` 至 `done=true` → `test/offer/result`。
4. real 模式下业务报文直接 POST 业务地址（`eop.base-url` + `eop.paths.<key>`），请求头携带
   `X-APP-ID`/`X-APP-KEY`/`Api-Key`（各接口 ApiID）/`Staff-Code`；失败一律返回
   `resultCode=REAL_CALL_FAILED`（不回退 mock），便于区分真实数据与失败，绝不静默降级为"未命中"。
