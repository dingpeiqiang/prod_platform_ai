## 幕1 需求提报与需求分析（执行方案生成）

**演示话术（输入）：**
```
我要上新一个 5G-A 套餐，月费 199 元，包含 60GB 国内流量和 1000 分钟国内通话，
流量可结转至次月，支持副卡，营业厅和 APP 渠道可办理，10月1日生效。
请帮我分析需求并生成执行方案。
```

**系统预期输出：**
1. 需求理解（1~2 句话）；
2. 分析结果：已识别要素 + 匹配相似产品（`query_similar_offer` 命中 900102308 5G-A套餐199元，相似度 ≈0.92）+ AI 补全字段说明（如收费方式=月付、退订生效规则=次月生效，来源"AI补全"）+ 待补充字段提示（若价格/资源类有缺失）；
3. 《产销品加载执行方案》Markdown 表格（4 列：字段分类/字段名称/字段值/来源）；
4. plan_id（如 `PLAN20260912001`，已存入节点结果存储）；
5. 确认提示：【确认执行】/ 修改意见。

**要点强调：** 字段来源只有"原始需求/AI补全"两种；价格、资源类未提供必须"待补充"，不推理。

**验收映射：** 需求要素映射准确率 ≥95%；AI 补全字段标记正确率 100%。

## 幕3 执行主干自动化串行（V1.5/V1.6）

**演示观察点：** 确认后一次运行连打四环节结果，**中途不停顿、无多余人工询问**。

**预期输出序列：**
```
【环节1/智能配置】✅ 执行成功
- 关键数据：product_id={...}，offer_id=9001023xx，四类字段写入结果：基础信息✓ 资源配置✓ 营销资源✓ 销售规则✓
- 已自动进入下一环节……

【环节2/配置规格稽核】✅ 执行成功
- 关键数据：稽核通过 + {audit_summary}
- 已自动进入下一环节……

【环节3/资费校准】✅ 执行成功
- 关键数据：资费校准通过，未发现叠加/互斥冲突
- 已自动进入下一环节……

【环节4/销售品自动测试（含受理验证）】✅ 执行成功
- 关键数据：场景 3 个（套餐新装/副卡加装/套餐退订）、测点 N 个全部一致；
  受理验证：orderId={...}，offerInstId={...}，各受理场景均通过
- 执行主干全部完成
```

**技术口径：** 各环节结果以 `EXEC{execution_id}_STAGE{n}` 写入节点结果存储；稽核为实时接口同步返回；测试为"发起→场景→轮询（5s/30min）→结果"。

**验收映射：** 执行主干串行连续性；每环节结果打印率 100%。

## 幕3A 异常中断与引导（可选彩排，反向演示）

**操作：** 换用预构造的含缺陷需求（互斥优惠叠加）重新走一遍需求分析 → 确认执行。

**预期输出：**
```
【执行中断】❌ 环节：配置规格稽核
- 异常原因：稽核驳回（pass=0）
- 关键明细：error_list——[互斥] 叠加优惠 X 与优惠 Y 互斥不可同订（error）
- 整改建议：移除互斥优惠之一后重新执行……
请选择下一步：
① 回复【重新执行】：将自动从失败环节继续（已成功环节不重复执行）
② 回复【修改执行方案】：请说明修改意见，将重新生成执行方案并再次确认
```

**续跑演示：**
```
输入：重新执行
预期：从稽核环节续跑；环节1 不重复落地（CRM 无重复记录）；已成功环节结果回放打印。
```

**修改方案演示：**
```
输入：修改执行方案，去掉优惠 Y
预期：回到需求分析重新生成执行方案（覆盖写同 plan_id），再次等待确认。
```

**验收映射：** 异常处置完整性；续跑正确性（写接口不重复调用）。

## 幕3B 成功详情汇总与审批发起确认（第二次中断）

**预期输出（四环节全部成功后）：**
```
【执行主干全部完成】✅ 共4个环节执行成功：
1. 智能配置：product_id={...}，offer_id={...}，四类字段全部写入成功；
2. 配置规格稽核：通过，{audit_summary}；
3. 资费校准：通过，未发现叠加/互斥冲突；

   受理验证：orderId={...}，offerInstId={...}，各受理场景均通过。

是否发起上线审批？回复【发起审批】将汇总以上结果提交审批流；
回复【暂不】可稍后发送"发起审批"继续。
```
