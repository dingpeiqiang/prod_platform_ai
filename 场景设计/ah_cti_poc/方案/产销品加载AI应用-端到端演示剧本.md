## 幕1 需求提报与需求分析（模板轨 V3.0：分节多表）

**演示话术（输入）：**
```
我要上新一个 5G-A 套餐，月费 199 元，包含 120GB 国内流量和 1000 分钟国内通话，
套外流量 3 元/GB、套外语音 0.15 元/分钟，流量可结转至次月，
营业厅和 APP 渠道可办理。
请帮我分析需求并生成执行方案。
```

**系统预期输出（六步流程：①识别→②相似→③模板→④提取→⑤合并→⑥渲染）：**
1. 需求理解（1~2 句话）；
2. 步骤① 产品识别：LLM 封闭 schema 输出 `{prodName, prodType=个人主套餐}`，经 `identify_products` 校验（valid=1）；
3. 步骤② 相似检索：本地 `存量产品目录_清洗后.json` 命中 900102308 5G-A套餐199元（personMainPrc）→ 直接取 K5 实例化报文 `references/K5存量报文/900102308.json`（本地主源；远端 `similar_offer` 兜底）；
4. 步骤③ 模板获取：`get_template` 返回 personMainPrc schema（85 叶子，提示词注入 1~3K token）；
5. 步骤④ 要素提取：LLM 按模板叶子清单提取嵌套要素 → `validate_elements` 校验闸（路径合法/枚举不改写/质量门禁 ≥0.30）；
6. 步骤⑤ 合并：`merge_nested`（JSONPath 对位，schema 骨架）——需求值 source=原始需求、相似品补全 source=AI补全、schema default source=默认值；**价格字段需求未提供时留空（禁止从相似品照搬）**；
7. 《加载方案》**分节多表**（`render_table` V2.0 代码生成，业务人员可读）：概览卡片置顶（资费名称/套餐月费/包含资源）+ "1. 基础信息 / 2. 发布信息 / 3. 可选配置…" 独立小节 + 小节内二级分组加粗子标题 + 三列表格（字段名称/字段值/备注），**纯 x-label 中文，无技术键名**；
8. req_id + plan_json_v2 双份入库（`save_node_result`：嵌套报文 payload + _meta 溯源 + flat24 派生 `flat_fields` 供环节2/3 后端 24 字段校验）；
9. 确认提示：【确认配置】/ 修改意见。

**要点强调：**
- 来源备注形态：【原始需求】/【AI补全】/【默认值】+ 条件提示/默认值标注（render_table 自动生成）；
- **LLM 仅在步骤①④做"自然语言→结构化翻译"**，合并/校验/渲染/路由全部脚本执行（四层架构，输出逐字节可回归）；
- 价格纪律（纪律11）：主套餐档位 ≠ 宽带月功能费 ≠ 副卡月功能费，各自独立判定；需求未提供的价格字段一律进【待补充字段】（出口A）；
- enum 校验不改写（评审结论#4）：提取值 ∉ 模板枚举 → `_meta.enum_violation` 清单 + 出口B 附【枚举确认提示】小节人工确认；
- 同输入输出逐字节稳定（幂等），禁止为"展示好看"加工渲染结果。

**验收映射：** 需求要素映射准确率 ≥95%；模板轨六步全链路可回归（同输入逐字节一致）；AI补全字段标记正确率 100%。

## 幕1B 融合需求提报（多成员一次加载，V2.0 新增；V3.0 模板轨口径）

> 场景定位：融合套餐 = 1 个主商品 + N 个成员商品，一次需求提报、多商品协同加载。
> V7.0 模板轨链路：步骤① 识别产品列表（members 含宽带/天翼高清/副卡表述）→ 步骤② 本地检索命中 familyBasePrc 模板品 → 步骤③~⑥ 逐产品按 familyBasePrc 模板执行（提取时成员表述归入 phoneMbrInfo/broadBandMbrInfo 成员容器）。

**演示话术（输入）：**
```
我要上新一个 5G-A 融合套餐 199 元，主卡套餐含 100GB 国内流量和 1000 分钟国内通话，
允许办理副卡，流量可结转；同时绑定 1000M 宽带和天翼高清，副卡功能费 10 元/月。
请帮我分析需求并生成执行方案。
```

**系统预期输出（模板轨六步，familyBasePrc 93 叶子）：**
1. 需求理解（1~2 句话，点明"融合套餐=主商品+成员商品"）；
2. 步骤① 识别：`{prodName: 5G-A融合套餐199元, prodType: 家庭基础套餐, members: [宽带, 天翼高清, 副卡功能费]}`；
3. 步骤② 本地检索命中 900113046（familyBasePrc；dup 900102306 自动指向 active）；
4. 步骤④ 提取：成员资费值逐项入成员容器（副卡功能费 10 元/月 → phoneMbrInfo 成员月租），主套餐资费入基础/可选配置；
5. 《加载方案》**分节多表**（render_table 按 familyBasePrc 容器分节：基础信息/发布信息/成员信息/可选配置…各成独立小节，成员信息小节内按成员分组）；
6. req_id + plan_json_v2 双份入库；
7. 出口二选一：任一产品 `pending_required` 非空（如宽带月功能费需求未提）→ 出口A（整体不保存不产 req_id，【待补充字段】逐项提示）；全部齐备 → 出口B（已保存 + 建议输入"确认配置"）。

**要点强调：**
- **价格禁止跨成员照搬**：主套餐档位（199元）与宽带/天翼高清/副卡功能费月功能费互相独立，各字段独立判定（merge_nested normal 模式强制）；
- 成员表述归入对应成员容器，禁止混入基础信息（提取提示词规则7）；
- 待补充判定唯一事实源=merge_nested `pending_required`（模板轨按路径定位，如"成员信息-副卡月租"）；
- K5 融合品报文资费值逐字保留原文，禁止改写。

**验收映射：** 融合成员要素归容器正确率 100%；分节多表生成正确率 100%；跨成员价格隔离（不照搬）。

## 幕1D 模板轨全链路演示（V3.0 新增：需求→分节表格→双份入库→下游可用）

> 演示目标：完整展示 V7.0 模板轨"四层架构"卖点——LLM 只做翻译，确定性逻辑全部代码化，每步出参逐字节可回归。

**1D-1 正常链路（出口B）：**
```
输入：幕1 话术（价格齐备版：月费 199 元）
预期（工具调用序列逐个展示）：
  ① identify_products → valid_products=1（prodType=个人主套餐）
  ② 本地检索 → 900102308（K5 报文主源；断网演示远端 similar_offer 兜底）
  ③ get_template → personMainPrc schema（85 叶子）
  ④ LLM 提取 + validate_elements → PASS（rate≥0.30，enum_violation=0）
  ⑤ merge_nested → payload 嵌套报文 + _meta 溯源（原始需求/AI补全/默认值逐叶子可查）
  ⑥ render_table → 分节多表（概览卡片 + 分节 + 待补充归零）
  ⑦ derive_flat24 → flat_fields 9 字段（套餐名称/套餐档位/套外…）+ save_node_result 双份入库
  ⑧ 出口B（已保存 + req_id + 建议"确认配置"）
观察点：merge_nested 重跑输出逐字节一致（幂等）；_meta 可逐字段回答"这个值从哪来"。
```

**1D-2 价格缺失链路（出口A）：**
```
输入：预构造价格缺失需求（不含月费/档位金额）
预期：merge_nested pending_required 非空（prcMonthFee/fixFee 留空）→ 出口A：
  分节多表正常展示（补全字段齐备）+【待补充字段】列出价格项（x-label 中文）+
  "执行方案暂未保存、暂不能执行（回复"确认配置"无效）"；
  反向核验：此时库中无该 req_id 记录（save_node_result 未调用）。
观察点：价格禁止照搬——相似品 900102308 报文含 prcMonthFee=199，但需求未提价格时
  合并器拒绝取值（normal 模式强制），留空进待补充。
```

**1D-3 枚举异常链路（人工确认，不阻断）：**
```
输入：构造含非枚举措辞的需求（如收费方式描述与 calcMode 枚举不一致）
预期：validate_elements 报 enum_violations（不改写值）→ merge_nested _meta 标记 →
  出口B 文案末尾附【枚举确认提示】小节（字段/提取值/可选枚举前6项）；
  观察点：LLM 不强行归一枚举（评审结论#4 校验不改写），异常进清单人工确认。
```

**验收映射：** 幕1D 全链路 7 工具出参可核对率 100%；幂等回归 PASS；价格隔离（不照搬）实演示；枚举异常处置完整。
