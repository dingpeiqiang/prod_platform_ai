# 智能体工作流集 V1.6 — 测试用例手册

> 测试对象：`场景设计/ah_cti_poc/工作流配置/智能体工作流集V1.6/` 下 11 个子工作流 `wf_sub_00`~`wf_sub_10`。
> 测试侧重：**节点链路 + 入参出参**（三层引用一致性、出参声明、分支走向）。
> 交付形式：本文档（Markdown）。可配合 `_validate_flows.py` 做 JSON 结构性回归校验。
> 节点类型：`0`开始 / `1`LLM / `2`分支 / `3`插件 / `6`代码 / `9`结束。
> 约定：节点 id 简写为尾 12 位，如 `...000000000001`；`<- B.O` 表示引用节点 `B` 的出参 `O`。

---

## 0. 通用静态校验（全部工作流共用）

| 编号 | 规则 | 通过条件 |
|---|---|---|
| G-1 | 节点类型白名单 | 仅允许 `{0,1,2,3,6,9}`，无其他类型 |
| G-2 | 开始节点存在且唯一 | 有且仅有 1 个 type=0，置于链路起点 |
| G-3 | 结束节点存在 | 至少有 1 个 type=9 |
| G-4 | 边可达 | 图中每个非开始节点均有入边，无非开始孤立节点 |
| G-5 | ref 入参三层一致 | 每个 type=ref 入参：`blockID`、`nameValue[0]`、`currValue` 前缀均为上游 `id`；`nameValue[1]`/`currValue` 整体为 `{上游id},{出参名}` |
| G-6 | ref 出参可解析 | 每个 type=ref 入参的 `relName` 均能在上游节点声明中找到同名出参 |
| G-7 | 代码节点出参格式 | 每个 type=6 节点的 `outputs` 均含 `relName` 且 `relName = "{自身id},{出参名}"`、`name` 与之同名 |
| G-8 | chat_id 可选透传 | 开始节点含 `chat_id` 选填入参（`required=false`），不强制下游透传 |

> 已用 `_validate_flows.py` 对 11 个 JSON 实测：G-1~G-8 全部通过（见各节 `静态校验: 通过`）。

### 1.1 链路
`开始(1) → LLM需求字段抽取(2) → 代码需求提报单渲染(3) → 分支待补充判定(4) ──0── 插保存需求工单(5) → 插需求工单审批(6) → 结束提报成功(7)`

### 1.2 关键节点断言

| 节点 | 类型 | 入参引用 | 出参声明 | 断言 |
|---|---|---|---|---|
| 2 需求字段抽取 | 1 LLM | `requirement_text <- 1.requirement_text` | `elements_json` | 入参三层一致；prompt 引用开始节点需求文本 |
| 3 需求提报单渲染 | 6 代码 | `elements_json <- 2.elements_json`；`reporter <- 1.reporter` | `report_text,pending_fields,pending_count,req_id,elements` | 出参 relName=`...003,{出参名}` 格式；仅 2 个 ref 入参（req_id/need_summary 已删） |
| 4 待补充判定 | 2 分支 | 条件左值 `...003.pending_count` | — | 条件=**pending_count 不为空**(op10) |
| 5 保存需求工单 | 3 插件 | `req_id <- 3.req_id`；`result_json <- 3.elements`；node_name/status 常量 | `code,msg,record_id` | ref 指向代码节点出参 |

| 8 结束有待补充 | 9 | `req_id,report_text,pending_fields <- 3` | — | 有待补充分支终点 |

### 1.3 分支走向用例

| 用例 | 前置 | 预期走向 | 结束节点 |
|---|---|---|---|
| WF00-01 | pending_count 为空（无待补充字段） | 4→5→6→7 | 结束(提报成功) |
| WF00-02 | pending_count 长度>0（存在待补充字段） | 4→8 | 结束(有待补充) |

### 1.4 关键边界
- 需求文本空/全部字段未提及 → LLM 输出全空串 elements_json → 代码节点判定 price/resources 为空 → pending_count>0 → 走 WF00-02。
- code 节点未传 req_id 入参时自动生成 `PLAN+时间戳+3位随机`。
