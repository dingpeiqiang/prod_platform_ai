[测试规范] 销售品测试用例设计规范与模板（试用版 V1.0）

> 说明：知识库冷启动试用版，作为测试用例生成（gen_test_cases）与执行判定依据。

一、测试范围与分类

销售品上线前必须完成以下四类测试（case_type 对应）：
| case_type | 场景 | 必测项 |
| --- | --- | --- |
| acceptance | 受理 | 新订购成功、重复订购拦截、不具备资格用户拦截、各渠道受理 |
| change | 变更 | 档位升降级、变更生效时间、变更后资费正确 |
| cancel | 退订 | 月末退订生效、退订后权益截止、退订后无后续计费 |
| billing | 计费 | 月租金额、按天分摊、优惠生效、超套计费、跨月边界 |
| all | 全部 | 以上全部（上线前必须 all） |

二、测试环境要求

| 环境枚举 | 用途 | 数据要求 |
| --- | --- | --- |
| sit | 功能联调 | 可用造数，允许脏数据 |
| uat | 业务验证 | 接近生产的配置与用户群 |
| pre | 上线前预验证 | 与生产配置同步，只读对比+灰度验证 |

禁止在生产环境执行任何测试写入操作。

三、测试数据准备规范

1. 测试用户：按用户群准备（新入网/存量/携转/政企/欠费用户各 ≥1）；
2. 关联产品：与目标产品存在互斥/依赖关系的在订产品各准备 1 例；
3. 时间样本：覆盖月末（28-31 日）订购、月初（1-3 日）订购、月中订购三类时间点。

四、用例设计要素（单条用例必含字段）

| 字段 | 说明 |
| --- | --- |
| case_id | TC+产品编码+3位序号 |
| case_type | acceptance/change/cancel/billing |
| precondition | 用户状态、在订产品、时间点 |
| step | 操作步骤（受理/变更/退订指令，或出账触发） |
| expect | 预期结果（含资费金额精确到分） |
| actual | 实际结果 |
| result | pass/fail |
| fail_reason | 失败原因定位（接口/配置/数据/环境） |

五、核心用例模板（按场景）

5.1 受理类（acceptance）
- 用例1：符合资格用户通过 APP 订购 → 预期：订购成功，次月生效，CRM 状态"在订"；
- 用例2：重复订购同一产品 → 预期：拦截，提示"已订购该产品"；
- 用例3：互斥组产品在订用户订购 → 预期：拦截并提示互斥产品名；
- 用例4：依赖未满足用户订购（副卡无主套餐）→ 预期：拦截并提示前置条件。

5.2 变更类（change）
- 用例5：档位升级（30GB→50GB）→ 预期：立即生效，补收按天差额；
- 用例6：档位降级 → 预期：次月生效，当月资费不变；
- 用例7：变更后三侧状态一致（CRM/计费/CPCP）→ 预期：一致。

5.3 退订类（cancel）
- 用例8：月末退订 → 预期：次月 1 日失效，当月权益可用，无次月计费；
- 用例9：退订后立即再订购 → 预期：按新订购流程，次月生效；
- 用例10：合约期内退订 → 预期：拦截并提示违约金规则（如有）。

5.4 计费类（billing）
- 用例11：整月出账 → 预期：月租金额与配置一致（精确到分）；
- 用例12：月中 15 日订购 → 预期：按 16/30 天分摊（四舍五入到分）；
- 用例13：优惠生效 → 预期：折扣/减免按规则体现，且仅一个折扣生效；
- 用例14：互斥组出账 → 预期：不存在双重优惠；
- 用例15：超套出账 → 预期：按超套单价计费，不足一单位按一单位；
- 用例16：跨月边界（31 日 23:50 订购）→ 预期：当月仅收 1 天分摊或次月生效，与配置一致。

六、通过标准

1. 单产品上线：四类场景 all 通过率 100%，无未解释失败；
2. 失败处理：任何 fail 项必须定位原因（配置/接口/用例），配置类失败整改后全量回归；
3. 关键项一票否决：出现计费金额错误、互斥失效、退订后计费三类 fail，禁止上线；
4. 回归要求：修复后至少回归失败用例 + 关联场景用例。

七、测试报告模板

《销售品上线测试报告》结构：
1. 产品概述（名称/编码/档位/生效期）；
2. 测试概况（环境、用例总数、通过/失败数、执行时间）；
3. 分场景结果（acceptance/change/cancel/billing 各自统计）；
4. 失败明细与定位（case_id、step、expect、actual、reason、责任人）；
5. 风险提示（未覆盖项、环境限制）；
6. 结论（通过/有条件通过/不通过）与上线建议。
