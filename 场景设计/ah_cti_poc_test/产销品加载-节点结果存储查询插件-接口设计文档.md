# 产销品加载 AI 应用 · 节点结果存储/查询插件接口设计文档

> 版本：v1.0
> 日期：2026-09-11
> 目的：打通端到端数据流。各子工作流把环节结果 JSON 按需求单号存入；后续环节按需求单号查询上游结果 JSON。消息窗口只输出 MD 文本。

---

## 1. 设计原则

- **key 设计**：`req_id`（需求唯一标识 REQ-yyyyMMdd-NNN）+ `node_name`（环节名）唯一确定一条记录
- **同键覆盖**：同一 req_id + node_name 重复存储时覆盖旧记录（支持重跑环节）
- **透传存储**：result_json 原样存储（字符串），不做格式校验解析
- **状态码统一**：`code=0` 成功，非 0 业务失败（与现有 11 个插件一致，string 类型）

---

## 2. 插件一：节点结果存储 `save_node_result`

### 2.1 基本信息

| 项 | 值 |
|---|---|
| 插件名称 | 节点结果存储 |
| toolCode | `save_node_result` |
| 请求方式 | POST |
| Content-Type | application/json |
| URL | `http://10.86.13.201:31281/api/v1/appstore/result/save` |

### 2.2 请求参数（入参，平铺）

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| req_id | string | 是 | 需求唯一标识，格式 REQ-yyyyMMdd-NNN；非法格式返回 5002 |
| node_name | string | 是 | 环节名，枚举：requirement/config/spec/fee/test/acceptance/approval/monitor；枚举外值返回 5003 |
| result_json | string | 是 | 本环节结果 JSON 字符串，最大 64KB，超限返回 5004 |
| status | string | 否 | 本环节状态：ok / failed / rejected，默认 ok |

### 2.3 响应参数（出参，平铺）

| 参数名 | 类型 | 说明 |
|---|---|---|
| code | string | 统一状态码，0 成功 |
| msg | string | 状态描述 |
| record_id | string | 存储记录 ID，如 REC20260911000001 |
| saved_at | string | 存储时间 yyyy-MM-dd HH:mm:ss |

### 2.4 请求/响应示例

请求：
```json
{
  "req_id": "REQ-20260911-001",
  "node_name": "config",
  "result_json": "{\"decision_json\":{...},\"crm_config_json\":{...},\"billing_config_json\":{...}}",
  "status": "ok"
}
```

响应：
```json
{
  "code": "0",
  "msg": "success",
  "record_id": "REC20260911000001",
  "saved_at": "2026-09-11 15:40:00"
}
```

### 2.5 错误码

| code | msg | 场景 |
|---|---|---|
| 0 | success | 成功 |
| 5002 | invalid req_id format | req_id 格式非法 |
| 5003 | invalid node_name | 环节名不在枚举内 |
| 5004 | result_json too large | 超 64KB |
| 9000 | storage service error | 存储服务异常 |

## 3. 插件二：节点结果查询 `query_node_result`

### 3.1 基本信息

| 项 | 值 |
|---|---|
| 插件名称 | 节点结果查询 |
| toolCode | `query_node_result` |
| 请求方式 | GET |
| URL | `http://10.86.13.201:31281/api/v1/appstore/result/query` |

### 3.2 请求参数（入参，平铺，query string）

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| req_id | string | 是 | 需求唯一标识 |
| node_name | string | 否 | 环节名；不传返回该单号全部环节记录 |
| latest_only | string | 否 | "1"=只返回每个环节最新一条（默认）；"0"=返回历史全部版本 |

### 3.3 响应参数（出参，平铺）

| 参数名 | 类型 | 说明 |
|---|---|---|
| code | string | 统一状态码，0 成功 |
| msg | string | 状态描述 |
| total | string | 命中记录数 |
| list | string | 记录数组 JSON 字符串，元素结构见下 |

list 元素结构：

| 字段 | 类型 | 说明 |
|---|---|---|
| req_id | string | 需求单号 |
| node_name | string | 环节名 |
| result_json | string | 环节结果 JSON（存储时原样返回） |
| status | string | ok / failed / rejected |
| create_time | string | 存储时间 |
| update_time | string | 最后更新时间 |

### 3.4 请求/响应示例

请求：
```
GET /api/v1/appstore/result/query?req_id=REQ-20260911-001&node_name=requirement
```

响应：
```json
{
  "code": "0",
  "msg": "success",
  "total": "1",
  "list": "[{\"req_id\":\"REQ-20260911-001\",\"node_name\":\"requirement\",\"result_json\":\"{...}\",\"status\":\"ok\",\"create_time\":\"2026-09-11 15:30:00\",\"update_time\":\"2026-09-11 15:30:00\"}]"
}
```

### 3.5 错误码

| code | msg | 场景 |
|---|---|---|
| 0 | success | 成功（total=0 表示无记录，不算失败） |
| 5002 | invalid req_id format | req_id 格式非法 |
| 9000 | storage service error | 存储服务异常 |

## 4. 环节名（node_name）枚举约定

| node_name | 所属子工作流 | 存储内容（result_json 内的建议字段） |
|---|---|---|
| requirement | wf_sub_01 需求分析 | req_id, parsed_json, complete_flag, missing_items |
| config | wf_sub_02 智能配置 | decision_json, crm_config_id, crm_config_json, billing_config_json |
| spec | wf_sub_03 规格稽核 | pass, error_list, suggest_list |
| fee | wf_sub_04 资费校准 | pass, risk_list, risk_explain |
| test | wf_sub_05 自动测试 | total, passed, failed, fail_detail, case_ids |
| acceptance | wf_sub_06 受理验证 | pass, order_id |
| approval | wf_sub_07 上线审批 | approval_id, status, report |
| monitor | wf_sub_08 监控运维 | order_count, error_count, fee_error_rate, alarm_list, alert_id |

---

## 5. 工作流接入约定（端到端数据流）

```
sub_01: LLM生成REQ单号 → 业务 → save(requirement) → MD输出(含单号)
sub_02~08 开始: LLM从chat_context提取REQ单号 → query(上游node_name) → 业务处理
sub_02~08 结束前: save(本环节node_name) → 结束(MD输出，不打印JSON)
```

- **查询失败/无记录**：判断器分流，结束节点输出"未找到该需求单号的环节数据，请确认单号或先完成前置环节"（MD）
- **存储失败**：不阻断主流程，MD 中提示"结果存档失败"（告警环节除外）
